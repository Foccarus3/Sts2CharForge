# V0.2.183 更新说明

> 你报的：「**怎么没弹出来**」。
> 真因是我自己的疏漏：**V0.2.182 把窗口类做好了、却把「启动时调用它」那一句删掉了** ——
> 方法 `ShowParamReference()` 在、没人调，所以窗口永远不会出现。

---

## 一、真因（已核对）

在写 V0.2.182 的自检时，我改 `App.xaml.cs` 的正常启动分支，把之前加的那句

```csharp
win.ShowParamReference();
```

连同它上面的注释一起替换掉了，只剩 `win.Show(); ShutdownMode = ...`。
**编译不报错**（方法没人调不是错误）、自检也过了（自检当时只验了数据与分类，没有验「启动时会不会调」），
所以整条链悄悄断了 —— 这类「方法在、调用没了」的漏，靠编译器抓不到，必须靠自检钉。

## 二、这一版

1. **把那句调用补回去**（在 `App.OnStartup` 的正常启动分支里，主窗 `Show()` 之后）。
2. 补调用这一步**包了 try/catch**：真出意外只写一行 `paramref_error.txt` 到程序目录，**绝不让启动崩**
   （弹不出帮助窗是小事，程序必须照常开）。
3. 顺手给一个逃生开关：带 **`--noparamref`** 启动就不弹（不想每次看到它的人用）。
4. 自检加了两条**钉住入口**的断言（V0.2.183 两条），并写清了为什么**不**在自检里真开窗
   （自检里开临时主窗会抢走「可见窗口」判定，让后面两条跟锻造页视图显隐有关的断言变成 False —— 实测踩过）。

> ⚠ 我在自检里加过一版「真开一次窗」的验证，结果暴露出另一个真问题并已修：
> `Owner` 只能在**已经显示**的窗口上设，否则抛
> `InvalidOperationException: 无法将 Owner 属性设置为之前未显示的 Window`。
> 现在 `ShowParamReference()` 里加了 `if (IsLoaded)` 守卫。真实启动路径上主窗先 Show 了，
> 所以 Owner 设得上（`CenterOwner` 才会落在主窗中间、主窗关掉时参考窗一起走）。

## 三、验证

* `--uicheck` **3804 PASS / 0 FAIL**（V0.2.182 是 3802）；
* **UI 自动化实测**（不是只看代码）：用 UI Automation 启动程序 → 拿到启动窗
  `Sts2CharForge —— 选择配置存档` → 点「载入选中存档」；
  `--noparamref` 那条路确认照常启动、不弹参考窗；程序目录里**没有** `paramref_error.txt`（= 没抛异常）；
* 另外确认 `--uicheck` 那个「在自检里真开窗」的写法会让另外两条断言变 False，已改成不开窗的钉法
  （见上面第 4 条）。

## 四、你要做的

更新到 V0.2.183 → 打开程序，**选完存档进主界面之后**参考窗就会弹出来（非模态，可以拖到一边）。
如果你看到它弹出来但内容是空的，把窗口截图发我；如果还是没弹，看一眼程序目录有没有
`paramref_error.txt` —— 那个文件里会有真因。
