# V0.2.349 — 插件框架支持「动态行集合」：招式列表那种界面，插件也能做了

你要的是**能适配的框架**，不是又一个写死的页。这一版就是给插件/自定义页补齐「动态列表」这块底盘。

## 之前为什么做不了

插件一页的栏位只有 `text / number / bool / pick / multiline`（`PluginFieldSpec`），
全是「一个值」的输入框；`emit` 也只是把 `{key}` 一对一替换成字符串。
所以「招式列表 / 怪物列表 / 掉落表」这种**多行、可增删**的界面在插件里表达不出来 —— 上一轮那句
「插件 newTab API 没有动态列表控件」说的就是这件事，那部分是对的。

## 这一版加了什么

### 1. 新栏位类型 `type = "list"`

```json
{
  "key": "moves", "label": "招式", "type": "list", "itemLabel": "招式", "defaultRows": 2,
  "fields": [
    { "key": "name", "label": "招式名", "type": "text",   "default": "Tackle" },
    { "key": "kind", "label": "类型",   "type": "pick",   "options": ["攻击", "防御", "上状态"] },
    { "key": "dmg",  "label": "数值",   "type": "number", "default": "6" }
  ]
}
```

界面自动长出「+ 添加一行」和每行的「↑ / ↓ / 删除」，行内子栏位支持 `text / number / bool / pick / multiline`。
插件只声明数据结构，WPF 由编辑器出。

### 2. `emit` 的块宏（逐行展开）

```
{moves}
    "[{index}] {name}（{kind}，{dmg}）",
{/moves}
```

* 块里可用的占位符 = 该行的子栏位 + `{index}`（1 起）/ `{index0}`（0 起）；
* 块可以出现多次；**必须配对**，不配对在加载期就报问题（不会静默生成半截文件）；
* 子栏位**不能**再是 `list`（嵌套 v1 不支持，报问题）；
* `target`（文件名）里**不能**用 list 栏位（报问题）。

### 3. 行数据独立存储

`plugins\<插件 id>\rows.json`，和 `values.json` **分两个文件**是故意的：
老版本编辑器读到新数据不会把 `values.json` 整份读坏（只是看不到列表内容）。

### 4. 页面级问题与跳过

`PluginPageSpec.Problems`：有问题的页在生成时**直接跳过**（并显示红字），同插件的其它页照常 ——
不会因为一页配错就整份插件不产出。

### 5. 示例 + 文档

* 示例插件多了「招式列表（list 字段示例）」页（`plugins/示例插件/plugin.json` 的 `move-list`），
  填一行行招式 → 生成一个 `.cs` 片段，可直接拿它当模板；
* `docs/插件开发规范.md` 第 11 节、`docs/插件AI提示词.md` 第 15 节写清了语法、宏、限制。

## 这套框架现在能 / 不能做什么

* **能**：任意「多行数据 → 按行生成文本」的编辑器：招式表、掉落表、事件分支表、状态列表…
  也就是说「完整敌人编辑器」那种界面**用这套框架就能表达**（缺的不是列表控件了，而是「敌人」这个业务模型要不要写）。
* **不能**（v1，已记在文档里）：嵌套列表；一页按列表值生成**多个文件**（一页仍只产出一个文件）；
  在页面里引用生成器的其它对象（比如从列表里下拉选一张已有卡牌 —— 那要「引用型栏位」，下一版再说）。
