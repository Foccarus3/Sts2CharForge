# V0.2.240 — 小屏幕适配：窗口不再被屏幕边裁掉，整窗可缩放

## 用户反馈

「有一些人的屏幕小，就会发生有一些地方被遮挡，怎么办」（附截图：效果编辑区底部那一截被窗口边切掉）

## 根因

主窗口尺寸原来是写死的 **1420 × 880**，而且没有任何兜底：

- `MainWindow.xaml` 只有 `Height` / `Width`，没有 `MinWidth` / `MinHeight`，也没有启动时按屏幕修正；
- 在 1366×768 / 1280×720 这类屏上，窗口比屏幕还大 → 右边和下边直接被屏幕边切掉，
  被切掉的正好是「效果编辑区下半部分 / 状态栏」（截图里那两条规则文字下面那一整块）；
- 而窗口内部的滚动条只能滚**窗口里面**的内容，滚不出屏幕外 —— 所以那些控件就是点不到。

## 这一版做了什么（三件事一起，缺一件都还会被裁）

1. **窗口压进屏幕可用区域**（`MainWindow.FitWindowToScreen`）：启动时按
   `SystemParameters.WorkArea`（已扣掉任务栏）把 `Width` / `Height` 收进去，留 16px 余量；
   屏幕比最小尺寸还小时直接最大化。同时补上 `MinWidth="960" MinHeight="600"` ——
   手动拖也不会拖成「小到没法用」。
2. **整窗缩放**：根布局 `RootPanel` 加 `LayoutTransform`（**不是** RenderTransform ——
   后者只缩放绘制、不改布局，内容照样被裁，文字还会糊）。缩放档 60%~125%，
   顶栏新加「界面缩放：」下拉，改了立刻生效，并记在
   `%LOCALAPPDATA%\Sts2CharForge\ui-scale.txt`（没写权限就静默跳过，只在本进程生效）。
3. **自动挑档**（`MainWindow.AutoUiScaleFor`，纯函数、自检钉着）：

   | 屏幕可用高度 | 自动缩放 |
   |---|---|
   | ≥ 900 | 100% |
   | ≥ 800 | 90% |
   | ≥ 700 | 80% |
   | ≥ 620 | 75% |
   | < 620 | 70% |

   另外**窄屏**（可用宽度 < 1300）再降一档、最高只给 80%。
   例：1920×1040 → 100%；1366×728 → 80%；1280×620 → 75%；1024×600 → 70%。

4. 另外两个独立小窗（「选择配置存档」`760×480`、「参数参考」`980×660`）也按可用区域夹了一次 ——
   它们不跟主窗缩放走，极小的屏上同样会被裁。

## 实测（本机 1920×1080，强制 80% 档截图确认）

- 顶栏出现「界面缩放：80%」，窗口整体按 80% 排布，**底部的效果编辑区和状态栏都完整可见**；
- 自检：开发版 **4244 PASS / 0 FAIL**（新增 7 条：最小尺寸、启动压进 WorkArea、四档自动值、
  窄屏降档、改档立即作用到 RootPanel、下拉选中项与当前档一致、收尾恢复）。

## 注意

- 缩放是**布局级**的（LayoutTransform）：字号、间距、控件尺寸一起等比缩，不是把画面拉伸；
  鼠标坐标 WPF 会自己折算，锻造页的拖拽 / 连线不受影响。
- 想回到「不缩放」直接在下拉里选 100%（会被记住）。
- 老存档 / 生成结果一条都不受影响（这一版只动界面）。
