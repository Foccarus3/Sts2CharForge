## 四、「下回合生效」补齐时老存档怎么算（用户 2026-10-10 答：**逐个定**）

**用户的选择：那 8 种全部「从此生效」**（即：老存档里勾过它们的，新版本起会真的生成延迟分支 —— 这是**用户明确接受**的「老存档输出会变」的唯一一类）。

逐个核对过的事实（V0.2.131 代码）：历史上界面上能被勾上「下回合生效」的只有 **13 种**（`EffectKindOption.SupportsNextTurn=true`），其中

| 类别 | 种类 | 处理 |
|---|---|---|
| 早就真的实现了（5 种） | 格挡 / 抽牌 / 能量 / 额外资源量 / 施加状态 | 不动 |
| **勾了但一直没生效（8 种）** | 透支能量 / 翻倍状态层数(`DoublePower`) / 暴露(`Expose`) / 清除指定状态(`ClearPowerOne`) / 清除全部减益(`ClearPowerDebuffs`) / 禁止获得格挡(`ForbidBlock`) / 禁止回复生命(`ForbidHeal`) / 伙伴攻击(`PetAttack`) | **用户已定：全部「从此生效」** —— 补齐延迟分支后，老存档里勾过它们的会开始真的延迟生效 |
| 从来没出现过这个勾选框（其余 52 种） | 见 `D:\ds\s\_tmp\下回合生效_补齐清单（预研）.md` | 没有历史包袱，补齐后直接用（不存在「老存档输出变化」问题） |

⚠ 实现时的硬要求：
1. `EffectKindOption.SupportsNextTurn` 必须与 `EffectCatalog.HonorsNextTurn` **逐条对齐**（否则界面又会出现「勾了没反应」——用户报过）；
2. **发版说明里要点名列出「从此开始真的生效」的那 8 种**（用户会拿它对照自己的老存档）；
3. 每个新延迟分支都要有**真编译探针**（延迟状态是新生成的类型，签名/可见性错了只有编译能发现）；
4. 除这 8 种之外，**其余任何种类都不许改变老存档的生成输出**（红线①照旧）。
