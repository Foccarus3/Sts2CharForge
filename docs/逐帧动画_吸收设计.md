## 二、生成出来的文件（黄金文件在 `_art/anim_ref/`）

```
images/characters/anim/<slug>/<slug>_<anim>_<000..N-1>.png          # 裁剪后的帧（RGBA）
images/characters/anim/<slug>/<slug>_<anim>_<idx>.png.import        # Godot 导入设置（最近邻）
images/characters/anim/<slug>/<slug>_<anim>_frames.tres             # SpriteFrames（动画名 = anim，duration = 每帧秒数）
images/characters/anim/<slug>/<slug>_<anim>_manifest.json           # 该动作的计划（anim/loop/frames/size/crop/scale/yOffset/trigger）
```

要点：
- `frames.tres` 里 `"speed": 1.0`，**每帧秒数写在 frame 的 `duration` 上** ——
  Godot 的 `SpriteFrames.speed` 是**倍率不是 fps**（参考实现踩过：填 30 会额外加速 30 倍）。
- `.png.import` 里的 `path` / `dest_files` 用的是
  `res://.godot/imported/<文件名>-<md5(源文件的 res:// 路径)>.ctex`
  —— **哈希 = 源路径的 MD5**（实测命中；这就是参考版引用 `System.Security.Cryptography` 的原因）。
- 帧图用现有的 `PngUtil.WriteRgba` 写（我这边已经有这个 API）。
- `Scale`/`YOffset` 精确到小数；`frameSeconds` 写 5 位小数（如 `0.13333`）。

## 三、语义（拿参考实现实测出来的矩阵）

输入：自造 3 帧 GIF（20×24，帧延时 100/200/100ms，白底 + 黑描边色块）：

| 设置 | crop | 尺寸 | scale | yOffset | 说明 |
|---|---|---|---|---|---|
| 默认（key=on, align=on） | 0,0,20,24 | 20×24 | 8.125 | -97.5 | 内容高 = 整幅（白底没被抠掉也算内容） |
| `KeyBackground=false` | 同上 | 同上 | 同上 | 同上 | **抠底不影响计划**（计划按原图算，抠底只在写帧时做） |
| `AlignByFirstFrame=false` | 同上 | 同上 | 同上 | 同上 | 单动作时两种模式结果相同（多动作才会不同） |
| `ManualCrop="7,12,13,21"` | 7,12,13,21 | **6×9** | 21.667 | -97.5 | x1/y1 开区间；计划里写「裁剪框用界面指定的」 |
| `FrameSeconds=0.2` | — | — | — | — | 所有动作的每帧秒数都变 0.2 |
| `Scale=3; YOffset=5` | — | — | **3** | **5** | 填了就用填的（自动值让位） |

- 自动缩放 = `静态立绘高(195) ÷ 待机内容高`；自动 yOffset **精确公式**（拿参考实现跑了 7 组实验拟合，7/7 成立）：

  ```csharp
  // bottom = ContentBox(待机第 0 帧, 全画布宽, 全画布高) 给的「内容底边」（全画布坐标，开区间）
  // H = y1 - y0（裁剪框高）。yOffset 是**中心对齐**的精灵的位移：半个裁剪框高 − 裁剪框内的内容底边；
  // 负值 = 往上挪，也就是让脚落在静态立绘底边所在的位置。
  int bInCrop = Math.Clamp(bottom, y0, y1) - y0;
  yOffset = (H / 2.0 - bInCrop) * scale;
  ```

  实测对照（`_art\anim_ref` 里 `oracle.txt` 可复现）：

  | 素材 | 裁剪框 | H | scale | yOffset |
  |---|---|---|---|---|
  | 不透明底 | 0,0,20,24 | 24 | 8.125 | -97.5 = (12−24)×8.125 |
  | 不透明底 | 0,0,20,12 | 12 | 16.25 | -97.5 = (6−12)×16.25 |
  | 不透明底 | 7,12,13,21 | 9 | 21.667 | -97.5 = (4.5−9)×21.667 |
  | 透明底 | 自动 → 0,4,20,24 | 20 | 21.667 | -151.667 = (10−17)×21.667 |
  | 透明底 | 0,0,20,24 | 24 | 21.667 | -195 = (12−21)×21.667 |
  | 透明底 | 7,12,13,21 | 9 | 21.667 | -97.5 = (4.5−9)×21.667 |

  ⚠ 参考实现的注释/反编译展开式容易看错成 `(y0-y1+h/2-clamp(bottom,y0,y1))×scale` ——
  那个式子**连基线都对不上**（算出来 −292.5）。以这张表为准。
- 每帧秒数：`FrameSeconds>0` 用它；否则用动图自己的延时**取平均**（100/200/100 → 0.13333）。
- `Loop`：待机 true；攻击/施法/受击 false；`die` 的 `HoldAtEnd=true`（播完定格最后一帧）。
- 没素材的动作只写 `[提示]`（死亡/篝火/商店都会退回待机），**待机必须有**，否则 `[错误]` + `Ok=false`。
- 各动作画布尺寸不一致时会写 `[警告] … 不同，仍按同一裁剪框裁（可能错位）`。

## 四、运行时 + 补丁（两个生成文件，参考版原文见 `_art/anim_ref/runtime.ref.cs` / `patches.ref.cs`）

**运行时 `FrameAnimRuntime.cs`**：`FrameAnimRegistry`（角色 id → 各动作的帧资源 + scale/yOffset/speed/filter/keepRestShop）
+ `FrameAnimPlayer`（一个 `Node`，挂到角色视觉节点上，驱动一个 `AnimatedSprite2D`）。
补丁只做三件事：把本体的动画请求翻成帧动画、篝火/商店/死亡那几个特例、没有 Spine 的角色别去包 Spine 节点。

**必须复刻的坑（参考实现的注释里逐条写了）**：
1. `AnimatedSprite2D` 要和静态立绘**同级、插在它后面一位**，不能嵌进去（嵌进去把静态图 `Visible=false` 会连动画一起隐藏，角色整个消失）。
2. 挂上后 **1 秒做一次渲染确认**（`IsPlaying() && IsVisibleInTree()`）：确认了才收掉静态立绘；没确认就整个回滚，绝不留下「角色不见了」。
3. 循环动画**不能**计时切回待机：参考实现原来对循环也计时，表现是「篝火/商店先播专属动画，过一会儿变待机」。
4. 篝火/商店：本体进场景后会再发一次 `Idle` 把场景动画顶掉 —— `KeepRestAndShopAnim` 时要忽略 `Idle`/`Relaxed`。
5. 死亡：本体 `StartDeathAnim` 里那句 `SetAnimationTrigger("Dead")` 在 `if (_spineAnimator != null)` 里面，
   没有 Spine 的角色根本不触发；而且它返回的时长是 0，动画会被立刻切掉 → 补丁里触发 + 返回帧时长。
6. `NRestSiteCharacter` / `NMerchantCharacter` 的 `_Ready` 会**无条件**把第一个子节点当 Spine 包
   （`MegaSpineBinding` 的 `ValidateBoundObject()` 抛 `InvalidOperationException`）→ 非 Spine 时必须**前缀补丁返回 false 跳过原方法**。
7. 本工具生成的卡牌 `OnPlay` 里不请求动画（本体卡牌会调 `CreatureCmd.TriggerAnim`）：
   攻击牌能动（`DamageCmd.Attack` 内部触发），技能/能力牌完全不动 → 按卡牌类型补一次触发（Attack/Cast/PowerUp）。
8. `SpriteFrames` 载入后要**归一化**（`RemoveAnimation`+`AddAnimation` 重建，逐帧 `duration` 保持秒数、`speed=1`），
   再按 `SpeedScale` 重写每帧时长；同一个路径只做一次（静态 `Normalized` / `SpeedApplied` 集合）。
9. `FindDirectSpineChild` 用 `GetClass() == "SpineSprite"` 判（引擎级判断，不引 MegaSpine 类型）。

### 参考实现的坑（照抄之前先看这几条）

- **`AlignByFirstFrame` 参考实现根本没读它**：把 `_tmp\asmdiff\il_animframes.txt` 全文搜一遍，
  只有 `get_OutlineLuminance`，**没有 `get_AlignByFirstFrame`** —— 这个开关选与不选，
  输出一个字都不差（存档里那个字段只在界面上显示）。我们的实现同样**不生效**（对齐参考），
  界面也就不暴露这个勾选框，字段留着只为存档兼容。
- **`KeyBackground` 估底色只采「第一个 + 最后一个像素」两个点 —— 这一点必须实测确认，别信反编译**：
  参考实现这段 IL 是「先 `new int[N]`、再逐个写部分下标」，反编译出来像好几个采样点
  （很容易读成 `{0,1,0,1}` 之类），但**实测唯一对得上的是「头 + 尾」两个像素**：
  120×140 的渐变测试图（角上纯白 `#FFFFFF`、紧邻像素 `#787878`）——
  - 取「头 + 尾」→ 底色均值 `(255,255,255)`，抠掉 2103 个像素，**与 oracle 产物逐字节相同**；
  - 取「头两个」→ 均值 `(187.5,187.5,187.5)`，一个像素都抠不掉，输出对不上。

  判别方法是「只看 alpha 通道」：这种采样点错误 **RGB 完全相同**，只差 alpha，
  比 RGB、看缩略图都发现不了 —— 必须比 PNG 字节（或 alpha 通道）。我们实现就是「头 + 尾」。
- **`AutoYOffset` 不需要这个探测数组**：它取的是 `ContentBox(第 0 帧)` 的**内容底边**
  （全画布坐标），再按上一节的精确公式算；实测 7 组全中。
- **`KeyBackground` 只采样头尾两个像素估底色** → 角色压住左上 / 右下角的素材会抠不干净
  （本体被算进底色均值，纯色底的像素反而落到容差外）。这是参考实现的局限，
  我们**原样保留**（改了就和已发布的参考版表现不一致），对拍时按它的行为对齐。
- **手动裁剪框填了非数字**（如 `1,2,3,x`）：参考实现的 `int.Parse` 抛 `FormatException`，
  整次生成直接崩。我们改成「当作格式不对 → `[警告] 手动裁剪框格式不对（要 x0,y0,x1,y1）：…，改用自动`
  → 走自动裁剪」。（`AnimFramesGen.cs` 里注释标了这处有意偏离。）

**回归覆盖（拿参考实现当 oracle）**：解码器的 torture 素材和工具留在 `_tmp\giftorture`
（Python 生成的真 LZW：字典增长 / 码长递增、120×140 大图、真隔行、处置方式 0~3、
透明索引、局部色表、17 字节小数据块、delay=0），对拍程序在 `_tmp\animverify`
（`dump` 跑我们的实现，`check` 比 oracle 的 `oracle.txt` 与产物逐字节 MD5）。
三套用例：`_tmp\diff`（baseline + 6 变体）、`_tmp\diff2`（14 组透明底 / 裁剪变动组合）、
`_tmp\diff3`（上面那些 torture GIF × 默认 / 关抠底 / 剥描边）。

### 对拍（我们的实现 vs 黄金文件）

```powershell
dotnet build D:\ds\s\_tmp\animcheck\animcheck.csproj
D:\ds\s\_tmp\animcheck\bin\Debug\net9.0\animcheck.exe <存档.json> <我的输出目录> <黄金目录>
```

两个**会误报**的坑（都踩过；工具已修，但换工具 / 改目录时要记得）：

1. 黄金目录里**不能混进别的子目录** —— 工具会递归找产物，把 `probes\`、`variant_*` 之类也当成"缺失"报出来
   （一次误报 143 个"缺"）。现在 `animcheck` 会跳过 `probes` / `variant_*` / `*.ref.cs` / `oracle.txt` / `tools` / `testgif`。
2. **存档必须和黄金文件一对一配对**：把 `trans.gif`（整幅帧 + 透明底）的存档配到 `sub_d1.gif`（10×10 子矩形帧）
   的黄金上，裁剪框 / 缩放当然不同，看起来像实现错了。

### 完整管线产物的验收（比只调 `AnimFramesGen` 更硬）

走 `forge --profile <探针> --out <目录>`（**不加 --build**，这样 Godot 不会改写 `.import`）：

- `images/characters/anim/<slug>/` 下 **16/16 个文件（PNG / `.png.import` / `.tres` / manifest）与黄金文件逐字节相同**；
- `ModEntry.cs` 里四个 `__anim*` 常量 + `FrameAnimRegistry.Register(...)` 都在（含 `__animYOffset = -97.5f` 的符号）；
- `cs\FrameAnimRuntime.cs` / `cs\FrameAnimPatches.cs` 与参考文件**只差一行**：`ProjectFilesGen.WriteText`
  会给所有以 `// <auto-generated>` 开头的文件**自动插一行 `#nullable enable`**（仓库统一约定，否则编译器报 CS8669）。
  也就是说 `FrameAnimGen.RuntimeSource/PatchesSource` 的输出与参考**逐字一致**，落盘时多这一行 ——
  对拍时不要拿落盘后的文件哈希直接比参考文件，会误判成不一致。

### 回读（`--recover`）的边界

生成出来的 `FrameAnimRuntime.cs` / `FrameAnimPatches.cs` / ModEntry 里那几行注册代码**不会**让回读多出
「没认出来」（实测：带动画生成的工程 `--recover` 干净）。
但反过来**回读不还原动画设置**：产物里只有「裁好的帧资源」，GIF **源路径**根本没写进去，
所以 `CharacterProfile.Animation` 只能靠存档 JSON 本身保存 —— 这也是这一档必须在存档里而不是从工程反推的原因。

### 1) 界面「动画」页（`App.xaml` + `MainWindow.xaml.cs`）

参考版（那份二进制）的 `MainWindow` 成员名就是行为清单 —— 照这些做：

注意「待机」是回退目标，界面上要说明**必须有**。文案清单见本文 §五。

### 2) 校验器（`ProfileValidator.cs`）

- 勾了总开关但**待机没填** → 错误（待机是回退目标，没它整条废）；
- 填了的槽位**文件不存在 / 不是 GIF** → 错误（指到具体那个槽位）；
- 勾了总开关但**没有任何素材** → 提示；
- 「手动裁剪框」填了但格式不是 `x0,y0,x1,y1` → 错误（`AnimFramesGen.BuildPlan` 自己会写一条 `[警告]`，但校验器要在生成前就拦住）；
- 没勾总开关却在槽位里留了路径 → 提示（不会生效，别让人以为生效了）；
- `Scale` / `SpeedScale` / `KeyTolerance` / `OutlineLuminance` 是负数或超范围 → 错误。

### 3) `--uicheck` 断言（加在 `MainWindow.SelfTest()` 里，照现有 `Check(...)` 块写法）

1. 7 个槽位都在界面上，而且「待机（循环）」那一行写着「必须有」之类的说明；
2. 不勾总开关时：设置区/按钮**不显示**（或显示为禁用）+ 出现「上面已经放了动画素材，但总开关是关的」提示与「一键启用」按钮（素材已填的前提下）；
3. 勾上后：`Scale`/`YOffset`/`KeyTolerance`/`OutlineLuminance` 等行出现，且默认值与参考实现一致（`KeyTolerance=12`、`OutlineLuminance=170`、`AlignByFirstFrame/NearestFilter=true`、`SpeedScale=1`）；
4. `AnimationSpec.Slots` 只 yield 填了路径的槽位，且顺序 = 待机/攻击/施法/受伤/死亡/篝火/商店，动作名 = `idle_loop/attack/cast/hurt/die/overgrowth_loop/relaxed_loop`；
5. `HasAny` **只看待机**；`Display` 三种状态（未启用 / 已启用但没上传待机 / `N 个动作 · 最近邻 · 1×`）都写对；
6. 生成：勾了动画 + 待机素材 → 工程里出现 `FrameAnimRuntime.cs` / `FrameAnimPatches.cs` / 帧 PNG / `.png.import` / `_frames.tres` / `_manifest.json`，且 `ModEntry.cs` 里有 `FrameAnimRegistry.Register(...)` 与四个 `__anim*` 常量；
7. **不勾总开关时，生成结果与以前逐字一样**（把 `ModEntry.cs` 的文本钉死；而且**不能**留下上次生成的 `FrameAnimRuntime.cs`/`FrameAnimPatches.cs`）；
8. 待机解不开（指向一个不是 GIF 的文件）→ `BuildPlan` 给 `[错误]`、`Ok=false`，生成**不写**任何动画资源（但模组照常能编译）；
9. 抠底 / 剥描边真的改了像素（同一帧在 `KeyBackground=false/true` 下生成的 PNG 字节不同），而且**不影响**裁剪框（计划不变）；
10. 「最近邻」关掉时，注册行要带 `filter: Godot.CanvasItem.TextureFilterEnum.Linear`（**我们对参考实现的修正**：它那个勾选框其实没生效，实测 `.import` 与注册调用都不变）；
11. 校验器那几条（见上一节）各来一条断言。
