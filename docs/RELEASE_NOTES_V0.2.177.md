# V0.2.177 更新说明

> 修你报的「**升级后失去关键词不生效**」。
> 这个功能是 **V0.2.136** 加的，两半里**只有一半写完了** —— 另一半从加进去那天起就是死代码。

---

## 一、功能本来是「显示等价物」，分两处

本体的 `CardKeyword` 是**封闭枚举**，模组加不了新值，所以「自定义关键词」是拿三块拼出来的显示等价物：

1. 卡面描述开头那行 `[gold]名字[/gold]。`；
2. `ExtraHoverTips` 覆写（鼠标悬停时弹出的说明框）；
3. `card_keywords` 本地化键。

「升级后获得 / 失去」就是让**第 1 块和第 2 块**按有没有升级分叉。

## 二、真因：`upDel` 算出来了，却一个字都没用

`CSharpCodeGen.HoverTipsOverride` 里：

```csharp
var upAdd = …;   // 升级后获得的悬停说明
var upDel = …;   // 升级后失去的悬停说明   ← 算出来了

var upTips = tips.Concat(upAdd)…;   // ← 只并了 add，upDel 从头到尾没被用过
```

于是现场是这样：

| | 卡面那行字 | 悬停说明 |
|---|---|---|
| 没升级 | ✅ 有 | ✅ 有 |
| **升级后** | ✅ 正确消失（描述那半截的 `{IfUpgraded:show:…\|…}` 一直是对的） | ❌ **还在** |

**你看到的就是右边这一格**：卡面上的字没了，鼠标一悬停说明还弹着 —— 所以判定成「失去没生效」。

而且比「没生效」更糟一点：**升级后那两个分支里把失去的那个词列了两遍**（一次在条件分支里、
一次在「一直在」那组里），生成的 C# 里是个重复项 —— 悬停时会看到同一个说明出现两次。

## 三、改完之后（两半现在都对了）

以一张「ECHO 一直在、FATE 升级后获得、VOID 升级后失去」的牌为例：

```csharp
protected override IEnumerable<…IHoverTip> ExtraHoverTips =>
[
    ..(base.IsUpgraded ? new …IHoverTip[]
    {
        … FATE …                 // ← 升级后：补上「获得的」
    } : Array.Empty<…>()),
    … ECHO …,                    // ← 一直在的：升级前后都有
    … VOID …                     // ← 「失去的」：只在没升级时有
];
```

* 升级后那段：从「一直在」那组里**真的剔掉**失去的，再补上升级后获得的；
* 没升级那段：本来就有「一直在」那组，再把失去的**并进来**。

第②条是顺手补齐的：以前「升级后失去」的那个词**连没升级时都没有悬停说明**
（`upDel` 谁都没用，等于这两栏的「失去」方向整个不起作用）。现在「没升级时有、升级后没有」，
才是完整的「失去」语义。

## 四、顺手对齐的一处自相矛盾

同一张牌上，如果某个词**既勾在「一直在」里、又填进「升级后失去」**：

* 卡面描述 → 以「失去」为准（升级后不显示）；
* 悬停说明 → 以前以「一直在」为准（升级后还显示）。

两处口径不一致。现在**统一以「失去」为准**，并且校验器会出一条**提示**把实际行为说清楚
（「升级前显示、升级后不显示；想升级前后都显示就把它从『升级后失去』里去掉」）。

> 注意这条**不是**矛盾，是一种「升级后拿掉」的写法。所以给的是「提示」不是「警告」，
> 而且**不拦生成** —— 你按自己的意思来就行。

## 五、验证

* **探针实测**（真生成 + 真 `dotnet build`）：
  * 「一直在 + 升级后获得 + 升级后失去」三个词 → 没升级/升级后两段都对，**0 错误**；
  * 边界档「升级后那段一个悬停说明都不剩」时的 `Array.Empty<…>` 分支 → 也 **0 错误**；
* `--uicheck` → **3778 PASS / 0 FAIL**（V0.2.176 是 3774，新增 4 条断言把这件事钉死：
  「升级后那段里没有失去的那条」「没升级那段里还在」「升级后那段不是空的」「卡面描述与悬停说明口径一致」）；
  自检夹具也一起改了 —— 以前 VOID 只写在「失去」栏，**升级后要不要丢掉它根本没有断言盯着**，
  这正是它能一直漏过去的原因；
* `--samplegen` 与 V0.2.143 基线对拍：113 个文件里仍然**只有 2 个不同**
  （`ExampleMod.sln` 的随机 GUID、`SevenGuard.cs` 的 `GainsBlock` —— 后者是 V0.2.170 起就有的既知差异），
  **没有扩大**。没填那两栏的存档走的还是老路径，逐字节不变。
