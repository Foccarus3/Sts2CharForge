# V0.2.76 更新说明

> 按你的两条反馈改的：
> ①「关系符的结果**连不到** if 的条件」—— 老版「条件」是【if】右边的一个**出口**，
> 那一头只能**往外**拖，方向存下来是反的，生成端根本看不到；
> ②「这样看起来好怪」—— 条件那条链（对象 → 状态 → 关系符）从左边进来才顺。
> 所以这一版把【if】的「条件」**从右边出口挪到了左边入口**，和别的模块一样「来源出口 → 目标入口」。

## 现在的【if】长这样

```
   接入 ──┐                 ┌── 是   （条件成立 → 这支）
          │   if            │
   条件 ──┘                 └── 否   （条件不成立 → 这支）
```

- 左边上面「**接入**」= 执行链：谁领到这一块（【触发时机】/【指向对象】/别的分支）；
- 左边下面「**条件**」= 接一个能出「成立 / 不成立」的模块的**结果**出口
  （【条件】/【且】/【或】/【关系符】都可以）；
- 右边「**是**」「**否**」两支各走一条分支（生成成 `if` / `else`）。

顺带一个好处：老版「接入」和「条件」在存档里**编号都是 0**（一个入口一个出口），
只能靠类型猜；现在一个是入口 0、一个是入口 1，**不撞车了**。

## 你的老存档不用重连（自动迁移）

打开存档时会做一次迁移（存档里记了版本号，只做一次）：

1. 老版那条「**从条件口往外拖**」的线（`if.条件 → 【对象】`）：
   顺着它找到**条件链末尾那个能出布尔的模块**（你那张是 `对象 → 状态 → 关系符` 里的**【关系符】**），
   把它的「**结果**」接进新的「条件」入口 —— 条件那条链**不会丢**，打开就是连好的；
2. 「是」从出口 1 挪到 0、「否」从 2 挪到 1（**不会对调** —— 这是迁移里最要紧的一条）；
3. 老版没用的残留线删掉；已经是新版的存档一个字不动（幂等）。

> 我在**你的存档副本**（`SparkleMod.json`）上跑过：迁移完 `SparkleCard40` 那个 if 的条件口
> 就接着【关系符】的结果了，「配置检查」里那条「条件恒为不成立」也消失了。

## 顺带修掉的三个「静默失效」

这一轮为了对好端口，把整条链路（画布 → 积木视图 → 生成端 → 校验器）都用**同一套判据**重新对了一遍，
发现并修掉三处会**一声不吭**出错的地方：

**① 从「条件」口往外拖，现在会被当场拦下。**
它是**入口**（往里插来源），不是出口。落错口以前是放行的，存下来的线方向反了、生成端看不到 ——
正是你踩的那个坑。现在拦住并说明：要判断「某个敌人身上的状态大于 N」该按哪三步接。

**② 积木视图写回时会把「取值槽」那条线写反。**
【数值】→【效果】的「数值」口、【对象】→【状态】的「归属」这种线，写回时方向弄反了
（写成 `效果.1 → 数值`）。生成端按「谁接到数值口上」找来源，读不到就**静默退回模块上填的常数**——
表现就是「数值块明明连了，但算的是另一个数」。现在方向固定是「子块的出口 → 父块那个入口」，
而且「切到积木再切回来」**逐字不改图**（探针里有一条专门断言：图里每条线 `FromPort` 都必须是真出口）。

**③ 拖块时放不进去的情况不再悄悄写一条无效的线。**
以前把一块拖进【对象】里面（它没有「取值口」）会写出一条指向不存在出口的线：块看着在、实际什么都不做。
现在会**当场说一句**（状态行），块留在原处。

## 积木视图也跟着改了

- 【if】那一块下面先列它的「**条件：**」那条链（以前条件块是「挂」在 if 名下的，看不出是判断依据），
  再是「**是：**」「**否：**」两个分支标题 + 「（if 到这里结束）」收口；
- 拖进【效果】/【状态】这种块里面 = 放进它的**取值口**（类型配得上才放得进去）；
- 拖进【且】/【或】、或把类型对不上的块拖进取值口 —— 都会被拒绝并说明原因。
