# V0.2.128 更新说明

> 这一版做的是《锻造优化.md》的**第 1、2 条**：**锻造页的数值栏现在能填参数/公式**，【触发时机】变成**固定模块（删不掉）**并新增「**这张牌被保留时**」。
> 第 3 条（锻造【效果】模块与卡牌页效果编辑器合并成一套）是大改，留到下一版。

## 一、锻造页的数值栏能填参数/公式了

锻造页里**所有能填数字的地方（12 处）**现在都能填**参数或公式**：

| 模块 | 栏位 |
|---|---|
| 【触发时机】 | 血量阈值 / 到达 N 层 / 每 N 次 |
| 【能量】 | 能量费用 / 额外资源量费用 |
| 【效果】 | 数值 / 生效次数 / 命中次数 / 概率 |
| 【条件】 | N / M |
| 【关系符】 | 右值 |

三档输入、语义分明：

- **纯数字** → 和以前**一模一样**（老存档的生成结果逐字不变）；
- **生成期常量公式**（`1+1`、`A+3`，`A` 是「固定数值」参数）→ 生成时就折叠成那个数；
- **运行时公式**（`X` 当前能量 / `Y` 当前额外资源量 / 自定义参数 / 内置只读量如 `HandCount`、`Turn`）→ 打出时现算。

配套：

- **填错不再被悄悄吞掉**：以前公式解析不出来会**静默变成默认值**，现在校验器会指出是哪个模块的哪一栏、什么原因；
- 界面上数字框会**描红（写错）/ 标蓝（公式）**，ToolTip 与布顶那行写清**可用量清单**，`…` 按钮可以直接插入参数与内置只读量；
- 积木摘要里也会把公式显示出来（以前被吞掉，看不到）；
- 卡面描述同步：次数/概率/条件 N·M/关系符右值写公式时，卡面印的是**算出来的数和公式本身**（不是那个用不上的固定值）。

⚠ **【能量】那两栏（能量费用 / 额外资源量费用）只收「生成时就算得出来」的数** —— 本体的卡牌费用要求编译期常量，所以那里写 `X` 会被校验器**报错拦住**（写 `1+1`、`A+3` 这种可以折叠的没问题）。

## 二、【触发时机】固定模块 + 新增「这张牌被保留时」

- 【触发时机】现在和左上角的【能量】一样是**固定模块**：**删不掉、全选（Ctrl+A）也带不走**（状态栏会给一句说明）。它**照常可以选中、拖动摆位置**（位置本来就是你摆的）。
- 新增时机「**这张牌被保留时**」（卡牌档）：本体没有「牌被保留」的独立回调，走的是丢手牌那一步交出来的名单 —— `AfterFlush(…, retainedCards)` + `retainedCards.Contains(this)`，所以「有保留关键词 / 这回合被单回合保留 / 整手牌都不丢」三种情况都算。

## 三、顺手修掉的既有 bug

1. 卡牌档挂在**没有 `cardPlay` 参数**的钩子上（被消耗 / 被丢弃 / 被抽到 / 被保留）时，生成出来的代码会引用不存在的 `cardPlay` → **CS0103 编译不过**。现在会自动补 `CardPlay? cardPlay = null;`。
2. 锻造节点图生成的代码，以前会被「从工程恢复」当成**卡牌时机 / 遗物触发时机**去解析 → 平白报 6 条「没认出来」。现在整段跳过（**恢复出来的字段更干净**，见下面第五节）。

## 五、已知边界（都没动手，留给你定）

1. **锻造节点图仍然不能被「从工程恢复」还原**（这是老问题，不是这一版引入的）：工程里只有编译结果，节点图本身只存在存档里 —— 所以恢复出来的锻造卡会**丢掉图**（实测：4 张锻造卡恢复后 `ForgeGraph` 全空）。要真支持得给生成端加「整张图的标记 / 内嵌 JSON」，建议**单开一版**做；
2. **费用栏只收编译期常量**（见第一节的 ⚠）；要让费用也能运行时算，得动卡牌费用模型；
3. 三个运行时公式的语义小边界：临时增益的「数值」写公式时按**正数那条路**生成（公式算出负数不会走扣层那条路）；「生命值在 N%~M% 之间」写公式时用 `Min/Max` 排区间，**没有**复刻常数档「任一负 = 区间外」的约定；「仅生效 N 次」写公式时一定会生成计数，公式算出 ≤0 时那一支一次都不跑；
4. 三条既有未修项（这一版没碰）：锻造条目「布是空的」在**图非空**时也会假报警；遗物/锻造卡的「生效次数复位」override 在回读时会被认成**多一条触发时机**；挂在非 `OnPlay` 时机上的锻造卡会留一个空 `OnPlay`（只有 CS1998 警告，0 错误）。
