# V0.2.311 — 覆盖血条「两个状态却有 3 个颜色」：红条被缩了两次

用户截图 + 原话：

> 状态覆盖血条显示异常（两个状态却有 3 个颜色）

## 查到的真因

截图里敌人的血条（58/58，满血，身上 **2 个** 状态，图标各 2 层）右端出现 **3 段颜色**：
黄（`#FFFF00` 染色：黄）、粉红（`#FF6464` 染色：红）、橙。

逐像素量了一下：两段是我们画的覆盖条（黄 + 粉红），最右边那 12px 的橙色 **不是** 配置里的颜色 ——
它是本体的 `%HpMiddleground`（`health_bar.tscn` 里 `modulate = Color(1, 0.498, 0)` = **#FF7F00**，
就是「掉血 / 回血预览」那条）。

它为什么会露出来：**红条被缩了两次**。

* 补丁以前在 `RefreshForeground` **和** 它的调用方 `RefreshValues` 上**各打一次**；
* 而 `RefreshValues` 内部第一句就是 `RefreshForeground()` ⇒ 同一次刷新我们的 Postfix 跑**两遍**：
  1. 第一遍：按本体的「当前血量右端」把红条缩短 12×N 像素（给覆盖条让位）；
  2. 第二遍：读到的 `red.OffsetRight` 已经是第一遍写进去的值，又缩了一次；
* 结果：红条右端比覆盖条左端多退了「一整截」，最右边那 12px 没人盖 → 露出橙色的预览条。
  2 个状态就这么变成了 3 段颜色。

（顺带说明：这也解释了为什么「有时候看着对、有时候不对」—— 取决于最后一次刷新走的是哪个入口。）

## 改法（两层）

1. **只打一个入口**：现在固定打 `RefreshForeground`（真正画血条的那个）；只有在**找不到它**时
   才退而求其次接它的调用方 `RefreshValues`（二选一，绝不同时打）。加载日志里会写清走了哪条。
2. **幂等记忆**：Postfix 里用一个 `ConditionalWeakTable` 记住「上次我们自己写进去的偏移」和
   「写之前的本体原值」。如果读到的就是自己写的值，就用**本体原值**当基准 —— 万一哪天本体多调一次、
   或者两个入口同时生效，也不会把红条越缩越短。

## 你要做的

重新生成 + 构建安装（`② 一键构建 + 安装`）即可，配置不用改。生成后血条上应当只有
你配置的那几段颜色（2 个状态 = 2 段），最右端不再有橙色小条。

  ModEntry 里是「一主一兜底」分支、整份工程 **`dotnet build` 0 错误**。

  「两个入口都接」的断言按新设计改掉）。
