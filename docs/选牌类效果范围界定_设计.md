# 选牌类效果「范围界定」设计（需求 ③）

> 状态：**未实现**。这份文档是接手用的施工图 —— 2026-10-04 的会话做到了 V0.2.46，
> 上下文用尽前把设计、确切位置和踩过的坑固化在这里。需求原文：
> 「(3) 所有可选牌的效果种类都增加**范围界定**（与生成 / 变化卡牌一致）」。

## 一、目标行为

「生成卡牌 / 变化卡牌」早就有两档：**取卡方式**（`SpawnPick` = 指定卡 / 按范围随机）+ **范围限定**
（`SpawnFilter` = 不限 / 攻击 / 技能 / 能力 / 诅咒 / 状态 / 自定义关键词分组）。
现在要把**同样那两档**给下面这些「能选牌 / 对牌动手」的效果种类：

| # | Kind | 现在怎么选牌 |
|---|---|---|
| 1 | `ExhaustCard` 消耗卡牌 | 手牌 / 抽牌堆，自己选或随机 |
| 2 | `DiscardCard` 丢弃卡牌 | 同上 |
| 3 | `TransformCard` 变化卡牌 | 同上 |
| 4 | `UpgradeCard` 升级卡牌 | 手牌 / 抽牌堆 / 弃牌堆 |
| 5 | `GiveKeyword` 给予卡牌关键词 | 手牌 / 抽牌堆 / 弃牌堆（0 = 这张牌自己） |
| 6 | `CopyCard` 复制卡牌 | 手牌 / 抽牌堆 / 弃牌堆 |
| 7 | `ReplayCard` 重放卡牌 | 同上 |
| 8 | `TurnEndPlay` 回合结束时自动打出 | 同上（0 = 这张牌自己） |
| 9 | `TakeFromDraw` 从抽牌堆拿牌到手牌 | 抽牌堆 |
| 10 | `TakeFromDiscard` 从弃牌堆拿牌到手牌 | 弃牌堆 |
| 11 | `TakeFromExhaust` 从消耗牌堆拿牌到手牌 | 消耗牌堆 |
| 12 | `Scry` 预见 | 抽牌堆顶 N 张（可以一张都不丢） |

三个上下文都要接：**卡牌**（`CSharpCodeGen.EmitCardEffect`）、**遗物 / 触发时机**
（`EmitRelicEffectOnce`，注意 `hasContext` 守卫）、**药水**（`EmitPotionEffect`）。

## 二、复用的现成机制（别另造一套）

| 东西 | 在哪 |
|---|---|
| `EffectSpec.SpawnFilter`（空 = 不限）/ `SpawnPick` / `SpawnChoice` | `Profile/Profile.cs`（`SpawnPick` 的 setter 里 Raise 显隐属性） |
| 选项表 `SpawnFiltersFor(profile)`（6 档 + `Keyword:XXX` 分组） | `Effects/EffectCatalog.cs` |
| `IsKeywordFilter` / `KeywordFilterKey` / `KeywordFilterPrefix` / `KeywordGroupCards` / `SpawnFilterZhFor` | 同上 |
| 显隐：`Profile.ShowSpawnFilter => UsesSpawnOptions && IsSpawnRandom` | `Profile/Profile.cs`（改 Kind / SpawnPick 时都要 Raise） |
| 界面那一行 | `App.xaml`：「范围限定」Grid 绑 `ShowSpawnFilter`，`ItemsSource={Binding SpawnFilters}`（`MainWindow.xaml.cs`：`EffectCatalog.SpawnFiltersFor(_profile)`） |
| 候选池表达式 | `CSharpCodeGen.SpawnPoolExpr(...)`（生成 / 变化用），照它写一个共用的 |
| 生成期标记行 | `CSharpCodeGen.SpawnMarker(e)` → `CET:SpawnPick=… CET:SpawnFilter=… CET:SpawnChoice=…` |
| 回读 | `ProjectRecovery`：`pendingSpawn` + `ApplySpawnOpts`，已认 `CET:SpawnFilter=([^\s]+)` |
| 校验器 | `ProfileValidator`：已有「自定义关键词分组不存在 / 是空组」那条检查，复用写法 |

## 三、做法

1. **字段与显隐**：新增 `EffectSpec.UseCardScopeFilter`（这个种类支不支持范围界定）与
   `Profile.ShowCardScopeFilter`（界面上那一行的显隐：`UseCardScopeFilter && IsSpawnRandom`）。
   **直接复用 `SpawnFilter` 字段本身**（同一份选项表、同一套文案），不要新建 `CardScopeFilter`。
2. **共用候选池过滤表达式**：抽一个 `CardScopeFilterExpr(e, p)`（生成期）返回形如
   `__pool.Where(c => c.Type == CardType.Attack)` / `c.Rarity == CardRarity.Curse` / 关键词分组那套的表达式；
   范围为空时返回 `__pool`（**行为与现在完全一致**）。
3. **接进 12 个种类 × 3 个上下文**：在「取候选（手牌 / 某一摞 / 抽牌堆顶 N 张）」之后、选牌 / 随机之前套上过滤。
   注意每一处的兜底：
   - 过滤后候选为空 → **不要弹空选牌界面**，直接跳过（参考「重放卡牌」的 `__replayPool` 兜底写法）；
   - 「自己选」与「随机」两条路都要过同一份过滤；
   - `Scry` 是对「抽牌堆顶 N 张」再过滤（丢了任意张），语义上最容易出错，最后做。
4. **卡面描述**：用到范围限定时写清（例：「从**攻击牌**里选 1 张消耗。」/「从「命运」那一组里随机丢 1 张。」），
   沿用生成 / 变化那边的措辞（`EffectCatalog.SpawnFilterZhFor(p, filter)`）。
5. **标记与回读**：这些种类已经有 `SelfContainedMarker`（`CET:Effect=…`）或逐行实现，
   把 `CET:SpawnFilter=` 也带上（`SpawnMarker` 已经会写），回读端确认 `pendingSpawn` 能配到这些种类上
   （`ApplySpawnOpts` 现在只对 `UsesSpawnOptions` 的效果生效，要按新名单放宽）。
6. **校验器**：范围为「自定义关键词分组」但那个组是空的 → 报错（复用现有写法）；
   另外给一条「范围 + 取牌方式」的说明（随机 / 自己选）。
7. **文档**：README 与 `tools\使用说明.template.txt` 各加一节。

## 四、上一次尝试为什么失败（必读）

2026-10-04 早先那轮把一个子代理派去做 ③，做到一半被叫停、改动**整体还原**（工作区一度半成品）。
复盘出的具体问题：

- 子代理在 `EffectSpec.Kind` 的 setter 里**重复**写了两遍 `Raise(nameof(UsesCardScopeFilter)); Raise(nameof(ShowCardScopeFilter));` —— 加完新属性后一定要检查 Raise 只留一处；
- 它给 `Naming.cs` 第 1 行加了 UTF-8 BOM、还把 `SpawnFilter` 的 setter 重排成多行 —— **纯格式改动会让 diff 变脏**，别做；
- `Naming.CurrentProfile` 这种「静态兜底」可以留，但**凡是手上已经有 profile 的调用点都要显式传参**；
- 范围界定如果只在「按范围随机」那一档显示，就要和生成 / 变化**完全同一套显隐规则**，否则用户会找不到入口
  （历史上就报过「找不到在哪限定范围」）。

## 六、顺带提醒（本会话新建立的套路，写新效果时用得上）

- 新增「自包含效果」四处配套：`SelfContainedMarker`（生成期标记）→ `ProjectRecovery` 的
  `selfContainedKind` 精确跳过名单 → `CSharpCodeGen.HasNoDynamicVar` → `CSharpCodeGen.AmountIsStrength`；
- 需要新生成「辅助 Power / 状态」时：`Naming` 加类名 → `CSharpCodeGen.XxxSource` + `NeedsXxx` 门控 →
  `ModGenerator` 里按门控 `WriteText`（参考 `DrawCostPower.cs` / `NoHealPower.cs`）；
- 需要 Harmony 补丁时：把补丁类放进那个辅助类**同一个文件**即可（`ModEntry` 里是 `harmony.PatchAll(程序集)`），
  并且**别用「前缀返回 false」去跳过 async 方法**（原方法返回 `Task`，跳过后调用方 await 到 null 会炸）；
- 回读的整段跳过名单里，**没有独特记号**的实现行要按 `selfContainedKind` 精确跳过
  （`ForbidBlock` 正数分支就踩过：会多回读出一条 `ApplyPower(NoBlockPower)`，等于下次生成多叠一次）。
