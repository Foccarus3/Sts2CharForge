# V0.2.148 更新说明

> 修你报的：「**升级后费用里面填不了 Y 和 X，但是填过之后什么都没有也会报错**」。

## 一、两个真因（都在「升级后额外资源量费用」那一栏）

1. **填不进去的样子**：那一栏的显示逻辑以前**只认绝对数字**——你填 `Y`（或填了一个看不懂的式子）时，
   工具把它记在「原文」字段里，但框子读的是「绝对数字」，于是**框子显示成空**，看着就像「填不进去」。
   现在（和左边「升级后费用」那一栏同款）**原文也认**：填了 `Y`，框里就一直显示 `Y`。
2. **清空之后错误还在**：那一栏**清空时没有把「原文」一起清掉** → 那句「升级后额外资源量费用看不懂：X」
   永远留在配置检查里，改不掉（你说「填过之后什么都没有也会报错」就是它）。
   现在清空、或改成数字，都会把原文一起清掉。

## 二、顺带把「Y」这一档从「报错」改成「合法」

`Y` 在「升级后额外资源量费用」里的意思是「**升级后还是 Y**」——而本体**根本改不了 X 那一档的资源量费用**，
所以它等价于「升级不改」，生成端本来就什么都不用写。以前工具却把它当成「看不懂」报错拦住了。

- 现在：填 `Y` → **合法**（等价于留空，不生成任何 `UpgradeStarCostBy`），配置检查只给一句「提示」；
  如果你这张牌当前的「额外资源量费用」**不是** Y，则给「警告」（写了也不生效，Y 会被当成 0）。
- 仍然做不了的是「**升级后 Y+1**」：本体 `UpgradeStarCostBy` 碰到「额外资源量费用 = X」的牌会
  **直接抛异常**（`UpgradeStarCostBy called on … which has star cost X.`）——
  这一档现在会**明确报错**并告诉你怎么办（想固定花 N 点，请先把「额外资源量费用」从 `Y` 改成数字）。

另外：「升级后费用」（**能量**那一栏）现在也照样支持 `X`（= 升级后还是 X，等于不改）与 `X+1`；
如果把 `Y` 填进了这一栏，报错里会顺带提示「这一栏是能量费用，Y 请填右边那一栏」。

## 三、验证（都是重新跑一遍的数字）

- `dotnet build Sts2CharForge.sln -c Debug` → **0 错误**；
- `--uicheck`：Debug **3373 PASS / 0 FAIL**、发布版（本版正式 publish 出来的 exe）**3373 PASS / 0 FAIL**
  （本版新增 9 条断言：填 `Y` 框里看得见 / 填 `Y` 不报错且不生成 `UpgradeStarCostBy` /
  **非法 → 清空后错误必须消失**（就是你这个 bug）/ 非法 → 改数字后原文一起清掉 /
  `Y+1` 报错并说清本体原因 / X 费牌填 `X` 与 `X+1` 都过 / 固定资源量费用的牌填数字照样生成 `UpgradeStarCostBy(2)` /
  `Y` 填错栏的提示）；
- **红线①默认输出不变**：`--samplegen` 与 V0.2.143 基线对拍 **112 个文件逐字节一致**（只差 `.sln` 的随机 GUID）——
  本版只改了「配置检查怎么写报错」+「那一栏的显示/清空」，没有动任何老写法的生成结果；
- 探针（`_tmp` 自造存档）实测：`Y` 费牌 + 升级后 `Y` → 生成通过、源码里没有 `UpgradeStarCostBy`；
  升级后 `Y+1` → 报错（文案里带本体那行异常）；`X` 费牌 + 升级后 `X+1` → 生成
  `decimal __X = ForgeFormulaRuntime.Energy(base.Owner) + (base.IsUpgraded ? 1 : 0);`。
