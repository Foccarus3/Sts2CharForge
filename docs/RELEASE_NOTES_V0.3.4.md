# V0.3.4 — 斩杀时「升级卡牌（全局）」在只剩一只怪时不生效

## 原因

「斩杀」判的是**这一击有没有把目标打死** —— 结果要等伤害结算完才知道，所以这条效果只能排在伤害**之后**。
而这一击要是把**最后一只怪**打死，战斗立刻进入结束流程，牌组 / 牌堆类操作就再也没机会跑 → 升级没生效。

（V0.2.372 已经处理过同一类问题，但当时只把「**需要选牌**」的斩杀效果提前；
「升级卡牌（全局）」不弹选牌，所以没被提前，仍然排在伤害之后。）

## 改法

把「提前到伤害之前」的名单从「需要选牌」扩到**动牌组 / 动牌堆 / 给奖励**这一类：

* 升级 / 变化 / 移除 / 加进牌组（全局）：`UpgradeCardGlobal` `TransformCardGlobal` `RemoveCardGlobal` `AddCardGlobal`
* 生成卡牌 `GenerateCard`、卡牌奖励 `CardReward`
* 从抽牌堆 / 弃牌堆 / 消耗牌堆拿牌 `TakeFromDraw` `TakeFromDiscard` `TakeFromExhaust`

它们仍然用同一段**斩杀预判**顶着（`Hook.ModifyDamage` 算出这一击的真实伤害 ≥ 目标当前生命），
只有「这一击真的会打死」时才执行 —— 所以语义没变，只是抢在战斗结束之前跑完。

**没动的**：伤害 / 上状态 / 加格挡这类效果**不会**被提前（提前跑没有意义，还会改变「先打再上状态」的语义）。

这个顺序成立（预判=1634、升级=2076、伤害=2368））。

## 你需要做的

更新到 **V0.3.4** → 重新生成 → 构建安装。再用那张「斩杀时升级」的牌去杀场上最后一只怪，牌组里那张应该会被升级。

## 仍然存在的边界（如实说）

斩杀预判只看**伤害数值 vs 目标当前生命**，**不含格挡**（格挡在伤害结算时才扣）。
所以「目标有格挡、伤害刚好够打穿血量」这种极窄情形，预判会认为「会斩杀」而实际没打死 ——
此时升级会照做（提前跑了），但怪没死。真遇到再告诉我，我把格挡算进预判。
