# V0.2.215 —— 锻造卡【能量】里写 `X`（消耗全部能量）不再被拦：X 费 / Y 费真的接上了

> 来源：用户截图（生成失败对话框）——卡牌「虚化」（升级前 / 升级后）：
> 「【能量】的『打出时消耗的能量』只能填**生成期就算得出来的数**……『X』里用了运行时才算的量」。

## 1. 自相矛盾的一处

那一栏的界面提示一直写着：**「X = 消耗掉的能量」**（本体「消耗全部能量」那套，`HasEnergyCostX`），
可校验器把它当「运行时值」**报错拦住**，于是 X 费卡根本建不出来 —— 用户被自己的提示卡死。

## 2. 现在真的接上了

- 【能量】的「打出时消耗的能量」写 **`X`** → 这张牌按**本体 X 费**生成：
  ```csharp
  protected override bool HasEnergyCostX => true;
  public XuHuaProbe() : base(0, CardType.Skill, CardRarity.Common, TargetType.Self) { }
  …
  decimal __X = base.ResolveEnergyXValue();   // = 打出时**消耗掉的**能量（不是剩余能量）
  ```
- 「打出时消耗的额外资源量」写 **`Y`** → `public override bool HasStarCostX => true;`、`__Y = ResolveStarXValue()`。
- `X+1` / `X+2`（升级后 +N）也认（本体那套 `(base.IsUpgraded ? N : 0)`）。
- 校验器现在只拦**真正做不到**的量（读血量 / 读状态 / 内置只读量…），报错文案里补一句
  「也可以写 X（消耗全部能量）/ Y（消耗全部额外资源量，只有那一栏认）」。
- 界面上那一格：填 `X`/`Y` **不描红也不标蓝**，改成绿色提示「✓ X 费：打出时消耗全部能量（本体 HasEnergyCostX）」；
  提示文字也改了（以前写「X / Y 不能用」，现在写清 X / Y 能用、别的实时读数不能）。

## 3. 红线

- 费用那两栏填**普通数字 / 常量公式（1+1 / A+3）**时，生成文本与以前逐字一致
  （没有 `HasEnergyCostX`、`__X` 仍是「剩余能量」那套）；
- 老存档逐文件对拍：示例 **113** / WhiteCloak **412** 个文件 **0 差异**（只差 `.sln` 的 GUID）；
- 你那份 `AinodiMod.json` 重新生成：429 个文件里**只有 `.sln` 的 GUID 不同**。
