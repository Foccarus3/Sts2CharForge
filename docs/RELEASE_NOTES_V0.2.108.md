## 一、锻造页【能量】填的费用，现在真的是「这张牌的费用」了

**你猜的方向不是接线问题** —— 那块【能量】是固定模块、不靠连线生效；问题是它以前**没有声明成卡牌费用**：

- 生成时写的是「打出时偷偷扣一次」：`await PlayerCmd.LoseEnergy(1m, __fgPlayer)` + `SetStars(...)`；
- 卡牌自己的费用一直是 `CardSpec.Cost` = **0**（锻造卡在「卡牌」页没有费用栏，所以这个 0 没人改），
  于是**卡面、游戏里都是 0 费**，可打出后确实扣了 1 能量 + 1 额外资源量。

现在按本体的正规做法：

| 【能量】那一栏 | 生成成什么 | 本体行为 |
|---|---|---|
| 能量 `N` | 卡牌构造函数 `base(N, …)` | 卡面显示 N 费；能量不够时**打不出去**；打出前自己扣 |
| 额外资源量 `M` | `public override int CanonicalStarCost => M;`（本体星星费用） | 不够时禁止打出（`UnplayableReason.StarCostTooHigh`）；卡面费用数字变红；打出前自己扣 |
| 两块布填得不一样 | 升级后那块为准 → `OnUpgrade` 里 `base.EnergyCost.UpgradeBy(差值)` | 和本体「升级后费用变少」一个写法 |

同时：

- **不再扣第二次**：打出时那两句 `LoseEnergy` / `SetStars` 删掉了
  （本体 `PlayCardAction.ExecuteAction` 是**先 `SpendResources()` 再 `OnPlay`**，所以钩子里已经是扣完的值）；
- **X / Y 的数值一个字都没变**：以前是「没扣 − 费用」，现在是「本体扣完」，两者相等 ——
  已经用【能量】算子过公式的存档，生成出来的数值结果和以前一样；
- 「卡牌」页的卡牌列表里也显示布上那个费用了（以前显示 `0 费`，还得点进去看那行只读提示）；
- **费用还是 0 的锻造卡逐字不变**（老写法 `- 0m` 那两行原样保留，红线照旧）。

⚠ 行为变化说清楚：以前「【能量】= 1」的锻造卡**0 能量也能打出去**（扣到 0 为止），现在**需要 1 点能量**才能打
（这才是一张「1 费卡」该有的样子）。想「有能量就多花、没有也能打」请改用效果里的「花费能量」那种写法（数值填负数）。
