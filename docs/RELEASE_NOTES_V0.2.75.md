# V0.2.75 更新说明

> 修你报的「敌人身上有 4 层虚弱，打出去还是走了『我失去生命』那一支」——
> 根因是【if】的「条件」口**连反了**，而且生成端遇到这种情况**一声不吭**地按「不成立」处理。

V0.2.74 的内容（【指向对象】+【关系符】）也都在这一版里。

## 你报的现象：虚弱 > 3 还是走了「否」

我把你的存档 `SparkleMod.json` dump 出来看，那张 `SparkleCard40` 的连线是：

```
触发时机 → 指向对象(单体敌人) → if            ← 执行链（正常）
if 的「条件」口 → 【对象】(单体敌人) → 【状态】(虚弱) → 【关系符】.左值     ← 条件那条链
                                                        └ 右值空着、**结果也没接到任何地方**
```

两个问题叠在一起：

1. **条件是「从 if 的条件口往外拖」连的**（方向反了）。存档里存的是 `if.条件 → 对象`，
   而生成端是按「**谁接到条件口上**」找来源的 —— 它根本看不到这条线。
2. 就算反过来拖（从【关系符】的「结果」拖到「条件」口），**画布以前会先把同下标的那条链线删掉**
   （【if】的「接入」和「条件」在存档里**编号都是 0**，「一个口只留一条线」把它们当成同一个口）
   —— 那样 if 就从执行链上掉下来，整块什么都不执行。

于是生成出来的条件是 `if (false)`（`BoolExpr` 找不到 Bool 来源时取 false），
**永远走「否」** —— 你看到的就是「我失去生命」。

## 这一版修了什么

**① 画布：连线按「种类」去重。**
【if】的「接入」（执行链）和「条件」（插槽）现在能**同时存在**：连条件不会再把链线删掉，
连链线也不会把条件删掉；同类仍然只留一条（连第二条条件会替换第一条）。

**② 画布：不许从「条件」口往外拖。**
「条件」是「往里插来源」的口，从它出发拖出来的线方向是反的、生成端看不到 ——
现在直接拦住并提示：**请从【关系符】的「结果」拖到它上面（右 → 右）**。
（以前这么拖是**放行**的，就是这一条把你带进坑里。）

**③ 配置检查：条件没接就报错，并写出三步接线。**
以前条件口空着 / 接的不是布尔模块时，生成端静默取 false。现在：

> 【if】的「条件」口其实**没有接条件**（那条线是执行链的「接入」，接的是【指向对象】）——
> 生成出来的条件是**恒为「不成立」**，所以永远只会走「否」那一支。
> 把【条件】/【且】/【或】/【关系符】的**结果**出口拖到【if】的「条件」口上。要判断「某个敌人身上的某个状态大于 N」：
> ①【状态】(那个状态) 的「数值」出口 → 【关系符】的「左值」；②【数值】(N) 的出口 → 【关系符】的「右值」；
> ③【关系符】的「结果」出口 → 【if】的「条件」口；（【状态】左边的「归属」接【对象】= 那个敌人）

**④ 顺手修掉校验器自己的一个判据不一致。**
它当时是「看那个口上的**第一条**线」，而生成端是「找那条**能出布尔**的线」——
两条线同下标共存时，校验器会误报「条件口没接条件」。现在两边用**完全一样**的判据
（这也正是①之后必须修的一处，不然你补对了线它还会报错）。

**⑤ 【关系符】的结果没接到任何地方 → 警告。**
「这一块白算了」这种情况以前看不出来。

## 你这张牌修好之后长这样

（我在你的存档副本上按正确方式补了那条线，再生成——现在是这样的）

```csharp
Creature? __fgTarget = cardPlay.Target;                                     // 【指向对象】= 指定单体敌人
decimal __pA = ForgeFormulaRuntime.PowerAmount(__fgSelf, "VulnerablePower"); // A = 自己身上的易伤
decimal __fg1 = ForgeFormulaRuntime.PowerAmount(__fgTarget, "WeakPower");    // 那个敌人的虚弱
if (((__fg1) > (3)))                                                        // ← 真的在判断了
{
    decimal __fg2 = (__pA + (3m));
    await DamageCmd.Attack(__fg2).FromCard(this, cardPlay).TargetingAllOpponents(base.CombatState).Execute(choiceContext);
}
else
{
    foreach (Creature __fgFoe in ForgeFormulaRuntime.AllAllies(__fgPlayer))
        await CreatureCmd.Damage(choiceContext, __fgFoe, (5m), ValueProp.Unblockable | ValueProp.Unpowered | ValueProp.Move, this, cardPlay);
}
```

生成出来的工程**真 `dotnet build`：0 个错误**。

## 你要做的（两步）

1. 打开那张卡的节点图（**升级前和升级后两块布都要**——你的存档里两块布都有这个 if）：
   **删掉**「从【if】的『条件』口拖到【对象】」那条线（现在画布也会主动拦住这种连法）；
2. 把 **【关系符】的「结果」** 拖到 **【if】的「条件」** 上（右 → 右）。
   （右值不接也行 —— 会用【关系符】上填的数字；你那张是空的，按默认 3 算。）

改完「配置检查」里那条错误会消失，生成出来的条件就是上面那句 `if (((__fg1) > (3)))`。
