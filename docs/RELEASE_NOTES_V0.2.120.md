## 一、① 「临时增益 / 临时减益」：补上本体那套 `ITemporaryPower`

「临时增益」是「这一回合 +X 层，到点还原」，生成端早就是照本体「尖啸 PiercingWail」那套写的
（`BeforeApplied` 里静默施加真状态 / `AfterPowerAmountChanged` 补增量 / 到点 `Remove(this)` + 施加 `-base.Amount` 还原）。
本版把**本体那套接口**补齐并端到端验证：

- 生成的临时状态类现在声明 `: PowerModel, ITemporaryPower`，并实现两个成员：
  `public AbstractModel OriginModel => this;` 与
  `public PowerModel InternallyAppliedPower => ModelDb.Power<真状态>();` ——
  本体好几处（「痛苦 Misery」「幻觉」「扒手」「不安之灯」，以及「减益」成就徽章）都靠这个接口
  认出「这只是临时挂上去的，不是真的状态」；
- 四种档位都对着本体核过：

| 档位 | 生成的做法 |
|---|---|
| 正数（本回合 +X 层） | `BeforeApplied` 里 `PowerCmd.Apply<真状态>(…, amount, …, silent: true)`（本体 FlexPotion 同款） |
| 负数且**本体允许负层数**（力量 / 敏捷 / 专注…） | **照本体「尖啸」**直接把负数施加进去（目标本来 0 层也能扣成负数） |
| 负数且**本体不允许负层数**（虚弱 / 易伤…） | 先 `GetPower<真状态>()` 再 `ModifyAmount(-N)` 扣已有层数（目标身上没有那个状态时什么都不做） |
| 「下回合开始才撤」（撑过敌人的回合） | 撤除时机从 `AfterSideTurnEnd` 换成 `AfterPlayerTurnStart`，其余照旧 |

- **拦住说清**（以前会「配了等于没配」）：
  - 「数值 0」→ **错误**：本体 `PowerCmd.Apply` 收到 0 会**在第一行直接 return**，打出去一点变化都没有
    （这正是用户报的「临时增益不生效」），提示里给出「填 5 / 填 -5 / 写数值公式 / 填升级增量」四条出路；
  - 「没选状态」→ **错误**：`未选择有效的 Power（可以选本体的状态，也可以选「自定义状态」页里自己造的那个）`。

**验证**（探针 `_tmp\tempprobe`，2026-10-09）：

- 四条卡（正数 / 负数-允许负层 / 负数-不允许负层 / 下回合撤）+ 一只遗物 + 一瓶药水；
- 生成出来的 `cs\TempPowers.cs` 共 5 个类，全部 `: PowerModel, ITemporaryPower`；
- 对着**真游戏程序集**编译：生成的工程引用 `libs\sts2.dll`（与游戏目录里那份 SHA256 完全相同，
  且该 DLL 里就有 `ITemporaryPower` / `InternallyAppliedPower` / `OriginModel`）→
  「编译 DLL（dotnet build）」**OK，0 错误**（`cs\TempPowers.cs` 本身 0 警告 0 错误）；
- `--recover` 回读：六条 TempPower 效果的 `PowerId / Amount / TempPowerReverse / TargetSide`
  **6/6 逐字段一致**，TempPower 相关「没认出来」**0 条**。

## 二、④ 遗物侧的「只对哪类牌生效」（和状态侧同一套）

遗物页的【触发时机】选「**打出一张牌后**」时，下面多出「**只对哪类牌生效**」，
候选和状态页**同一份**：任意 / 攻击 / 技能 / 能力 / **诅咒 / 状态 / 关键词：XXX / 组：XXX**。

| 新档 | 生成出来的判据 |
|---|---|
| 攻击 / 技能 / 能力 | `if (cardPlay.Card.Type != CardType.Attack) return;`（判据和状态侧同一句，遗物侧写成守卫式 return） |
| **诅咒** | `cardPlay.Card.Rarity == CardRarity.Curse` |
| **状态** | `cardPlay.Card.Type == CardType.Status \|\| cardPlay.Card.Rarity == CardRarity.Status` |
| **关键词：XXX / 组：XXX** | 你配的「自定义关键词 / 组」里那一组牌，展开成显式 `ModelId` 判据 |

五处配套都做了：

- **生成**：老四档判据和状态侧逐字同款；新档复用卡牌那边同一套 `ScopeCondForFilter` 谓词
  （「组里有哪些牌」的算法只有一份，不会漂移）；**选「任意」时一个字都不多**（老存档生成结果逐字不变）；
- **回读**：筛选不是「任意」时写一行 `// CET:CardFilter=<筛选值>`，`--recover` 原样认回来
  （判据是展开出来的，从代码反推不回来）；**老四档没有标记行**，靠那句
  `cardPlay.Card.Type != CardType.Attack` 守卫反推（和状态侧同一个口径）；
- **卡面 / 文案**：遗物描述里会写出来 —— 例「打出一张牌后（只对攻击牌生效）：获得 3 点格挡。」，
  游戏里玩家能看出这只遗物挑牌；
- **校验器**：选了「关键词组 / 组」但**那一组里一张牌都没有** → **错误**拦住（生成出来会是 `if (false)`，
  这条时机永远不会触发）；时机不是「打出一张牌后」却填了筛选 → 提示「这个值不生效」（不静默）；
- **界面**：遗物属性里、触发时机下拉的**正下方**；只在选「打出一张牌后」时出现（换时机要当场显隐，已接通知）。

### ④ 后半段：锻造页【触发时机】和遗物页合并成同一套

动手前锻造页的遗物档只有 **11** 条时机，遗物页有 **29** 条 —— **缺 20 条**（战斗结束 / 造成伤害 /
花掉能量 / 花掉额外资源量 / 生成卡牌时 / 到达 N 层 / 打出一张牌后 / 消耗·抽到·弃掉一张牌 /
失去生命 / 获得格挡 / 敌人死亡 / 敌人回合开始·结束 / 敌人受到·造成·获得格挡 / 层数变化 / 被移除 …）。
这一版全部补齐，并且**不是只把菜单列出来**：

- **Id / 显示名 / 钩子名逐字照抄遗物页那份**（`EffectCatalog.RelicTriggers`，单一事实来源）。
  自检断言「去掉锻造页专属的两条后，两边 id 集合**双向相等**」——实跑打印
  「锻造共享 29 条 / 遗物页 29 条；多=（无） 少=（无）」；
- **签名只留一份**：锻造页遗物档直接 `return CSharpCodeGen.RelicTriggerSignature(t.Id)`，不再抄第二份。
  （唯一变长的文本是「受到攻击后」那条签名：老的裸 `AttackCommand` 在生成的 GlobalUsings 下会 CS0246，
  换成全限定名是修 bug；其余 8 条既有遗物时机签名逐字未变，默认输出不受影响。）
- **归属守卫同一套**：新增 `CSharpCodeGen.ForgeTriggerGuardLines(...)`（遗物页那个 `switch` 的等价副本），
  在锻造页钩子体开头按 8 空格缩进写。以前锻造页的遗物图**一条守卫都没有** ——
  敌人打我 / 敌人打牌 / 别人掉血都会触发「你自己的」锻造遗物。遗物页那份文本**一个字没动**；
  嵌进遗物自己钩子的那种（`ForgeGraphOnTrigger`）不重复写守卫（那个普通方法没有钩子参数，写了会 CS0103）；
- **choiceContext**：本体没给、但在战斗里能自己造的那几条（花掉能量 / 花掉额外资源量 / 生成卡牌时 /
  失去生命 / 获得格挡 / 敌人回合开始 / 敌人获得格挡 / 被移除 / 血量低于 N）造 `HookPlayerChoiceContext`；
  「获得时」造阻塞式的；造不出来的（战斗胜利后 / 战斗结束 / 获得金币 / 当遗物被点击时）
  由校验器**报错拦住** —— 需要 context 的效果绝不许静默变成 `null!` 在运行时炸；
- **「盯哪个状态 / 到达 N 层」**：【触发时机】模块新增这两栏（状态那栏可打字搜索），
  只在这三条时机下显示；
- **顺手修掉 4 个既有生成 bug**（都属于「生成出来是错的 / 什么都不做」）：
  1. 节点图里的「抽牌」生成的是 `CardPileCmd.DrawCards(...)` —— 本体**没有**这个方法（CS0117）→
     改 `CardPileCmd.Draw(choiceContext, count, player)`；
  2. 两只「当遗物被点击时」的遗物 → 补丁文件里两行用了同一个局部变量 `__fgRelic`（CS0128）→
     拆成 `__fgRelic0/1`；
  3. 遗物 / 药水图里的「全体伤害」「生成卡牌」写 `base.CombatState` —— `RelicModel` 上**没有**这个属性
     （CS0117）→ 按 scope 取 `base.Owner.Creature.CombatState`；
  4. 「仅生效 N 次」填 **0**（= 无限次）时生成 `if (__fgUses >= 0) return;` —— 这句**恒成立**，
     于是「血量低于 N」「当遗物被点击时」的图**原来一次都不会执行**；现在填 0 不再写那道门。

> **已知、本版没修的边界**（已记进 `docs\QUEUE.md` 待办）：遗物自己的触发时机是
> 「每回合开始时 / 战斗胜利时」，同时节点图里用了「当遗物被点击时 / 血量低于 N」**且**
> 填了「仅生效 N 次（N > 0）」时，两处生成的复位 override 会撞 **CS0111**（防重名只比了图那条钩子）。
> 避开办法：这类组合把「仅生效次数」留 0（无限次），或把图挪到别的触发时机上。

## 三、顺手修掉：卡牌数值「迁成公式」后**回读成 0**（并在报告里刷「升级增量找不到对应效果」）

第 9 批 ① 的探针跑出 11 条「没认出来」，追下去发现是**与临时增益无关**的一个老坑：

- **根因**：V0.2.112 起，卡牌上的固定数值在打开存档时会自动**迁成公式**，声明跟着变成
  `new ForgeFormulaDamageVar(static (card, target) => (7m))`（施加状态那个是泛型
  `ForgeFormulaPowerVar<VulnerablePower>(…)`）。而回读的变量解析正则要求 `(` 后面**紧跟数字字面量**，
  于是这类变量**整条都没被认出来**；
- **后果有两层**（都很致命）：① 变量表里整条缺失 → 卡的**基础数值全部回读成 0**
  （再保存一次就真的把配置写成 0 了）；② `OnUpgrade` 的升级增量对不上效果 →
  报告里刷一片「升级增量找不到对应效果（变量 Damage）」，用户以为配置丢了；
  另外这张牌**后面**那几个变量在表里的次序还会整体前移，按顺序配的数值可能串到别的效果上；
- **修法**：两种声明按**声明顺序**合并进同一张变量表（顺序 = 生成代码里的顺序，红线）；
  公式里的常数（`(7m)`）当作数值；真·现算公式取不到常数就记 0 ——
  数值本身由生成端的 `// CET:AmountFormula=` 标记负责还原，这里只要「种类 + 名字 + 顺序」对；
- **实测**（拿探针生成的工程直接回读）：修前「打击 / 防御 / 七式斩 / 七的重压 …」的基础数值**全是 0**、
  11 条没认出来；修后**打击 6（升级 +3）、防御 5（升级 +3）** 都回到本体原值，**0 条没认出来**；
- **不动点验证**（最硬的一条）：「生成 → 回读 → 再生成 → 再回读」两个来回，
  回读出来的存档**逐字节一致**（同一个 SHA256），全程 0 条「没认出来」——
  说明这套往返是真正无损的，不是「碰巧没报错」；
- 自检加了三断言：迁成公式的固定数值回读成 7（不是 0）、升级增量 +3 认得回来、这一轮 0 条「没认出来」。

## 四、顺手补：发布包里不再带「来自网络」标记 + 说清「无法验证发布者」那个框

有用户（包括本机自检）遇到过双击时弹：

> **打开文件 - 安全警告**：无法验证发布者。你确定要运行此软件吗？（发行商：未知发布者）

**这不是程序坏了、也不是杀毒在拦**：exe 没有代码签名证书，而 Windows 认为文件「来自网络」
（从浏览器下载的 zip 解压出来的文件各带一份 NTFS 备用数据流 `Zone.Identifier`），
未签名程序被这个标记一标，双击 / `start` / `Start-Process`（走 ShellExecute）就会先问一次。

- **发布侧**：`tools\release_all.ps1` 在 `dotnet publish` 之后新增一步「清掉发布目录里的
  『来自网络』标记」（逐个文件查 `Zone.Identifier` → `Unblock-File`）——
  这个标记**会跟着 `Copy-Item` 传播**（某台机器上 NuGet 缓存里的 apphost 带了标记就可能被复制进
  「程序文件」），所以打出来的包里保证没有它；
- **文档侧**：`tools\使用说明.template.txt` 与 `README.md` 都写清了这个框是什么、怎么一次解决
  （右键 exe → 属性 → 勾「解除锁定」；**更彻底**是先解除 zip 的锁定再解压；
  已解压的可以 `Get-ChildItem -Recurse -File | Unblock-File`）；
- **自检脚本侧**：后台自动化里**不要**用 `Start-Process` 起发布出来的 exe（会被这个框卡住），
  直接调用（`& $exe --uicheck`）走 CreateProcess、不弹框。

## 五、顺手补：源码备份 + 编码体检（防止「源文件被写坏又发现不了」）

2026-10-08 出过一次事故：某个工具把 `MainWindow.xaml.cs` 按错代码页重写了一遍（UTF-8 字节被当
CP936 读出、再按 UTF-8 写回），文件变成一坨乱码还丢了字节；而当时 git HEAD 还停在 V0.2.51
（落后 68 个版本）、手边**一个干净副本都没有**，只能拿已发布 DLL 里的字符串当「预言机」反推。现在补两道闸：

- `tools\backup_src.ps1`：把源码树（`src` / `tools` / `docs` / `README.md` / `.gitignore`）整份快照到
  `..\_备份\源码\源码_<时间戳>\`，附 `清单.tsv`（每个文件的 SHA256），默认留最近 30 份；
- 同一个脚本做**编码体检**：非法 UTF-8 字节 / `U+FFFD` / 私用区 PUA（U+E000~U+F8FF，就是那坨乱码的特征），
  命中返回退出码 1；平时可 `-Check` 只体检、`-List` 看快照、`-Keep N` 改保留份数；
- `release_all.ps1` **每次发版自动先跑一遍**（在改动任何东西之前），体检命中就**中止发布**
  （要跳过加 `-SkipBackup`）；
- `README.md` 与 `docs\QUEUE.md` 都写清了用法，并记下一条教训：发版建议带 `-Commit` 让 git 历史跟上 ——
  昨天难救的根因就是 68 个版本没提交。
