# 插件开发规范（V0.2.339）

> 一句话：把插件文件夹丢进 **`plugins\`**（程序目录下，和 `Sts2CharForge.exe` 同级），
> 编辑器「插件」页点「重新加载插件」就能用。插件只认 **JSON 清单 + C# 代码模板**，不加载 DLL。

---

## 1. 目录结构

```
Sts2CharForge.exe
plugins\
├─ 示例插件\                    ← 一个插件 = 一个文件夹（文件夹名随便，不用和 id 一样）
│  ├─ plugin.json               ← 必须叫这个名字（也允许直接放 plugins\我的插件.json）
│  ├─ cs\PluginDemo.cs          ← 可选：跟模组一起编译的 C#（会被拷进生成工程 cs\Plugins\<id>\）
│  └─ assets\...                ← 可选：其它要一起打包的文件
└─ 我的插件\
   └─ plugin.json
```

* 扫描位置：`<程序目录>\plugins\*\plugin.json` 和 `<程序目录>\plugins\*.json`。
* 任何一个插件坏掉，**只影响它自己**（「插件」页里标 ⚠ 并写明原因），编辑器照常启动。
* 插件里引用的自带文件必须落在**插件自己的文件夹内**（越界路径会被拒绝）。

## 2. `plugin.json` 全字段

```jsonc
{
  "id": "example",                  // 必填：插件唯一标识（英文/数字/下划线，字母开头）
  "name": "示例插件（可删）",         // 显示名
  "version": "1.0",                 // 插件自己的版本（显示用）
  "apiVersion": "1",                // 必填：清单版本。目前只支持 "1"；写别的会被拒绝加载（并说明原因）
  "author": "Sts2CharForge",
  "description": "一句话说明",
  "readme": "Markdown 文本（编辑器「插件」页里显示）",

  "effects": [                      // 效果种类（本版**已接入生成**）
    {
      "kind": "PluginHealAndBlock", // 必填：种类 id（英文/数字/下划线，字母开头）
      "display": "插件示例：回复生命并给等量格挡",  // 下拉里显示的名字
      "unit": "点",
      "min": 0, "max": 99,          // 数值框范围
      "needsTarget": false,         // 是否显示「作用对象」那一栏
      "needsPower": false,          // 是否显示「增益 / 减益」那一栏
      "needsCard": false,           // 是否显示「目标卡」那一栏
      "note": "说明（可选）",
      "emit": "await CreatureCmd.Heal({self}, {amount});\nawait CreatureCmd.GainBlock({self}, {amount}, ValueProp.Move, null);"
    }
  ],

  "triggers": [                     // 触发时机 = 本体已有钩子的别名 + 一句额外守卫（V0.2.316 起已接入生成）
    { "id": "OnEnemyBlocked", "display": "敌人获得格挡时", "hook": "EnemyBlockGained",
      "guard": "if (creature == base.Owner.Creature) return;", "hasChoiceContext": true }
  ],
  "conditions": [                   // 条件 = 一段布尔表达式（V0.2.316 起已接入生成）
    { "id": "HasBlock", "display": "自己有格挡", "expr": "base.Owner.Creature.Block > 0" }
  ],
  "forgeModules": [                 // 锻造模块 = 图上的【效果】节点 + 模板（V0.2.316 起已接入生成）
    { "kind": "PluginPing", "display": "插件示例模块", "emit": "/* … */" }
  ],
  "pages": [                        // 额外内容页：默认在编辑器「插件」页里按插件分栏显示
    { "id": "howto", "title": "怎么写插件", "markdown": "正文…" },
    // tab 填了就是「生成器页签的扩展页」（V0.2.339）：card / relic / potion / power / forge / build
    { "id": "cardnote", "title": "卡牌备注", "tab": "card", "markdown": "这一页挂在「卡牌」页下面" }
  ],

  "csFiles": [ "cs/PluginDemo.cs" ],        // 随模组一起编译（→ 生成工程 cs\Plugins\<id>\）
  "assetFiles": [ "assets/icon.png" ]       // 随模组一起打包（→ 生成工程 plugin_assets\<id>\）
}
```

## 3. 效果模板（`emit`）—— 本版唯一会影响生成结果的插件能力

`emit` 里写**普通 C# 语句**（可以多行），生成时替换下面这些占位符（大小写不敏感）：

| 占位符 | 含义 | 卡牌链 | 遗物链 | 药水链 | 自定义状态链 | 锻造图 |
|---|---|---|---|---|---|---|
| `{amount}` | 这条效果的数值 | 数值框里的数字（`3m`）；卡牌上「数值 = X」时是那个 `x` 变量 | 数值框里的数字 | 同遗物 | 勾了「数值 = 本状态的层数」时是 `(int)base.Amount`，否则数值框里的数字 | 图上【数值】入口算出来的（公式 → 局部变量） |
| `{amountFormula}` | 同 `{amount}`（语义更明确的名字，V0.2.338） | 同 `{amount}` | 同 | 同 | 同 | 同 |
| `{self}` | 「自己」 | `base.Owner.Creature` | `base.Owner.Creature` | `base.Owner.Creature` | `base.Owner` | `__fgSelf` |
| `{player}` | 玩家 | `base.Owner` | `base.Owner` | `base.Owner` | `base.Owner.Player` | `__fgPlayer` |
| `{foe}` | 「指定敌人」 | `cardPlay.Target` | 第一个可打的敌人 | 第一个可打的敌人 | 触发器的目标 / 第一个敌人 | `TargetOrFirst(__fgTarget, __fgPlayer).FirstOrDefault()` |
| `{target}` / `{targetOrFirst}` | 同上（V0.2.337 加的别名，和 `{foe}` 同一个表达式） | ✔ | ✔ | ✔ | ✔ | ✔ |
| `{choice}` | `choiceContext` | `choiceContext` | 该钩子的 context（没有时是 `null!`） | `choiceContext` | `choiceContext` | 该执行点的 context |
| `{cardSelf}` | 这张牌 | `this` | `this`（遗物自己） | `this`（药水自己） | `null` | `this` |
| `{power}` | 这条效果「增益 / 减益」选的状态类名 | ✔ | ✔ | ✔ | ✔ | ✔ |
| `{card}` | 「目标卡」选的那张牌的类名 | ✔ | ✔ | ✔ | — | ✔ |
| `{spawnCardType}` | `ModelDb.Card<目标卡>()` 表达式（V0.2.338） | ✔ | ✔ | ✔ | ✔ | ✔ |
| `{combatState}` | 战斗状态（V0.2.338） | `base.Owner.Creature.CombatState` | 同 | 同 | `base.Owner.CombatState`（状态类的 `base.Owner` 本身就是 Creature） | `base.Owner.Creature.CombatState` |
| `{cardPlay}` | 本次出牌的 `CardPlay`（V0.2.338） | `cardPlay` | ✗（没有这个变量，用了编不过） | ✗ | ✗ | ✗ |
| `{state}` | 「这个状态实例」（V0.2.338） | `this`（牌自己，别当状态用） | `this`（遗物自己） | `this`（药水自己） | `this`（**只有这条链有意义**） | `this` |

**规则**

* 只能写**本体 API**（`CreatureCmd` / `PowerCmd` / `CardPileCmd` / `PlayerCmd` …）或你自己 `csFiles` 里的类；
  生成工程顶部已 `using MegaCrit.Sts2.Core.Commands;` 等（见生成工程的 `cs\GlobalUsings.cs`）。
* 数值：插件效果**只认数值框里的数字**。卡牌页上「数值公式」那一栏对插件效果**只认光秃秃的 `X`**
  （=「数值 = X」，这时 `{amount}` 就是那个 `x` 变量；写别的公式会被校验器拦住）。
  要按公式算，请在模板里自己写表达式（或调 `csFiles` 里的方法）。
  「升级增量」那一栏对插件效果**不显示**（要改升级后的值，请在模板里自己判 `base.IsUpgraded`）。
* 模板里不要写 `using` / `namespace` / `class`：它会被塞进方法体。要加类就放 `csFiles`。
* 每条效果执行一次；「生效次数 / 概率」这些通用栏位对插件效果**不生效**（插件自己控制）。
* `{cardPlay}` 只有卡牌链真有；`{state}` 只有状态链有意义。模板要跨链复用时按链判断
  （比如同一段模板别在状态链上写 `{cardPlay}`）。

### 3.1 「变化这张牌」的宏：`{transformSelf:类名}`（V0.2.338）

「把这张牌变成另一张」是本工具踩过坑的动作：打出的牌此刻躺在「打出」那一摞里，
直接 `CardCmd.Transform` 会把新牌塞回同一摞、战斗结束就看不见。所以给一个宏，写：

```jsonc
"emit": "{transformSelf:CarmenCrimsonScarAlteration}"
```

展开成验证过的写法（1 张换 1 张）：

```csharp
CardModel __plugMade1 = base.Owner.Creature.CombatState.CreateCard(ModelDb.Card<CarmenCrimsonScarAlteration>(), base.Owner);
await CardPileCmd.Add(__plugMade1, PileType.Discard);
if (this.Pile is not null) await CardCmd.Exhaust(choiceContext, this);
```

没有「这张牌」的链（状态 / 遗物 / 药水，以及**不是卡牌**的那几张锻造图）只做前半句（新牌进弃牌堆）——
那些链的 `this` 是状态 / 遗物 / 药水对象，没有 `CardModel.Pile`，写那句会 CS1061（V0.2.339 修正）。
一个模板里可以写多个（最多展开 16 个，各自的局部变量叫 `__plugMade1` / `__plugMade2` …）。

## 4. 生成 / 打包怎么走（需求③）

1. 生成工程时，**自带文件**会被拷进去：
   * `csFiles` → `cs\Plugins\<插件 id>\…`（`Microsoft.NET.Sdk` 会把它一起编进模组的 dll）；
   * `assetFiles` → `plugin_assets\<插件 id>\…`（留在工程里，随工程一起打包）。
2. 「② 一键构建 + 安装」照旧：插件内容跟着 mod 的 dll / pck 一起出去，**不需要额外操作**。
3. 插件效果生成的代码和其他效果在同一个方法体里，**可以相互混用**（需求①）——
   同一个效果列表里既有编辑器自带的效果、也有插件效果，彼此不冲突。

---

## 5. 兼容约定（需求②：编辑器升级不失效）

* 清单是**纯数据**：`apiVersion` 只在「清单结构变了」时才升；升级编辑器**不会**让老清单失效。
* 编辑器不加载插件的 DLL / 不反射插件类型，所以编辑器升级（甚至换 .NET 版本）不影响插件读取。
* `emit` 模板里引用的是**本体 API**（游戏侧），不依赖编辑器内部类；
  本体 API 变了要改的是模板（和编辑器自带效果一样要跟着改）。
* 以后若新增字段，会**只加不改**：老清单缺的新字段一律按默认值处理。

## 6. 调试

1. 「插件」页 →「重新加载插件」→ 左边列表点插件看详情：
   贡献了哪些效果、哪些触发时机 / 条件 / 模块（本版仅登记）、自带文件、问题列表。
2. 出了问题先看 ⚠ 列表：
   * `plugin.json 解析失败` → JSON 语法错（注意不要用尾随逗号以外的扩展语法）；
   * `清单版本 apiVersion … 不受支持` → 改成 `"1"`，或用新版编辑器；
   * `效果 kind … 重名` → 换个 kind；
   * `没写 emit 模板` / `自带文件不存在` → 按提示补。
3. 插件效果生成出来编不过：把生成的 `cs\Cards\...cs` 里那几行和本体 API 对照
   （模板里写错一个方法名就是 CS0103/CS1061）。

## 8. 自定义页框架（V0.2.319）

**不再只是说明页**：插件可以声明自己的页，编辑器渲染成表单，生成工程时按模板写成文件 ——
**页面内容完全由插件决定**，编辑器只提供底盘（控件 / 存值 / 预览 / 写文件）。

```jsonc
"pages": [
  {
    "id": "events",                 // 页面 id（存值用）
    "title": "事件",                // 页签标题
    "markdown": "这一页干什么（可空）",
    "fields": [                     // 栏位（空 = 纯说明页，按 Markdown 显示）
      { "key": "EventClass", "label": "事件类名（英文）", "type": "text",   "default": "MyEvent" },
      { "key": "EventName",  "label": "事件名",          "type": "text",   "default": "我的事件" },
      { "key": "Weight",     "label": "权重",            "type": "number", "default": "1" },
      { "key": "Repeatable", "label": "可重复",          "type": "bool",   "default": "0" },
      { "key": "Kind",       "label": "类型",            "type": "pick",   "options": ["普通","战斗","诅咒"], "default": "普通" },
      { "key": "Intro",      "label": "开场白",          "type": "multiline", "default": "" }
    ],
    "target": "cs/Plugins/{id}/Events/{EventClass}.cs",   // 写到工程的相对路径
    "emit": "public static class {EventClass} { public const int Weight = {Weight}; }"
  }
]
```

* **栏位类型**：`text` / `number` / `bool`（值渲染成 `1` / `0`）/ `pick`（`options` 里选）/ `multiline`。
* **占位符**：`emit` 和 `target` 里都能用 `{字段key}`；`target` 另外支持 `{id}`（插件 id）。
  `target` 里的值会自动去掉路径非法字符（中文 / 空格会变成下划线）。
* **生成时机**：点「生成工程」时，所有带 `fields` + `target` + `emit` 的页会被渲染成文件写进工程
  → 于是随 mod 一起编译 / 打包（`cs/Plugins/...` 下的 `.cs` 会编进 dll）。
* **值存哪**：`plugins/<插件 id>/values.json`（每页一组值）。改了插件清单不会丢；想重置就删这个文件。
* **手动写入**：页面上有「保存这些值」「生成到当前工程」两个按钮（改完不必重新生成整个工程）。
* **安全**：`target` 越界（`..\`）会被拒绝；写失败只丢这一页，不影响生成。

> 这条扩展点的意义：像「事件生成器」这种**编辑器本来不认识**的内容，插件也能自己定义页面 + 产物，
> 编辑器不需要为它写任何专用代码。你只要保证 `emit` 产出的代码在本体里能编译 / 能注册。

## 9. 把页面挂到生成器页签上（`pages[].tab`，V0.2.339）

默认插件的页在「插件」页右边出现。填了 `tab` 就不一样了 —— 这一页会作为**那个生成器页签里的扩展页**出现，
用户在编辑卡牌的同一屏就能看到它：

```jsonc
"pages": [
  {
    "id": "cardnote", "title": "卡牌备注", "tab": "card",
    "fields": [ { "key": "Note", "label": "备注", "type": "text", "default": "" } ],
    "target": "cs/Plugins/{id}/Notes/{Note}.cs",
    "emit": "// 由 {id} 生成"
  }
]
```

| `tab` 填什么 | 挂到哪个页签 |
|---|---|
| （不填 / 空串） | 「插件」页（老行为） |
| `card` | 卡牌 |
| `relic` | 遗物 |
| `potion` | 药水 |
| `power` | 自定义状态 |
| `forge` | 锻造 |
| `build` | 构建 / 日志 |

* **界面怎么显示**：那个页签底部会多出一条「插件扩展页（N）— 页1、页2」的折叠条，点开是一排页签
  （一页一个），页里的内容就是第 8 节那套（Markdown / 表单 / 预览 / 保存 / 生成到当前工程）。
  默认**收起**，不会挤占生成器本来的地方；没有扩展页的页签一点变化都没有。
* **别重复画**：挂走的页**不再**在「插件」页重复出现（那里只留在「信息」页里的一句说明，
  和「哪些页挂到哪儿」的清单）。
* **写错的值**：`tab` 写成别的（例如 `cards`）不算错误 —— 这一页照旧留在「插件」页，
  「插件」页的插件详情里会写一行「tab「cards」不认识（可用：card / relic / …）」。
* **插件本身有问题（⚠）时**：整份内容都不生效，页也不会挂过去（还是留在「插件」页里给你看）。

## 10. 给生成器加一个**一级功能页**（`pages[].newTab`，V0.2.340）

上面第 9 节是「钻进已有页签」；这一节是「**让生成器多一个自己的页**」——
就像「角色」「药水」「锻造」那样的一级页签。装上一个「怪物生成器」插件，生成器顶部就多一个
「怪物生成器」页：

```jsonc
"pages": [
  {
    "id": "monsters",
    "title": "怪物生成器",        // 一级页签的标题
    "newTab": true,               // ← 这一行就是「新功能页」
    "markdown": "填好东西点下面的按钮，会生成到工程里。",
    "fields": [
      { "key": "MobClass", "label": "怪物类名（英文）", "type": "text", "default": "MyMob" },
      { "key": "MobHp",    "label": "血量",             "type": "number", "default": "40" },
      { "key": "Kind",     "label": "类型",             "type": "pick", "options": ["普通","精英"], "default": "普通" }
    ],
    "target": "cs/Plugins/{id}/Mobs/{MobClass}.cs",
    "emit": "public static class {MobClass} { public const int Hp = {MobHp}; public const string Kind = \"{Kind}\"; }"
  }
]
```

* **位置**：固定插在「构建 / 日志」**前面**（不动现有页的相对顺序）。多个插件都有功能页时，
  按插件加载顺序 + 清单里的页顺序排。
* **页里是什么**：就是第 8 节那套（说明 / 表单 / 实时预览 / 「保存这些值」/「生成到当前工程」）。
  生成工程时也会自动按 `target` + `emit` 把值写成文件 → 随 mod 一起编译 / 打包。
* **拿不到编辑器数据**：功能页只有自己那一份值（`plugins/<插件 id>/values.json`），
  读不到当前存档里的角色 / 卡牌 / 遗物，也拿不到本体名录。所以「点开某张卡、右边多一栏」
  这种做不了 —— 做得到的是「填表 → 出文件」。
* **一份值对应一页**：不是「每个怪物一份」（要多个条目就在模板里自己按行/逗号拆，或者开多个页）。
* **同名页**：两个插件给了同一个 `title` 时，页签标题会自动带上插件名（`重名页（我的插件）`），
  不会出现两个一模一样的页签。
* **`tab` 和 `newTab` 一起填**：按 `newTab` 算（`tab` 忽略），「插件」页的详情里会写一行说明。
* **页不重复画**：`newTab` 的页不在「插件」页重复出现。
* **插件本身有问题（⚠）时**：不挂（页留在「插件」页里给你看问题）。
* **插件删掉 / 重新加载**：页签跟着消失 / 重建；如果当时正停在这个页签上，会退回第一个页签。

## 11. 动态行集合：`type = "list"`（V0.2.349「能适配的框架」）

以前的栏位只能表达「一个值」（文本 / 数字 / 开关 / 下拉 / 多行文本）。要写「招式列表」「怪物列表」「掉落表」
这类**多行、可增删**的界面就做不出来 —— 现在加了一个栏位类型：`list`。

### 11.1 怎么声明

```json
{
  "id": "moves-page",
  "title": "招式列表",
  "target": "cs/Plugins/{id}/Mobs/{Mob}.cs",
  "fields": [
    { "key": "Mob", "label": "怪物类名", "type": "text", "default": "DemoMob" },
    {
      "key": "moves", "label": "招式", "type": "list", "itemLabel": "招式", "defaultRows": 2,
      "fields": [
        { "key": "name", "label": "招式名", "type": "text",   "default": "Tackle" },
        { "key": "kind", "label": "类型",   "type": "pick",   "options": ["攻击", "防御", "上状态"], "default": "攻击" },
        { "key": "dmg",  "label": "数值",   "type": "number", "default": "6" }
      ]
    }
  ],
  "emit": "public static class {Mob}\n{\n    public static readonly string[] Moves =\n    {\n    {moves}\n        \"[{index}] {name}（{kind}，{dmg}）\",\n    {/moves}\n    };\n}\n"
}
```

* `list` 栏位自己的 `fields` 是**每行的子栏位**（`text / number / bool / pick / multiline` 都支持；
  **子栏位不能再是 `list`**，嵌套列表 v1 不支持，加载时会报一条问题）；
* `itemLabel` = 行标题口径（不填就用 `label`）；`defaultRows` = 第一次打开时给几行空行；
* 界面自动长出「+ 添加一行」和每行的「↑ / ↓ / 删除」，插件不用写任何 WPF。

### 11.2 emit 里的块宏

```
{key}
  …这一段的每个子栏位占位符，按**这一行**的值替换…
{/key}
```

* 块可以出现多次；块里除子栏位外还有 `{index}`（从 1 起）和 `{index0}`（从 0 起）；
* **块必须配对**：少一个 `{/key}` 就等于整段不展开（加载时会报「没配对」，不会静默失效）；
* 没写块的 list 栏位不产出任何文本；
* `target`（文件名）里**不能**用 list 栏位（文件名没法按行展开），写了会报问题。

### 11.3 行数据存哪

`plugins\<插件 id>\rows.json`：

```json
{ "moves-page": { "moves": [ { "name": "Slash", "kind": "攻击", "dmg": "6" } ] } }
```

**和 `values.json` 分开存是故意的**：老版本编辑器读到新数据时不会把整份 `values.json` 读坏
（它只是看不到列表内容）。有问题的页（`Problems` 非空）在生成时会被跳过，同插件的其它页照常。

### 11.4 这套框架能干什么 / 不能干什么

* 能：任意「多行数据 + 按行生成文本」的编辑器 —— 招式表、掉落表、事件分支表、生成器状态列表…
* 不能（v1）：嵌套列表、按列表值决定生成**几个文件**（一页仍然只产出一个文件）、在页面里调用生成器的其它对象
  （比如从列表里下拉选一张已有卡牌 —— 需要「引用型栏位」，下一版再说）。

## 12. 插件效果的「数值」与「下回合生效」（V0.2.355 修正）

* **`{amount}` 现在全链一致**：卡牌 / 遗物 / 药水 / 状态 / 锻造图 五条链都会把**那条链算出来的表达式**传给模板
  （以前遗物 / 药水链固定传数值框里的字面量：填「数值公式」或「数值 = X」时插件效果拿到的是 0 / 旧值）。
  所以模板里直接 `CreatureCmd.Heal({self}, {amount});` 就行，不用自己判断是不是公式。
* **插件效果支持「下回合生效」**：勾上之后生成端会生成一个延迟状态类
  （类名 `<角色>ForgeDelayedPlugin<种类>`，写在 `cs/DelayedPowers.cs`），本回合只挂状态，
  下回合开始时执行**你的模板**；模板里的 `{amount}` = 那一刻状态上的层数（`base.Amount`）。
  以前这一栏对插件种类是**静默无效**的（当回合就执行了）。
* 同一种插件的多条效果**共用一个**延迟类（按种类去重），因为是运行时取层数，不按数值分叉。

## 13. 引用型栏位 `type = "ref"`（V0.2.356）

以前的栏位只能填**字面值**（文本 / 数字 / 选项），想引用「存档里的某张卡」只能让用户手抄类名 —— 抄错就静默生成不出东西。
现在有引用型栏位：下拉里列的是**当前存档里真实存在的对象**，存的是它的**稳定标识**（类名 / 组 Id）。

```json
{ "key": "Card",  "label": "挑一张卡",     "type": "ref", "refKind": "card" }
{ "key": "Power", "label": "挑一个自定义状态", "type": "ref", "refKind": "power" }
```

| `refKind` | 下拉里是什么 | 存的值 |
|---|---|---|
| `card` | 存档里的全部卡（普通 / 诅咒 / 先古 / 状态牌） | 生成端用的**类名**（留空自动编号的也按同一口径算出来） |
| `power` | 自定义状态 | 类名（留空自动 = `<角色>Power<N>`） |
| `relic` | 遗物 | 类名 |
| `potion` | 药水 | 类名 |
| `pet` | 召唤物 / 伙伴 | 类名（留空 = 序号） |
| `group` | 「自定义参数 / 组」里的组 | 组 Id |

要点：

* **换存档会自动重建这些下拉**（下拉里是那份存档的对象）；
* 值在存档里**已经找不到**时，下拉会显示 `（找不到：<旧类名>）` 并且**选中它** —— 不会静默变成空；
* `emit` 里就当成普通字符串用：`public const string CardClass = "{Card}";`；
* `refKind` 写错会报「页面问题」（不会给你一个永远空的下拉）；
* 列表字段（`list`）的**子栏位**也能用 `ref`（例：招式表里每一行引用一个状态）。

## 14. 一页多文件 / 按行产出 / 条件宏（V0.2.357）

### 14.1 `outputs[]`：一页写多个文件

老的写法是 `target` + `emit`（一个文件）。现在可以写 `outputs[]`：

```json
"outputs": [
  { "target": "cs/Plugins/{id}/Mobs/{Mob}.cs", "emit": "public static class {Mob} { }\n" },
  { "target": "cs/Plugins/{id}/Mobs/{Mob}Info.cs", "emit": "// 说明\n" }
]
```

写了 `outputs` 就以它为准（老的 `target` / `emit` 被忽略，方便渐进迁移）。

### 14.2 `forEach`：按 list 每一行各出一个文件

```json
{ "target": "cs/Plugins/{id}/Moves/{Prefix}{name}.cs", "forEach": "moves",
  "emit": "public static class {Prefix}{name} { public const int Damage = {dmg}; }\n" }
```

* `forEach` = **这一页里**某个 `list` 字段的 key；它每一行都会生成一个文件；
* `target` 和 `emit` 里都能用该行的**子栏位**，以及 `{index}`（1 起）/ `{index0}`（0 起）；
* 行的顺序就是列表里的顺序；**空列表 = 一个文件都不生成**（不是错误）；
* `forEach` 写成一个不存在的字段 → 报「页面问题」（不会静默生成 0 个文件）。

### 14.3 条件宏

| 写法 | 含义 |
|---|---|
| `{#字段}…{/字段}` | 这个字段**有值**才渲染中间那段 |
| `{^字段}…{/^字段}` | 这个字段**为空**才渲染（写「没填就先用默认值」的兜底） |

「有值」= 非空、且不是 `0` / `false` / `否`。按行产出时，**行内子栏位也能当条件**。

### 14.4 生成 / 预览

* 生成工程时 `PluginGen.WritePageTo` 按上面规则把文件都写进工程；界面的「生成到当前工程」按钮走同一份代码；
* 预览里按文件分段显示，每段前一行 `// ---- 文件：… ----`（按行的会写「按『字段』第 N 行」）。

## 15. 启用/禁用开关 & 值按存档隔离（V0.2.358）

### 15.1 启用 / 禁用

* 「插件」页选中某个插件 → 「信息」页顶部有一个 **启用这个插件** 勾选框；
* 关掉之后：它的**效果种类 / 触发时机 / 条件 / 页面**全部不生效（下拉里也看不到），
  `csFiles` / `assetFiles` 也**不随 mod 打包**；
* 插件文件**一个都不动**：开关存在 `plugins\_enabled.json`（只记「关掉的」那些 id，所以新装的插件默认启用）。

### 15.2 值按存档隔离（行为变化）

| | 以前 | V0.2.358 起 |
|---|---|---|
| 页面标量值 | `plugins/<id>/values.json` | `plugins/<id>/profiles/<存档 key>/values.json` |
| 列表行数据 | `plugins/<id>/rows.json` | `plugins/<id>/profiles/<存档 key>/rows.json` |

* **存档 key** = 当前打开的那份存档文件名（去扩展名、非法字符换成 `_`）；还没打开存档时是 `default`；
* **老文件仍然会读**：新位置没有文件时会读老位置，把它当作这个存档的初值（老文件不删、不搬）——
  所以升级后之前填的值不会丢；
* 换存档时界面会自动重建插件页（值 + 引用型下拉都跟着换）。

## 16. 效果的卡面文字与悬停说明（V0.2.359）

`effects[]` 里多了两个可选字段：

```json
{
  "kind": "PluginHealAndBlock",
  "display": "插件示例：回复生命并格挡",
  "text": "回复 {amount} 点生命并获得 {amount} 点格挡。",
  "hoverTip": "MegaCrit.Sts2.Core.HoverTips.HoverTipFactory.FromPower<MegaCrit.Sts2.Core.Models.Powers.DexterityPower>()",
  "emit": "await CreatureCmd.Heal({self}, {amount});\nawait CreatureCmd.GainBlock({self}, {amount}, ValueProp.Move, null);"
}
```

* **`text`** = 这个效果在**卡面 / 遗物 / 药水 / 状态描述**里写的那句话。留空 = 和以前一样不产生文字。
  * 占位符**只认 `{amount}`**：换成这条效果的数值；「数值 = X」时写 `X`；填了「数值公式」时写公式文本；
  * 写了别的 `{…}` 会被当成问题报出来（否则会**原样印在卡面上**）；
  * ⚠ 插件效果**不声明动态变量**，所以卡面写的是**字面数字**，不会跟着力量 / 敏捷实时变 —— 要实时变请让玩家看 `hoverTip` 或写在「自定义描述」里。
* **`hoverTip`** = 悬停说明的**C# 表达式**，原样写进那件东西的 `ExtraHoverTips` 列表（写错是编译期报错，不会静默失效）。
  可以直接写本体的 `HoverTipFactory.FromPower<T>()`，也可以写你自己的 `new HoverTip(new LocString(...), …)`。

## 17. 动态变量 `var`（V0.2.360）

给 `effects[]` 写一个 `var` 名字，卡面数字就**跟着实时值走**（力量 / 敏捷 / 升级都算），不再是写死的字面量：

```json
{ "kind": "PluginHealAndBlock", "var": "Heal",
  "text": "回复 {amount} 点生命并获得 {amount} 点格挡。",
  "emit": "await CreatureCmd.Heal({self}, {amount});\nawait CreatureCmd.GainBlock({self}, {amount}, ValueProp.Move, null);" }
```

生成端会做三件事：

1. **真的声明这个动态变量**：`CanonicalVars` 里出现 `new DynamicVar("Heal", <数值>)`；
2. **`emit` 里的 `{amount}` 变成 `base.DynamicVars["Heal"].BaseValue`** —— 代码和卡面用的是同一个值；
3. **`text` 里的 `{amount}` 变成 `{Heal:diff()}`** —— 卡面显示算出来的数字，升级预览里还有对比值。

约束：

* `var` 必须是合法标识符（英文/数字/下划线、字母开头），且**不能用 `X` / `Y`**（本体保留名），写错会在加载时报问题；
* 同一张牌上两条效果用了同一个 `var` 名 → 自动加后缀（`Heal2`），不会撞；
* 不写 `var` = 老行为：不声明变量、卡面写字面数字（含「数值 = X」写 X、「数值公式」写公式文本）；
* 遗物 / 药水也适用（它们的 `CanonicalVars` 同样会声明）。
