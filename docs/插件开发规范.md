# 插件开发规范（V0.2.315）

> 一句话：把插件文件夹丢进 **`plugins\`**（程序目录下，和 `Sts2CharForge.exe` 同级），
> 编辑器「插件」页点「重新加载插件」就能用。插件只认 **JSON 清单 + C# 代码模板**，不加载 DLL。

---

## 1. 目录结构

```
Sts2CharForge.exe
plugins\
├─ 示例插件\                    ← 一个插件 = 一个文件夹（文件夹名随便，不用和 id 一样）
│  ├─ plugin.json               ← 必须叫这个名字（也允许直接放 plugins\我的插件.json）
│  ├─ cs\PluginDemo.cs          ← 可选：跟模组一起编译的 C#（会被拷进生成工程 cs\Plugins\<id>\）
│  └─ assets\...                ← 可选：其它要一起打包的文件
└─ 我的插件\
   └─ plugin.json
```

* 扫描位置：`<程序目录>\plugins\*\plugin.json` 和 `<程序目录>\plugins\*.json`。
* 任何一个插件坏掉，**只影响它自己**（「插件」页里标 ⚠ 并写明原因），编辑器照常启动。
* 插件里引用的自带文件必须落在**插件自己的文件夹内**（越界路径会被拒绝）。

## 2. `plugin.json` 全字段

```jsonc
{
  "id": "example",                  // 必填：插件唯一标识（英文/数字/下划线，字母开头）
  "name": "示例插件（可删）",         // 显示名
  "version": "1.0",                 // 插件自己的版本（显示用）
  "apiVersion": "1",                // 必填：清单版本。目前只支持 "1"；写别的会被拒绝加载（并说明原因）
  "author": "Sts2CharForge",
  "description": "一句话说明",
  "readme": "Markdown 文本（编辑器「插件」页里显示）",

  "effects": [                      // 效果种类（本版**已接入生成**）
    {
      "kind": "PluginHealAndBlock", // 必填：种类 id（英文/数字/下划线，字母开头）
      "display": "插件示例：回复生命并给等量格挡",  // 下拉里显示的名字
      "unit": "点",
      "min": 0, "max": 99,          // 数值框范围
      "needsTarget": false,         // 是否显示「作用对象」那一栏
      "needsPower": false,          // 是否显示「增益 / 减益」那一栏
      "needsCard": false,           // 是否显示「目标卡」那一栏
      "note": "说明（可选）",
      "emit": "await CreatureCmd.Heal({self}, {amount});\nawait CreatureCmd.GainBlock({self}, {amount}, ValueProp.Move, null);"
    }
  ],

  "triggers": [                     // 触发时机 = 本体已有钩子的别名 + 一句额外守卫（V0.2.316 起已接入生成）
    { "id": "OnEnemyBlocked", "display": "敌人获得格挡时", "hook": "EnemyBlockGained",
      "guard": "if (creature == base.Owner.Creature) return;", "hasChoiceContext": true }
  ],
  "conditions": [                   // 条件 = 一段布尔表达式（V0.2.316 起已接入生成）
    { "id": "HasBlock", "display": "自己有格挡", "expr": "base.Owner.Creature.Block > 0" }
  ],
  "forgeModules": [                 // 锻造模块 = 图上的【效果】节点 + 模板（V0.2.316 起已接入生成）
    { "kind": "PluginPing", "display": "插件示例模块", "emit": "/* … */" }
  ],
  "pages": [                        // 额外内容页：编辑器的「插件」页里按插件分栏显示
    { "id": "howto", "title": "怎么写插件", "markdown": "正文…" }
  ],

  "csFiles": [ "cs/PluginDemo.cs" ],        // 随模组一起编译（→ 生成工程 cs\Plugins\<id>\）
  "assetFiles": [ "assets/icon.png" ]       // 随模组一起打包（→ 生成工程 plugin_assets\<id>\）
}
```

## 3. 效果模板（`emit`）—— 本版唯一会影响生成结果的插件能力

`emit` 里写**普通 C# 语句**（可以多行），生成时替换下面这些占位符（大小写不敏感）：

| 占位符 | 含义 | 卡牌链 | 遗物链 | 药水链 | 自定义状态链 | 锻造图 |
|---|---|---|---|---|---|---|
| `{amount}` | 数值（数值框里的数字） | 字面量 | 字面量 | 字面量 | 勾了「数值 = 本状态的层数」时是 `(int)base.Amount` | 图上算出来的表达式 |
| `{self}` | 「自己」 | `base.Owner.Creature` | `base.Owner.Creature` | `base.Owner.Creature` | `base.Owner` | `__fgSelf` |
| `{player}` | 玩家 | `base.Owner` | `base.Owner` | `base.Owner` | `base.Owner.Player` | `__fgPlayer` |
| `{foe}` | 「指定敌人」 | `cardPlay.Target` | 第一个可打的敌人 | 第一个可打的敌人 | 触发器的目标 / 第一个敌人 | `TargetOrFirst(__fgTarget, __fgPlayer)` |
| `{choice}` | `choiceContext` | `choiceContext` | 该钩子的 context（没有时是 `null!`） | `choiceContext` | `choiceContext` | 该执行点的 context |
| `{cardSelf}` | 这张牌 | `this` | `this`（遗物自己） | — | — | — |
| `{power}` | 这条效果「增益 / 减益」选的状态类名 | ✔ | ✔ | ✔ | ✔ | ✔ |
| `{card}` | 「目标卡」选的那张牌的类名 | ✔ | ✔ | ✔ | — | ✔ |

**规则**

* 只能写**本体 API**（`CreatureCmd` / `PowerCmd` / `CardPileCmd` / `PlayerCmd` …）或你自己 `csFiles` 里的类；
  生成工程顶部已 `using MegaCrit.Sts2.Core.Commands;` 等（见生成工程的 `cs\GlobalUsings.cs`）。
* 数值目前是**固定字面量**（状态链可读层数）。所以插件效果**不显示**「升级增量」那一栏，
  也不支持「数值公式」—— 要做这些请在 `csFiles` 里自己写方法，在 `emit` 里调用。
* 模板里不要写 `using` / `namespace` / `class`：它会被塞进方法体。要加类就放 `csFiles`。
* 每条效果执行一次；「生效次数 / 概率」这些通用栏位对插件效果**不生效**（插件自己控制）。

## 4. 生成 / 打包怎么走（需求③）

1. 生成工程时，**自带文件**会被拷进去：
   * `csFiles` → `cs\Plugins\<插件 id>\…`（`Microsoft.NET.Sdk` 会把它一起编进模组的 dll）；
   * `assetFiles` → `plugin_assets\<插件 id>\…`（留在工程里，随工程一起打包）。
2. 「② 一键构建 + 安装」照旧：插件内容跟着 mod 的 dll / pck 一起出去，**不需要额外操作**。
3. 插件效果生成的代码和其他效果在同一个方法体里，**可以相互混用**（需求①）——
   同一个效果列表里既有编辑器自带的效果、也有插件效果，彼此不冲突。

---

## 5. 兼容约定（需求②：编辑器升级不失效）

* 清单是**纯数据**：`apiVersion` 只在「清单结构变了」时才升；升级编辑器**不会**让老清单失效。
* 编辑器不加载插件的 DLL / 不反射插件类型，所以编辑器升级（甚至换 .NET 版本）不影响插件读取。
* `emit` 模板里引用的是**本体 API**（游戏侧），不依赖编辑器内部类；
  本体 API 变了要改的是模板（和编辑器自带效果一样要跟着改）。
* 以后若新增字段，会**只加不改**：老清单缺的新字段一律按默认值处理。

## 6. 调试

1. 「插件」页 →「重新加载插件」→ 左边列表点插件看详情：
   贡献了哪些效果、哪些触发时机 / 条件 / 模块（本版仅登记）、自带文件、问题列表。
2. 出了问题先看 ⚠ 列表：
   * `plugin.json 解析失败` → JSON 语法错（注意不要用尾随逗号以外的扩展语法）；
   * `清单版本 apiVersion … 不受支持` → 改成 `"1"`，或用新版编辑器；
   * `效果 kind … 重名` → 换个 kind；
   * `没写 emit 模板` / `自带文件不存在` → 按提示补。
3. 插件效果生成出来编不过：把生成的 `cs\Cards\...cs` 里那几行和本体 API 对照
   （模板里写错一个方法名就是 CS0103/CS1061）。

## 8. 自定义页框架（V0.2.319）

**不再只是说明页**：插件可以声明自己的页，编辑器渲染成表单，生成工程时按模板写成文件 ——
**页面内容完全由插件决定**，编辑器只提供底盘（控件 / 存值 / 预览 / 写文件）。

```jsonc
"pages": [
  {
    "id": "events",                 // 页面 id（存值用）
    "title": "事件",                // 页签标题
    "markdown": "这一页干什么（可空）",
    "fields": [                     // 栏位（空 = 纯说明页，按 Markdown 显示）
      { "key": "EventClass", "label": "事件类名（英文）", "type": "text",   "default": "MyEvent" },
      { "key": "EventName",  "label": "事件名",          "type": "text",   "default": "我的事件" },
      { "key": "Weight",     "label": "权重",            "type": "number", "default": "1" },
      { "key": "Repeatable", "label": "可重复",          "type": "bool",   "default": "0" },
      { "key": "Kind",       "label": "类型",            "type": "pick",   "options": ["普通","战斗","诅咒"], "default": "普通" },
      { "key": "Intro",      "label": "开场白",          "type": "multiline", "default": "" }
    ],
    "target": "cs/Plugins/{id}/Events/{EventClass}.cs",   // 写到工程的相对路径
    "emit": "public static class {EventClass} { public const int Weight = {Weight}; }"
  }
]
```

* **栏位类型**：`text` / `number` / `bool`（值渲染成 `1` / `0`）/ `pick`（`options` 里选）/ `multiline`。
* **占位符**：`emit` 和 `target` 里都能用 `{字段key}`；`target` 另外支持 `{id}`（插件 id）。
  `target` 里的值会自动去掉路径非法字符（中文 / 空格会变成下划线）。
* **生成时机**：点「生成工程」时，所有带 `fields` + `target` + `emit` 的页会被渲染成文件写进工程
  → 于是随 mod 一起编译 / 打包（`cs/Plugins/...` 下的 `.cs` 会编进 dll）。
* **值存哪**：`plugins/<插件 id>/values.json`（每页一组值）。改了插件清单不会丢；想重置就删这个文件。
* **手动写入**：页面上有「保存这些值」「生成到当前工程」两个按钮（改完不必重新生成整个工程）。
* **安全**：`target` 越界（`..\`）会被拒绝；写失败只丢这一页，不影响生成。

> 这条扩展点的意义：像「事件生成器」这种**编辑器本来不认识**的内容，插件也能自己定义页面 + 产物，
> 编辑器不需要为它写任何专用代码。你只要保证 `emit` 产出的代码在本体里能编译 / 能注册。
