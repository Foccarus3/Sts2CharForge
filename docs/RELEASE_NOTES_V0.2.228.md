# V0.2.228 —— 卡面分辨率很高却「进生成器就变糊」：不是压缩，是引擎在缩；补了预览质量 + 可选的「按显示尺寸缩小」

> 来源：用户问「卡牌的卡面如果上传的画质分辨率过高，传进生成器时画质会被压缩导致很模糊怎么办」。

## 1. 先查清：工具没有压缩，一层都没有

- 上传只是**记住你本机那个文件路径**（`Art.CardPortraits[类名] = 绝对路径`），不转存、不重编码；
- 生成时那一步是 `FsSafe.Copy` —— **逐字节拷贝**（连 PNG 头都没动过）。自检里钉了这条红线：
  带一张 2000×1520 的图生成，工程里那个 PNG 和原图**哈希完全一致**；
- 生成工程的 PNG **没有 `.import`**，Godot 4.5 默认导入参数是 `compress/mode=0`（**无损**）、
  `mipmaps/generate=false`、`process/size_limit=0`（用本机 Godot 实测这份工程导入后是这套值）。

## 2. 真正发糊的地方

游戏里**卡面那块只有 1000×760**（`card.tscn` 的 `%Portrait` 是 250×190，×4 = 1000×760；先古卡 `%AncientPortrait`
598×842、本体素材 606×852）。你传一张比它大的图（比如 2000×1520），多出来的像素是**引擎在画的时候缩掉的**：
双线性 + 没有 mipmap，缩得越多越容易发糊 / 出锯齿 —— 看起来就像「被压缩过」。

顺带两个也会让人误以为是压缩的观感问题：

- **工具里的预览**以前用 WPF 默认的双线性把大图缩进 190px 高的框里 → 预览本身就糊；
- 图比显示区域「宽 / 窄」时游戏里会留黑边（`KEEP_ASPECT_COVERED`），先古卡那块是「直接拉满」→ 会被拉变形。

## 3. 这一版改了什么

1. **预览改成高质量缩放**（`RenderOptions.BitmapScalingMode="HighQuality"`，三处卡面预览）——
   工具里看到的更接近游戏里的样子；
2. **卡面预览下面多一行分辨率说明**（只在**比显示区域大 1.25 倍以上**时出现，不啰嗦）：
   ```
   ℹ 这张图 2000×1520，游戏里卡面这块只有 1000×760 —— 多出来的像素是引擎在运行时缩掉的
     （缩得越多越容易发糊 / 出锯齿）。想让最清晰：① 传一张 1000×760 的图；
     或 ② 在「美术资源」页勾上「卡面过大时高质量缩小」。
   ```
3. **「美术资源」页新增勾选框「卡面过大时高质量缩小到游戏显示尺寸」**（默认**关闭** = 老行为逐字不变）：
   - 勾上后，生成时把**比显示区域大**的卡面用**面积平均**（`PngUtil.Resize`，alpha 加权）缩到
     「刚好盖住那一块」——普通卡 1000×760、先古卡 606×852；比例不一样的按 `max(frameW/w, frameH/h)` 盖住
     （多出来的那条边本来就会被游戏裁掉，和本体语义一致）；
   - **只缩不放大**：本来就比显示区域小的图一个字都不动；
   - **原图不会被改**：缩的是拷进工程的那份副本，生成日志里写清
     `卡面 xxx：2000×1520 → 1000×760（按游戏显示区域 1000×760 高质量缩小，原图不动）`；
   - 不是 8bit RGB/RGBA 的 PNG（工具解不开）就保持原样并在日志里提示，不拦生成。

## 4. 建议怎么用

| 你的图 | 建议 |
| --- | --- |
| 正好 1000×760（先古 606×852） | 什么都不用做，最清晰 |
| 更大（2K / 4K） | 勾上「卡面过大时高质量缩小」，或上传前自己用 Lanczos 缩到 1000×760 |
| 比显示区域小 | 不会放大（会糊），请换更大的图 |
