# V0.2.355 — 插件两个真 bug：`{amount}` 不认公式 / 「下回合生效」静默失效

你把插件能力过了一遍，我核完代码先修了 A 组两个 bug（都是**不报错、结果不对**那种）。

## A1：遗物 / 药水链上插件模板的 `{amount}` 不认「数值公式 / 数值 = X」

* **以前**：这两条链把 `Lit.Dec(e.Amount)`（数值框里那个字面数字）传给模板；
  卡牌链 V0.2.339 早就改成传「那条链算出来的表达式」了，遗物 / 药水没跟上。
  → 在遗物 / 药水上用插件效果、又填了公式（或「= X」）时，模板拿到的是 **0 或旧值**。
* **现在**：五条链统一 —— 卡牌 / 遗物 / 药水 / 状态 / 锻造图 都把算好的表达式传进去。
  证据（自检里那条）：遗物 + `PluginHealAndBlock` 生成出来是
  `await CreatureCmd.Heal(base.Owner.Creature, base.DynamicVars["Value"].BaseValue);`
  （以前是写死的 `7m`；现在是那条链的表达式，公式 / X 都跟着走）。

## A2：插件效果勾「下回合生效」被静默忽略

* **以前**：延迟分支的判据只认本体那 65 种效果，插件种类不在表里 → 勾了「下回合生效」也**当回合立刻执行**
  （界面上勾还在，行为不对，最坑）。
* **现在**：插件种类也走延迟分支：
  * 生成 `<角色>ForgeDelayedPlugin<种类>` 类（写在 `cs/DelayedPowers.cs`），类体 = **你自己的模板**；
  * 本回合只 `PowerCmd.Apply<那个类>(…, 数值, …)`，下回合 `AfterPlayerTurnStart` 再执行；
  * 模板里的 `{amount}` 那时等于**状态层数**（`(int)base.Amount`），所以同一种插件的多条效果共用一个类就够；
  * 类名带「Plugin + 种类」，不会和本体 / 别的插件种类撞名。
