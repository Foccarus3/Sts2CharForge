# V0.2.168 更新说明

> 这一版给你两件事：
> ① **一块布上可以放多块【触发时机】了**（你问「多个触发时机能用了吗」，答「要，现在就加」）；
> ② 修你报的「**某个状态被移除时，好像无法正常生效**」—— 状态页上「盯敌人身上的状态」那条守卫写错了，
> 生成出来的代码**永远不会触发**（而且不报错、不编译失败，就是什么都不做）。

## 一、多个【触发时机】现在真的能用

一块布（锻造节点图）以前**只认第一块**【触发时机】，你再放一块，配了也白配。现在：

* 从上面那个「模块」下拉里**再选一次【触发时机】**就能加第二块、第三块 —— 菜单里不再加过一块就消失；
* **每块配自己右边那一条链**，各生成一个钩子。例：
  * 「卡牌被打出时」→ 造成 6 点伤害（还是走 `ForgeGraphOnPlay`，由 OnPlay 末尾调用）；
  * 「这张牌被消耗时」→ 抽 1 张牌（生成 `AfterCardExhausted` 覆写）。
* 遗物那块布也一样：图上两块【触发时机】分别对上遗物的两条触发时机时，
  分别嵌进那两个钩子（生成 `ForgeGraphOnTrigger` / `ForgeGraphOnTrigger2`，不会撞名编译不过）。
* **第一块【触发时机】还是固定模块**（删不掉、不会被「全选」带走）；**第二块起是普通模块**（能删能选能拖）。
* 新加的那一块默认挑「这块布上**还没用过**的时机」，不会一加出来就落在和第一块同一个时刻上。

### 一块布两块落在**同一个时刻**上时

比如两块都设成「卡牌被打出时」——那在同一个类里就是两个同名同参数的方法，
整个模组**编译不过**（CS0111）。这种配置：

* 生成端**只写第一块**（第二块留一段注释说明），绝不出坏代码；
* 校验器**报错**说清：「第 1 块和第 2 块【触发时机】落在同一个本体钩子上……
  要两件事都做：把它们合成一块（用【条件】/【if】区分），或者把这一块换成别的触发时机。」

（同一个「时刻」不只是同名同 id：像遗物档的「自己受到伤害后」和「敌人受到伤害后」也是同一个本体钩子，
所以这种也会被拦住。）

## 二、修「某个状态被移除时」完全不触发（状态页）

**你报的**：状态页上配了「某个状态被移除时」，盯**敌人身上的状态**（比如击晕值 / 易伤），完全没反应。

**真因**（生成端可直接看出来）：「盯某个状态」的这三条时机 ——
「某个状态层数变化后」「某个状态层数到达 N 层时」「某个状态被移除时」——
「盯谁 = 任意敌人」那一支生成出来的守卫写着：

```csharp
power.Owner != base.Owner && …HittableEnemies.Contains(power.Owner)
```

它要求「发生事的那份状态在**别的**生物身上」。可你把「盯哪个状态」填成**这只状态自己**（击晕值贴在敌人身上）时，
你要的是「**这份状态挂在谁身上，它自己那份出事就在谁那里触发**」——
结果这份状态自己那份被移除时 `power.Owner == base.Owner`，被这条挡得死死的：
生成成功、编译成功、进游戏不报错，**就是什么都不做**。

**修法**：这三条时机的「盯谁」守卫抽成一份共用实现（`CustomPowerGen.PowerWatchGuard`），规则改成：

| 你配的 | 生成出来的守卫 |
|---|---|
| 盯的是**它自己这个状态**（「盯哪个状态」= 这个状态自己） | `power.Owner == base.Owner`（**不管「盯谁」选自己还是任意敌人**）—— 挂谁身上就盯谁，包括贴在敌人身上的那份自己 |
| 盯的是**别的**状态 + 「盯自己」 | `power != this && power.Owner == base.Owner`（不变） |
| 盯的是**别的**状态 + 「任意敌人」 | 要求那份状态挂在别的生物身上（不变，这才是「盯敌人身上的易伤」的意思） |

校验器里原来那条「自己涨到 N 那一下不会触发」的**警告**也随之改成**提示**（说清按「这份状态自己」生成）。

> ⚠ 修的是**生成端**：旧工程要重新点一次「生成」才生效。

## 三、顺带修掉的老坑：卡牌档那几条时机的归属守卫

锻造图上把【触发时机】选成「这张牌被消耗时 / 被丢弃时 / 被抽到时」时，生成出来的钩子
**以前没有「被消耗的是不是我」这一句守卫** —— 本体这几个钩子是**广播给场上所有模型**的，
于是「任何一张牌被消耗」都会跑这张图的链（配了「被消耗时抽 1 张」就变成每消耗一张牌都抽）。

这一版补上（判据和卡牌页「卡牌时机」那一份**逐字相同**）：

```csharp
if (card != this || base.CombatState is null) return;   // 消耗 / 丢弃 / 抽牌是广播给所有模型的，只认自己
```

「这张牌被保留时」也补上本体那两句（`player != base.Owner` + `retainedCards.Contains(this)`）。

## 四、修「次数填 Y（或 X）还是只生效一次」（你在游戏里实测报的）

**你报的**：「次数填写 Y 或者 X 次还是只生效一次」。

**日志里看到的**（`godot.log` 的模组调试行）：

```
Player 1 playing card SPARKLE_CARD43 (targeting 噬尸蛞蝓 (index 1))
[模组调试] 卡牌「新卡」(SparkleCard43) → 造成伤害；数值=(base.IsUpgraded ? 2m : 1m)
```

生成出来的是：

```csharp
decimal __Y = ForgeFormulaRuntime.Stars(base.Owner);   // Y = 当前额外资源量
…
.WithHitCount((int)System.Math.Clamp(__Y, 1m, 20m))
```

**真因**：这张牌是「**额外资源量费用 = X**」（`HasStarCostX`）—— 本体**先扣费、再跑效果**
（`PlayCardAction`：`await _card.SpendResources()` → `OnPlayWrapper(...)`），
所以效果跑的那一刻「当前额外资源量」已经是**扣完剩下的 0** → `Clamp(0, 1, 20)` = **1 下**。
「X 次」同理（X 费牌读「当前能量」也是 0）。

**修法**：这种牌里的 `X` / `Y` 直接按**这张牌花掉的那部分**生成 ——

```csharp
decimal __Y = (decimal)base.ResolveStarXValue();   // Y = 这张牌花掉的额外资源量
decimal __X = (decimal)base.ResolveEnergyXValue(); // X 费牌同理（花掉的能量）
```

（本体本来就为 X 费牌准备了这两个方法，和「= X」那一条效果走的是同一个值。）
**不是** X 费 / Y 费的普通牌里，`X` / `Y` 照旧是「当前能量 / 当前额外资源量」——一个字都没变。

校验器里原来那条「Y 读到 0、次数会被夹到 1」的**警告**也随之改成**提示**
（说清已经按「这张牌花掉的那部分」生成，你不用再改成 `YSpent` 了；`Y` 和 `YSpent` 在这种牌上现在等价）。

> 修的是**生成端**：重新点一次「生成 / 一键构建」就生效。

## 五、修「开着『生成调试日志』时锻造图那张卡编译不过」（你在游戏里实测报的）

**你报的**：一键构建失败 ——

```
SparkleCard41.cs(45,10): error CS8641: "else" 不能用在语句的开头。
SparkleCard42.cs(54,6): error CS1513: 应输入 }
```

**真因**：调试日志那一行是以行尾注释 `// CET:DebugLog` 收尾的，而锻造图那几档
（造成伤害 / 获得格挡 / 失去生命 / 施加状态）生成的是「`foreach (…) { <日志行><语句> }`」这种**拼在一行**的形状 ——
那行注释把**后面整条语句**（连 `foreach` 收尾的 `}`）一起吃成了注释 ⇒ 花括号不平、`else` 掉到语句开头。

顺带两个小毛病一起修了：

* 日志里的目标名以前是**转义后的字面量代码**（日志里打出来就是 `目标=[' + ((x)?.Name ?? \"?\") + ']`，
  看不到真正打到谁）—— 现在按**运行时**打（`目标=[铁甲战士]（不是自己）`）；
* 「执行前 / 执行后层数」那两段同样改成运行时求值。

> 只有**你勾了**「生成调试日志」时才会碰上这个坑（默认关着，生成结果一个字节都不变）——
> 你这次是为了排查「状态被移除时」才把它打开的，正好撞上。

## 六、修「描述栏里打回车换行会报错」（你在游戏/生成时实测报的）

**你报的**：「自定义状态的描述栏中 如果用回车换行会有报错」。

**真因**：WPF 的输入框里按回车，存下来的是 **CRLF**（`\r\n`）。生成端把这段描述塞进 C# 的
单行文档注释（`/// <summary>名字：描述</summary>`）时，只把 `\n` 换成了空格、**留下了 `\r`** ——
而 C# 把单独的 `\r` 也当**换行**，于是注释被截断，后半截（例：` 第二行描述…</summary>`）变成了代码 ⇒
**整个工程编译不过**。

**修法**（三处一起，防以后再犯）：

* 新增 `CustomPowerGen.OneLine(...)`：把 `CRLF / 单独 CR / LF` 全压成一行 —— 用在文档注释那里；
* `CodeWriter.Line(...)` 兜底：`CRLF → LF`、**单独的 `\r` → 空格**（永远不写出去一个裸 `\r`）；
* `CodeWriter.Str(...)`（字符串字面量）：单独的 `\r` 也转义成 `\n`（以前只处理 CRLF / LF）。

**多行描述本身是支持的**：本地化表是 JSON，换行会被正确转义，游戏里的悬停提示照样是多行 ——
只有「塞进 C# 注释」这条路上必须压成一行。新增探针 `--descprobe`（状态描述 / 卡牌自定义描述都写 CRLF 多行）
钉住这条：生成出来的源码里**一个裸 `\r` 都没有**，而且真的编译得过。

## 七、修「状态把上状态之前的计数也算进去了」（你在游戏里实测报的）

**你报的**：「状态会直接统计整个回合（战斗）的计数，然后哪怕那时候还没上状态，也会计数……
要打 4 张牌触发，但在上状态之前就打了 3 张，上状态之后只需要打 1 张就行了」。

**真因**：状态页「每累计 N 次触发一次」用的是本体战斗历史（`CombatManager.History`）里
**整个回合 / 整场战斗**的累计数，直接判 `累计 % N == 0` —— 于是**上状态之前**发生的事也被数进去了。
（「每 N 个敌人死亡」同理：工具自己记的那个计数器也是整场战斗的。）

**修法**：每个状态**实例**自己记一个「基准值」= 刚上这个状态时历史里已经有多少次（字段 `= -1` 表示还没记过），
只数基准**之后**的事件：

```csharp
private int __cntCardPlayedTurn = -1;
…
int __cnt = CombatManager.Instance.History.CardPlaysFinished.Count(e => e.Actor == base.Owner && e.HappenedThisTurn(base.Owner.CombatState));
if (__cntCardPlayedTurn < 0 || __cnt <= __cntCardPlayedTurn) __cntCardPlayedTurn = __cnt - 1;   // 本状态刚上 / 换了新回合：从现在开始数
if ((__cnt - __cntCardPlayedTurn) % 4 == 0) { …这条效果… }
```

* 「本回合」范围也顺带对了：换回合后本体那个累计数会**变小** → 自动重新记基准（不用额外的重置钩子）；
* 同一个状态上多条不同时机 / 不同范围各用各的基准字段（`__cnt<时机><范围>`），互不影响；
* **遗物**那条链没动（它的「每累计」还是按整个回合 / 整场战斗数）—— 要一起改成「从拿到遗物那一刻起数」再说。

## 八、让「透镜」能认你的格挡牌（你要求：加一个格挡的本体卡标签）

**你说**：「能不能加一个格挡的本体卡标签，不然透镜触发不了」。

**先查了本体怎么筛的**（`MegaCrit.Sts2.Core.Models.Relics.FresnelLens` + `Enchantments.Nimble`）：

```csharp
// Nimble（透镜给牌附魔的那个）
public override bool CanEnchant(CardModel card) => base.CanEnchant(card) && card.GainsBlock;
```

**透镜认的不是标签，是 `CardModel.GainsBlock` 这个属性**（本体注释里还专门写了一句
*Don't convert this into a CardTag*）——所以「本体卡标签 → Defend」勾不勾其实不影响透镜：
本体自己带 `CardTag.Defend` 的只有**初始那几张防御**，铁斩波 IronWave 一样能吃到透镜却没有 Defend 标签。

**修法**：生成的卡**按效果自动**声明 `public override bool GainsBlock => true;` ——
判据照本体自己的写法「打出时**立刻**获得格挡」：

| 这张牌 | 声明吗 |
|---|---|
| 打出时「获得格挡」正数（本体 防御 / 铁斩波 / 后空翻） | ✅ 声明 |
| 「获得格挡」填了负数（= 失去格挡） | ❌ 不声明 |
| 格挡勾了「下回合生效」（挂 BlockNextTurnPower，本轮没拿到） | ❌ 不声明 |
| 格挡只挂在「卡牌时机 = 被消耗时」这类钩子上（打出时并不获得格挡） | ❌ 不声明 |
| 锻造节点图上有一块【效果】= 获得格挡 | ✅ 声明 |
| 你自己勾了「本体卡标签 → Defend」（老行为） | ✅ 照旧声明 |

声明它的第二个好处（本体注释里写明的）：这张牌会**自动带上「格挡」的悬停提示**。

> 你存档里那 7 张牌现在都会带上它：防御 / 戏法护盾 / 静观其变 / 假面舞步 / 巧妙脱身 / 镜花水月 / 花月夜。
> **要重新生成一次**才生效。

## 九、修「无限升级升级后不加数值」（你实测报的）

**你说**：「无限升级怎么升级后不加数值了」。

**真因**：打了「**数值公式**」的牌，打出时用的是**公式算出来的值**（不读 `CanonicalVars` 里那个变量），
而升级增量并进表达式的写法是「**升没升过**」两档：

```csharp
await DamageCmd.Attack((base.IsUpgraded ? 9m : 6m))   // ← 只分两档
```

「可被无限升级」（`MaxUpgradeLevel => int.MaxValue`）的牌，**第 2、3、4… 次升级全落进「升过了」那一支** ——
数值再也不涨（`OnUpgrade` 里的 `UpgradeValueBy` 加的是变量，而打出时根本不读变量）。
卡面数字（`FormulaVars.cs` 的预览变量）也是同一个毛病。

**修法**：这种牌改成按**升级层数**算：

```csharp
await DamageCmd.Attack((6m + 3m * base.CurrentUpgradeLevel))   // 0 级 = 6、1 级 = 9、2 级 = 12 …
// 卡面：BaseValue = _formula(card, target) + (card.MaxUpgradeLevel > 1 ? _upgrade * card.CurrentUpgradeLevel : (card.IsUpgraded ? _upgrade : 0m));
```

* **普通牌**（`MaxUpgradeLevel == 1`）照旧写 `(base.IsUpgraded ? 9m : 6m)` —— **逐字不变**；
* 「从工程反推存档」也跟着认这个新写法（`(公式 + 增量m * base.CurrentUpgradeLevel)` → 数值 / 升级增量 / 公式都还原得回来）。

## 十、自定义状态里也能放「召唤伙伴」了（你截图报的：生成被拦住）

**你报的**：自定义状态「聚能」的「生成卡牌时」第 1 条效果是「召唤伙伴」，生成端还没给「自定义状态」那条链实现这个种类，
所以生成被拦住了。

**修法**：给状态那条链补上「召唤伙伴」（复用卡牌那条链**同一份** `EmitSummonPet`，行为完全一致）：

* 生成的是 `await XxxCmd.Summon(choiceContext, base.Owner.Player, 生命);`
  （状态钩子里 `base.Owner` 是 `Creature`，而生成的 `Summon` 收的是 `Player`，所以这里传 `base.Owner.Player`）；
* 「数值 0 = 用『召唤物』页里配置的血量」、「已经在场就加最大生命、不重复召唤」这些行为和卡牌上完全一样；
* 触发时机的钩子**本体不给 choiceContext** 时（例：「生成卡牌时」`AfterCardGeneratedForCombat`），
  生成端会照本体的做法自己造一个 `HookPlayerChoiceContext` —— 不然会 CS0103（探针真编译抓到过）；
* 那只召唤物没启用 / 类名找不到时**照样报错拦住**（生成出来会引用不存在的类）；
* 状态描述也补了文字：以前会把英文种类名 `SummonPet` / `PetSacrifice` 原样印在状态说明里，现在写「召唤伙伴（12 点生命）」
  「牺牲伙伴，换取格挡」。
* 「从工程反推存档」两种召唤者写法（`base.Owner` / `base.Owner.Player`）都认。

> 「伙伴攻击 / 按生命值算」这类仍然不在状态链上（它们要「打出这张牌」的上下文或已有一只伙伴在场），
> 校验器会照旧报错说清。

## 十一、修「遗物的两个触发时机『全部满足』时要触发两次」（别人实测报的）

**现象**：遗物上配了**两条**触发时机、关系选「**全部满足才触发**」（All），结果要等其中一条**触发两次**效果才出来。

**真因**：All 模式以前写成「**只有最后那条**时机检查标记」—— 每条时机各自打 __andHit{i} 标记，但只有**最后一条**的钩子里才有
「__andHit 全为真 → 跑效果 → 清标记」那段。于是当**最后那条先触发、别的时机后触发**时（顺序取决于实际玩法），
凑齐的那一刻没有任何一条会去检查标记，必须等最后那条**再触发一次**才发现凑齐了 —— 表现就是「要触发两次」。

**修法**：All 模式改成**每一段都检查**（__andHit{i} 全为真就跑 + 立刻清标记）——谁最后凑齐谁当场跑，**与触发顺序无关**；
一个窗口仍然只会跑一次（跑完就把 __andHit 全清掉）。Any 模式一个字都没变。

> 只有「All 模式 + ≥2 条时机」的遗物受影响；重新生成一次即可。

**修法**：节点图的选牌类效果现在**四摞都支持**（手牌 / 抽牌堆 / 弃牌堆 / 消耗牌堆，外加「牌顶」）——

* 手牌：照旧走 CardSelectCmd.FromHand(...)（**老文本一个字符都不变**）；
* 别的三摞：走 CardSelectCmd.FromCombatPile(choiceContext, PileType.Draw/Discard/Exhaust.GetPile(__fgPlayer), __fgPlayer, ...)
  —— 和「卡牌」页那条链**同一套写法**；
* 随机取那一档也换成对应的那一摞（CardPile.GetCards(__fgPlayer, PileType.X)）；「牌顶」= 直接拿抽牌堆最上面那张；
* 覆盖的种类：【变化卡牌】【复制卡牌】【消耗卡牌】【丢弃卡牌】【升级卡牌】（以及本来就按种类固定那一摞的
  「从抽牌堆 / 弃牌堆 / 消耗牌堆拿牌到手牌」）。

校验器里那条「节点图只从手牌里挑」的**错误**随之删掉（不再拦住生成）。

> 仍然不支持的是「取几张（最多 N / 任意张）」和「取卡方式（按范围随机 / 多选1 / 自己挑一张）」——
> 这两条节点图仍然会报错说清（节点图按「恰好 N 张、目标卡那一栏指定的那张」生成）。

## 十三、节点图又补上 4 类「卡牌页早就支持」的效果（你截图报的「删除卡牌（全局）」）

**你报的**：卡牌「紧迫满点」的【效果】选了「删除卡牌（全局：从牌组删牌）」，被拦住说「节点图里还没接上」。

**修法**：把这几档在节点图里也接上 —— 它们都**不需要「打出这张牌」的上下文**，只要一个玩家
（选牌时再加一个 choiceContext），而卡牌页 / 状态页**早就有一份实现**，所以这次直接**复用同一份**：

| 效果种类 | 生成 |
|---|---|
| 删除卡牌（全局：从牌组删牌）RemoveCardGlobal | CardSelectCmd.FromDeckForRemoval(...) + CardPileCmd.RemoveFromDeck(c) |
| 添加卡牌到牌组 AddCardGlobal | 同一条全局路径（CardPileCmd.AddToDeck） |
| 变化卡牌（全局）TransformCardGlobal | CardCmd.TransformToRandom(...) |
| 升级卡牌（全局）UpgradeCardGlobal | CardCmd.Upgrade(c) |
| 毒性爆发 Outbreak | PowerCmd.Apply<PoisonPower>(...) + poison.Trigger() |
| 播放音效 PlaySfx / 播放上传的音频 PlaySoundFile | SfxCmd.Play(...) / AudioStreamPlayer |

实现上给节点图加了一个 ViaCodeWriter(...) 桥：把那几份现成的发射器（收 CodeWriter）写出来的文本
贴进节点图的 StringBuilder —— **不再抄第二遍**（抄第二遍必然慢慢长歪）。

> 仍然没接的（会照旧报错说清）：BoostCard（强化指定卡牌，它要额外生成一张强化 Power，节点图这条链还没验过）、
> ReplicateCard / ReplayCard / TurnEndPlay 这类要「打出这张牌」上下文的、以及毒/其它少数几种。

## 十四、节点图里也能「强化指定卡牌」了（你问「强化指定卡牌怎么不能做」）

**以前为什么不能**：节点图里这一档是**故意**没开的 —— 它要**额外生成一张强化 Power**
（<角色>ForgeBoost<目标卡><强化什么>Power，见 BoostPowers.cs），而那个「用到才生成」的判断
（CollectBoostEffects）只扫「卡牌 / 遗物 / 药水 / 状态」的效果、**不扫锻造图**；
真在节点图里放开就会引用一个没生成的类 → CS0246，整个模组编译不过。

**现在**：CollectBoostEffects 也扫锻造图上的【效果】模块了，于是节点图里这一档正式接上：

`csharp
// CET:BoostCard=SevenSlash CET:BoostStat=Damage
await PowerCmd.Apply<SevenForgeBoostSevenSlashDamagePower>(choiceContext, __fgSelf, (2m), __fgSelf, this);
`

生成写法和状态页那一份**逐字一致**（只是「自己」= __fgSelf），强化 Power 类照旧按「目标卡 + 强化什么」
**去重后生成一个**（两张牌强化同一张卡共用一个 Power）。

> 仍然没接的：要「**打出这张牌**」那一刻上下文的（复制卡牌 / 重放卡牌 / 回合结束时自动打出 / 将此牌放回手牌 / 斩杀条件），
> 以及节点图自带的栏位缺口（「取卡方式」的四档、「取几张」的档位）——这些都会报错说清。
