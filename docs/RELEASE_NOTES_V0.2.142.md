# V0.2.142 更新说明

> 这一版加的是**排查用的开关**：「生成调试日志」。**默认关着**，关着的时候生成结果和上一版**一个字节都不差**。

## 一、在哪、怎么用

「**角色**」页倒数第二行 → 勾上「**打开「生成调试日志」**（排查用：只影响日志，不影响游戏行为；排查完请关掉）」→ 重新「一键生成 · 构建 · 安装」→ 进游戏，日志（`%APPDATA%\SlayTheSpire2\logs\`）里就会多出几行 `[INFO] [模组调试] …`。

## 二、日志长什么样（探针实测原文）

```
[INFO] [模组调试] 卡牌「调试尖啸」(DbgPiercingWail) → 施加增益/减益（负数 = 扣除层数）（状态 StrengthPower）（实际按「施加负层数」执行：这个状态本体允许负层数，本体「尖啸」就是这么写的）；目标=[铁甲战士]（不是自己）；执行前层数=2（已经有了这个状态）；施加量=-2
[INFO] [模组调试] 卡牌「调试尖啸」(DbgPiercingWail) → …；目标=[铁甲战士]（不是自己）；执行后层数=0（现在有了）
[INFO] [模组调试] 卡牌「调试打击」(DbgStrike) → 造成伤害；数值=(base.IsUpgraded ? 10m : 7m)；目标=[cardPlay.Target?.Name ?? "?"]（不是自己）
[INFO] [模组调试] 自定义状态「调试回血状态」(DbgHealOnHit) → 回复生命；数值=3m；目标=[base.Owner?.Name ?? "?"]（自己）
```

- **「施加状态」执行前 / 执行后各打一行**：目标身上**本来没有**这个状态时层数记 `-` 并标「本来没有这个状态」，**已经有了**就记真实层数 —— 排查「填了 -2 层却不生效」这类问题就看这两行。
- 每行都写明**谁在跑**（哪张牌 / 遗物 / 药水 / 状态 + 类名）、**效果种类**、**目标是谁**（名字 + 是不是自己）、**数值**。
- 覆盖：卡牌（含诅咒 / 先古卡）、遗物、药水、自定义状态、锻造节点图；宠物链的「给伙伴施加状态」也一起。

## 五、已知边界

1. **开关开着 + 锻造节点图 + 从工程恢复存档**：锻造图那几条日志与效果语句写在**同一行**，回读按行跳过时会丢那一条效果（**开关默认关着，老工程一行日志都没有，完全不受影响**）。
2. 不是所有效果都打日志：抽牌 / 能量 / 金币 / 额外资源量 / 击晕 / 选牌类这些**非数值型**效果不单独打行（数值型：施加状态、临时增益、伤害、格挡、回复生命、失去生命、最大生命）。
3. 日志用的是 `Godot.GD.Print`（生成的工程是 Godot.NET.Sdk），游戏日志里同样是 `[INFO]` 前缀；已实测真编译 + 真实落入日志。

## 六、下一版（V0.2.143）已排期

你报的「遗物的条件选项」查清了：**中间那块「条件选项（整只遗物）」正常；右下角那块「单条效果的触发条件」选不中用不了**。真因是四个页面共用的折叠效果行**整行是一颗按钮**，按钮吃掉了点击 → 外层列表项**永远不会被选中** → 右下角那块绑的 `SelectedItem` **一直是 null**，条件写进空对象就丢了。下一版让「点行 = 选中这一行」（遗物 / 药水 / 额外资源量三页一起修），并补上「在下列表里选 → 写回存档」这一向的自检（这次漏掉的正是这个方向）。
