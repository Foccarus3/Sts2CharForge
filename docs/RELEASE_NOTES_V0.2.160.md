# V0.2.160 更新说明

> 回答你报的：「角色页右侧的角色显示名怎么这么右边都看不到了」。

## 一、真因：跨列的长文字把两个输入列撑爆了

角色页那张 4 列表单的列宽是 **`Auto / 320 / Auto / 320`**（固定宽），而同一个 Grid 里还塞着
4 块**跨越 3~4 列、且自动换行**的长说明：

- 「生成调试日志」下面那一大段（`ColumnSpan="3"`）；
- 「初始卡组里的打击 ×5 + 防御 ×5…」那一段（`ColumnSpan="4"`）；
- 「召唤伙伴 / 伙伴攻击已经搬到召唤物页…」那一段（`ColumnSpan="4"`）。

WPF 的 Grid 在量一个**跨列**子元素时，会把它的「想要的宽度」摊到**被跨越的那几列**上 ——
这几段长文字想要的就是「整幅宽度」，于是两个固定 320 的输入列被撑成 **各 1366px**：

```
自检实测（修之前，窗口 1420）：列宽 = 227 / 1366 / 147 / 1366
                               表单右边 = 3125，可视区右边 = 1395
                               「角色显示名」输入框右边 = 3117（宽 1358）→ 在窗口外面
```

而外层 `ScrollViewer` 的**横向滚动默认是关的**（`Disabled`）—— 所以不是「要往右拖一下」，
是**既看不到、也点不到**。

## 二、修法（两条一起上）

1. **输入列不再固定宽**：`Auto / 320 / Auto / 320` → `Auto / * / Auto / *`（星号列按窗口伸缩，
   带 `MinWidth="220"`）—— 窗口宽了它自己变宽，窄了也不会溢出；
2. **长说明搬出网格**：那 4 块说明改成放在网格**下面**单独的 `StackPanel` 里（还是同一个
   `ScrollViewer`，滚动照旧），再怎么长也挤不到表单列。

修好之后（同一个自检、同一个窗口尺寸）：列宽 **227 / 488 / 147 / 488**，
表单右边 **1368** ≤ 可视区右边 **1395**，「角色显示名」输入框宽 **480**、右边 1360 —— 完整可见。

## 三、顺手加的开发用截图模式

`Sts2CharForge.exe --roleshot` → 把「角色」页按默认窗口大小（1420×880）渲染成 exe 旁边的
`roleshot.png`（和已有的 `--uishot` / `--forgeshot` 一样：只给看，不参与生成、不写存档）。
以后再有「某页某栏看不到」的反馈，先截图 + 量尺寸，别再靠猜。

## 四、验证

- `dotnet build Sts2CharForge.sln -c Debug` → **0 错误**；
- `--uicheck`：Debug **3496 PASS / 0 FAIL**（新增 3 条量角色页尺寸的断言：4 列表单找得到、
  表单右边 ≤ 视口右边、角色显示名输入框完整可见且宽 ≥ 140；**修之前这两条是 FAIL**，
  实测数字见上面「真因」那一段 —— 就是反向验证）；
- 肉眼核对：`--roleshot` 截图里「角色显示名 = 七」完整显示在窗口内，长说明正常排在下半页；
- **默认输出不变（红线①）**：`--samplegen` 与 V0.2.143 基线 **111 个文件逐字节一致**
  （只差 `ExampleMod.sln` 的随机 GUID —— 这次只动界面版式，生成端一字未改）。
