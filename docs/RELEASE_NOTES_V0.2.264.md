# V0.2.264 — 「替换初始卡」下拉还是只显示范例卡：候选从来没刷新 + 打击/防御排在最前

## 你报的

> 被古老牙齿替换的初始卡底下的下拉选项还是只有范例卡

## 两个原因叠在一起

### ① 这个下拉的候选**从来没通知过刷新**（主因）

候选是按「**当前存档**的牌」算的，但 ComboBox 只在**第一次绑定**时取一次值。
程序启动时先有一份默认 / 示例存档（新建配置就是它），于是那个下拉把**示例存档的牌**取进去之后
就再也不更新了 —— 你后来载入了自己的存档，它显示的还是启动时那份。

**改法**：牌表一变就通知（`RefreshCardChoices()` 里补 `Raise("ToothStarterChoices")`，
载入存档 / 增删改牌 / 拖动排序都会走到它）。现在打开下拉即是**当前存档**的牌。

### ② 排序把「打击 / 防御」排在了最前面

新建存档时工具会自动塞进 `打击 ×5 + 防御 ×5`（这是**范例牌**，但它们在存档里算「你自己的初始牌」），
所以就算刷新对了，列表开头也全是它们，看起来就是「只有范例卡」。

**改法**：排序改成 **你的牌 → 本体牌 → 打击 / 防御**，并且每行尾巴标清归属：

```
（自动：初始卡组里第一张）
七式斩  (SevenSlash)   ｜ 你的初始牌
七的防线  (SevenGuard) ｜ 你的初始牌
…
打击  (SevenStrike)    ｜ 新建存档自带的打击 / 防御（范例牌）
防御  (SevenDefend)    ｜ 新建存档自带的打击 / 防御（范例牌）
```

## 验收

* 自检：**4384 PASS / 0 FAIL**（新增 2 条：刷新卡牌候选时会通知 `ToothStarterChoices` /
  自己的牌排第一、范例牌排最后且带「范例牌」标记）。
* 截图核对（用你那种「先启动、再载入大存档」的流程）：下拉里第一条是「（自动…）」，
  之后就是你存档里的牌，打击 / 防御在最后一行。
