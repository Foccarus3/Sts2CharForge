# V0.3.141 — 「到达 N 层」只留一个框，数字和公式都填它

## 一、问题（用户报）

自定义状态的触发时机选「某个状态层数到达 N 层时」后，界面上出现**两个**「到达 N 层」：

1. 「到达 N 层（层数跨过这一层那一下触发）」+ 左边数字框 + 右边公式框 —— 右边的公式**填了没用**；
2. 下面又一个「到达 N 层」+ 一个数字框 —— 和上面那个数字框是**同一个值**。

用户要求：只留一个「到达 N 层」，而且只要**一个框**，数字和参数 / 公式都填在里面。

## 二、真因

- 两个框绑的是**同一个属性** `TriggerAmount`：一个是通用「触发时机上的数值」行（它带「公式」框），
  一个是这一档专属的行 —— V0.2.152 加专属行时忘了把通用行按时机收起来；
- 生成端 `CustomPowerGen` 处理 `PowerReached` 时只读 `TriggerAmount`，
  **`TriggerFormula` 根本没参与** —— 所以右边公式填了等于没填（这正是「静默不生效」）。

## 三、改法

**界面**（只影响这一档）：

- 通用那一行（数值 + 公式两个框）在「到达 N 层」时**收起**（新属性 `ShowGenericAmountField`）；
- 专属的「到达 N 层」只留**一个 150px 的输入框**，绑定新属性 `TriggerAmountText`：
  - 纯数字（`5`）→ 存成常数（`TriggerAmount`），生成老写法；
  - 带字母 / 运算符（`A+2`、`X+1`）→ 存成公式（`TriggerFormula`），运行时算；
  - 框里显示的就是当前生效的东西（数字或公式原文）；
- 下面一句小字写清两种填法。

**生成端**（`CustomPowerGen` 两处 `PowerReached`）：

```csharp
// 没填公式（老写法，一个字符都不变）：
if (... && power.Amount >= 3m && power.Amount - amount < 3m)

// 填了公式（例 A+2，A = 最大生命）：
// CET:TriggerAmountFormula=A+2
if (... && power.Amount >= (decimal)(((base.Owner?.MaxHp ?? 0) + (2m)))
         && power.Amount - amount < (decimal)(((base.Owner?.MaxHp ?? 0) + (2m))))
```

- 判据和「触发次数公式」同一套（`ForgeFormula`：自定义参数、X / Y、内置只读量、算术）；
- 同时写 `// CET:TriggerAmountFormula=…` 标记 —— 从生成出来的工程反推存档时**公式不会丢**；
- 校验器本来就会「真的求值一次」检查公式，写错会报错拦住（不会静默退回常数）。

| 断言 | 结果 |

| 框里填 `5` → 存成常数，不算公式 | 通过 |
| 框里填 `A+2` → 存成公式，框里还显示 `A+2` | 通过 |
| 生成端按公式判层数（`power.Amount >= (decimal)(…)`） | 通过 |
| 回读标记 `CET:TriggerAmountFormula=` 写了 | 通过 |

## 五、老存档

- 没填公式（`TriggerFormula` 为空）：界面显示常数、生成文本**一个字符都不变**；
- 以前在右边公式框里填过东西、但生成没生效的存档：现在**真的会按公式算**（重新生成即可）。
