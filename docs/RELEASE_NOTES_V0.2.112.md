# V0.2.112 更新说明

> 这批需求里的第 ⑥ 条：**生成器效果去掉「数值」框、只保留公式**（你选的做法：全部编辑器都去掉、
> 公式留空 = 0）。

## 一、卡牌上那 5 种效果只剩「数值（公式）」这一栏

「卡牌」页 → 选中一张牌 → 效果编辑器里，原来「数值」+「数值公式」两栏并排；
现在**支持公式的 5 种**（伤害 / 格挡 / 失去生命 / 回复生命 / 施加状态）只剩下面这一栏：

| 以前 | 现在 |
|---|---|
| 数值 `5` + 数值公式（留空） | **数值（公式）** 留空 = **0**（这条效果不显示、也不执行） |
| 数值 `5` + 数值公式 `M/2` | **数值（公式）** `M/2`（卡面显示算出来的数字，见 V0.2.111） |

- **打开老存档时自动迁移**：卡牌上那 5 种的固定数值会转成公式（伤害 7 → 公式 `7`），
  数值一个都不变 —— 不会出现「数字看不见、却还在生效」的情况；
  迁移只做在**卡牌**上，且只做**正数**（负数那种「失去格挡 / 扣层数」的写法公式表达不了，照旧留在固定值上）；
- **不支持公式的种类照旧有「数值」框**：抽几张 / 生成几张 / 消耗几张 / 金币 / 能量 / 拿牌…
  这些的数值必须在生成时定下来（要提前分配卡面变量和选牌上限），没有公式可用；
- **遗物 / 药水 / 自定义状态上的效果也照旧有「数值」框**：公式目前只做在卡牌上
  （那几条链没有「打出这张牌」那一刻的上下文，填了会被校验器拦住）——
  所以那里收起来就没法填了。这两条是「公式都有并且更多」目前还不成立的地方，说清楚。
- 新加的效果依旧默认「数值 0」（早就是这么做的）：在卡牌上等于「先什么都不做，写好公式再生效」。

## 二、顺手修掉一个会被这次改动触发的真 bug

迁移之后，卡牌里的动态变量变成了 `new ForgeFormulaDamageVar(...)`（V0.2.111 那个「现算预览值」），
而生成后的**自检**（「引用了没声明的动态变量」）只认本体那几种变量类型 → 把
`Damage` / `Block` / `VulnerablePower`… 全部误报成「没声明」，**整次生成直接失败**。
已修：自检现在也认那 5 个公式变量类（泛型那个按 `T` 取键），并且老存档迁移后的工程**真 `dotnet build` 0 错误**。
