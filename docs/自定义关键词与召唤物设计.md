## 一、自定义关键词

### 1.1 游戏里的关键词其实是两套东西

**（A）真关键词 = C# 枚举，模组扩不了**

`Core\Entities\Cards\CardKeyword.cs:18-28` 是硬编码枚举，只有 8 个值：

```
None, Exhaust, Ethereal, Innate, Unplayable, Retain, Sly, Eternal
```

- 文案：`Core\Entities\Cards\CardKeywordExtensions.cs:15-23` → 类别 `card_keywords`，键 `<SLUG>.title` / `<SLUG>.description`
  （`localization\zhs\card_keywords.json` 就是「消耗 / 虚无 / 固有 / 不能被打出 / 保留 / 奇巧 / 永恒」这些）
- 卡面文字：`CardKeywordExtensions.cs:25-28` 的 `GetCardText()` 拼成 `[gold]标题[/gold]。`
- 枚举成员**无法在运行时扩展** → 「注册一个真关键词」这条路不通。

**（B）悬浮提示 = 完全独立、模组可自由使用**

- `CardModel` / `RelicModel` / `PotionModel` 都有 **虚属性** `ExtraHoverTips`。
- 生成本体的 `HoverTip` 不需要枚举：直接 `new HoverTip(new LocString(类别, 键), ...)`。
- 生成器**已经在用**这条路（`SparkleMod\cs\Cards\SparkleCardBurst.cs:15-17`）：

```csharp
protected override IEnumerable<IHoverTip> ExtraHoverTips => new[] {
    new HoverTip(new LocString("static_hover_tips", "STAR_COUNT.title"),
                 new LocString("static_hover_tips", "STAR_COUNT.description"))
};
```

- 本地化是**按「文件名 = 类别、逐键合并」**加载的（`Core\Localization\LocManager.cs`）：
  模组只在 `SparkleMod\localization\zhs\static_hover_tips.json` 里放了 2 个键，本体那些提示照常工作 →
  说明是**逐键合并**而不是整表替换，可以安全地自带任意多条「标题 + 说明」。

> 关键结论：**自定义关键词不需要真关键词，只要「本地化条目 + ExtraHoverTips + 描述里的 `[gold]` 标记」三件套**，
> 观感与本体关键词一致，且不改本体、不依赖未公开 API。

### 1.2 生成器要做的三件事

| 层 | 产出 | 依据/写法 |
|---|---|---|
| 本地化 | 模组工程里 `{ModId}\localization\{lang}\custom_keywords.json`：`<ID>.title` / `<ID>.description` | 键名用模组自有前缀（如 `SPARKLE_KW_FATE.title`），避免与本体 `card_keywords` 撞名 |
| 提示挂载 | 卡牌 / 遗物 / 药水的 `ExtraHoverTips` 里列出**它引用到的**自定义关键词 | 与现有 `STAR_COUNT` 写法完全一致 |
| 卡面文字 | 描述里出现 `[gold]关键词名[/gold]`（用户自己写，或生成器按「引用」自动追加） | 照抄 `CardKeywordExtensions.GetCardText()` 的观感 |

### 1.3 数据模型与界面（待细化）

- 存档里新增一个集合，例如：
  ```jsonc
  "CustomKeywords": [
    { "Id": "FATE", "Name": "命定", "Description": "打出后……", "IconPath": "…(可选)" }
  ]
  ```
- 卡牌 / 遗物 / 药水上加一个「引用的关键词」多选（存 `Id` 列表）。
- 新的界面页「关键词」：列表 + 增删 + 名称/说明编辑 + 图标上传（复用现有美术槽位的上传落盘逻辑）。
- 代码生成时：把用到的关键词汇总去重 → 写本地化 JSON → 给每个引用它的内容生成 `ExtraHoverTips` 项。
- 自检 `--uicheck`：加一条「关键词 → 本地化 → ExtraHoverTips」的端到端断言。

### 1.4 已验证：类别名必须沿用本体的

**模组本地化只能提供「与本体同名」的类别文件**，凭空新建类别不会被加载：

- `Core\Modding\ModManager.cs:966-979` `GetModdedLocTables(language, file)` 返回的是
  `res://{modId}/localization/{language}/{file}`，其中 `file` 是**本体已有的表名**；
- `Core\Localization\LocManager.cs:468-478` 是在「遍历本体 `res://localization/<lang>/*.json`」的循环里
  才去合并模组同名文件（`locTable.MergeWith(dictionary4)`），并且用 `fileNameWithoutExtension` 注册表；
- 所以不存在的表名会让 `LocManager.GetTable()` 抛 `The loc table='xxx' does not exist!`（`LocManager.cs:483-490`）。

**因此关键词的文案要写进本体已有的类别**，两个候选：

| 类别 | 键格式 | 说明 |
|---|---|---|
| `card_keywords`（推荐） | `<SLUG>.title` / `<SLUG>.description` | 语义正确（本体关键词就是这张表）；逐键合并，只要键名不撞本体那 8 个 SLUG（EXHAUST/RETAIN/…）就安全；`PERIOD` 别动 |
| `static_hover_tips` | `<ID>.title` / `<ID>.description` | 生成器现有「额外资源量提示」已经在用，实测可用；语义稍偏 |

**仍未验证**：`[gold]` 标记是否只是着色（悬停完全由 `ExtraHoverTips` 提供），
以及本体是否存在「按文本反查关键词」的通道 —— 见 `[ ] tooltip 解析链路细节`。

## 二、奥斯提式召唤物

### 2.1 好消息：有公开的通用宠物 API

`Core\Commands\PlayerCmd.cs:237-257`：

```csharp
public static async Task<Creature> AddPet<T>(Player player) where T : MonsterModel { ... }
public static async Task AddPet(Creature pet, Player player) { ... }
```

- Osty 用的是它 + 一层专用包装 `OstyCmd.Summon`；
- 而 **Byrdpip / Pael's Legion 两个宠物直接调通用 API，零特判**。
- 结论：**召唤一个「有血、能被指挥攻击、战斗结束消失」的伙伴，不需要任何 Harmony 补丁。**
- 模组内容注册也是自动的（`Models\ModelDb.cs:68-88` 会扫模组程序集里的 `AbstractModel` 子类；
  `ModelDb.Init` 用 `Activator.CreateInstance` → 子类必须有 **public 无参构造函数**）。

### 2.2 召唤时到底发生了什么

```
PlayerCmd.AddPet<MyPet>(player)
 ├ CombatState.CreateCreature(ModelDb.Monster<MyPet>().ToMutable(), Player, null)   // 兽体
 ├ player.PlayerCombatState.AddPetInternal(pet)                                     // 记进 _pets、设 PetOwner
 └ CreatureCmd.Add(pet)                                                             // 进战场 + 建 UI 节点
      └ NCreature.Create → MonsterModel.CreateVisuals()                             // 按约定路径找视觉场景
```

宠物**没有自主回合行为**（`Osty.cs:37-42` 的唯一 move 是空操作自循环），实际靠玩家出「指挥卡」驱动：
`DamageCmd.Attack(n).FromMonster(pet.Monster)` 或 `CreatureCmd.Damage(... dealer: pet ...)`。

### 2.3 需要补丁的只有「Osty 专属的花活」

| 想要的效果 | 需要什么 | 风险 |
|---|---|---|
| 专属站位 / 主人旁偏移 | 补丁 `NCombatRoom.PositionPlayersAndPets`（`NCombatRoom.cs:442-455` 里是 `Character is Necrobinder` + `is Osty` 双特判） | 高频、版本敏感 |
| 随血量缩放 | 补丁 `NCreature.OstyScaleToSize`（`NCreature.cs:776`，以 150 血为基准） | 同上 |
| 替主人挨打（替死） | 自定义 `PowerModel` 覆写 `ModifyUnblockedDamageTarget` + `ShouldCreatureBeRemovedFromCombatAfterDeath=false`，照抄 `DieForYouPower.cs:15-52` | 全局只允许一款伤害重定向（`AbstractModel.cs:1693` 注释），与 Osty 叠加时看 hook 顺序 |
| 跨战斗保留血量 | **靠遗物 `[SavedProperty]` 存状态 + 每次战斗重召** | `_pets` 在 `AfterCombatEnd()` 被清空（`PlayerCombatState.cs:142-151`），不能靠 Creature 记 |

**不要用**：`OstyCmd.Summon`（内部硬编码 `Osty` 类型，非 Osty 会抛异常）、`AttackCommand.FromOsty`（硬校验 `osty.Monster is Osty`）、
`MinionPower`（那是给敌方小怪用的标记）。

### 2.4 推荐模板：Byrdpip / Pael's Legion，不是 Osty

- **Byrdpip**（`Models\Relics\Byrdpip.cs` + `Monsters\Byrdpip.cs`）：遗物标 `SpawnsPets=true`，
  `BeforeCombatStart` 里 `PlayerCmd.AddPet<Byrdpip>`，宠物状态（皮肤）存在遗物的 `[SavedProperty]` 上 → 全通用。
- **Pael's Legion**：遗物当「宠物控制器」（状态/冷却都在遗物上），宠物只是表现层 → 架构最干净。
- **Osty**：底层通用，上层全是 `Necrobinder` + `Osty` 特判，只有做「替死 + 留尸 + 复活 + 随血变大」才值得抄。

### 2.5 生成器要产出的东西（三档）

**第一档 · 基础伙伴（无补丁，建议先做）**
1. `cs\Monsters\MyPet.cs`：`MonsterModel` 子类（public 无参 ctor、`Min/MaxInitialHp`、自循环 `NOTHING_MOVE`）
2. `cs\MyPetCmd.cs`：`Summon(ctx, player, amount)` → `AddPet` + `SetMaxHp` + `Heal`
3. 触发：一张「召唤」卡（`OnPlay`）或一个遗物（`BeforeCombatStart` + `SpawnsPets=true`）
4. 指挥：每张「伙伴攻击」卡 → `DamageCmd.Attack(n).FromMonster(pet.Monster)`，先查 `GetPet<MyPet>()?.IsAlive`
5. 本地化：`monsters.json` 的 `<ENTRY>.name`
6. 视觉：模组 PCK 提供 `res://{ModId}/creature_visuals/<entry>.tscn`，最少要有唯一名节点
   `%Visuals` / `%Bounds` / `%IntentPos` / `%CenterPos`；不做也能跑（回退 `error.png` 占位图）

**第二档 · 进阶（要补丁，可选）**
7. 替死 power（照 `DieForYouPower`）、专属站位/缩放补丁

**第三档 · 旗舰（Osty 级）**
8. 死亡留尸 + 复活（`AddPetInternal` 复用同一 Creature）、战斗外成长（遗物 saved property）、专属音效/特效

### 2.6 生成器侧的界面与数据结构（草案）

- 角色配置里加一个「召唤物」页：启用开关、名字、初始/最大血量、视觉（上传图或选内置占位）、
  是否替死、是否跨战斗保留、召唤方式（卡牌 / 战斗开始 / 每回合开始）。
- 卡牌编辑页加两个新效果类型：「召唤伙伴」「伙伴攻击」（后者目标/伤害由伙伴承担）。
- 生成时按上面的三档产出对应文件；第二/三档的补丁代码做成模板，默认不启用。

## 三、落地顺序建议

1. **自定义关键词**（低风险、纯增量、马上能用）：存档集合 → 界面页 → 本地化 + `ExtraHoverTips` 生成 → 自检。
2. **召唤物第一档**（中风险、不需补丁）：怪物模型 + 召唤命令 + 触发卡 + 指挥卡 + 占位视觉。
3. **召唤物第二档**（按需）：替死 power 与站位/缩放补丁，做成可选开关。
4. 第三档留到有明确需求再做。
