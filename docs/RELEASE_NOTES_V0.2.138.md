# V0.2.138 更新说明

> 这一版修的是**你报的卡死**：「额外资源量 → 在游戏中隐藏那只载体遗物」会让游戏在**获得新遗物**时卡死（你给的日志里是**先古事件选遗物**那一刻）。

## 一、卡死是怎么来的（日志里的确切位置）

你的日志里那一串是：

```
System.ArgumentOutOfRangeException: Index must be within the bounds of the List. (Parameter 'index')
   at List`1.Insert(Int32 index, T item)
   at NRelicInventory.Add_Patch2(NRelicInventory this, RelicModel relic, bool startsShown, int index)   ← 我们生成的补丁
   at NRelicInventory.OnRelicObtained(RelicModel relic)
   at Player.AddRelicInternal → RelicCmd.Obtain → 先古事件「选遗物」
```

**原因**：以前那个「隐藏」补丁是**前缀补丁，遇到载体遗物就 `return false` 把原方法整个跳过**。于是**遗物栏的界面节点列表比游戏模型（`Player.Relics`）少了一项** —— 之后你**再获得任何一只遗物**时，游戏按模型算出下标插进那个短了的列表，`List.Insert` 就**越界**，异步任务抛异常死掉，看起来就是**卡死**。
这条 bug 从 **V0.2.113**（加「在游戏中隐藏」那次）一直潜伏到现在 —— 之所以一直没抓到，是因为它只在**真游戏里、而且要在拿到载体遗物之后再获得别的遗物**才会触发，我们的自动探针只能验「生成 + 编译」，验不了运行期越界。

## 二、现在改成怎么做的

**后缀补丁 + 纯视觉隐藏**：

- 原方法 `NRelicInventory.Add` **一个字都不改地照跑**（节点照建、照插进列表、照进 Godot 树）→ **遗物栏节点列表的长度与顺序永远等于 `Player.Relics`** → 下标永远合法，**越界不可能再发生**；
- 跑完之后，才把刚建出来的那个节点设成 `Visible = false`（**纯视觉**，不碰下标、不碰列表、不碰树）；
- 补丁**只读**参数，不参与任何计算；
- 查证过程（都用我们自己的本体 DLL 副本，没碰你的游戏目录）：本体 `RelicModel` 上**没有**「别在遗物栏显示我」的可覆写虚属性、`NRelicInventory` 上**没有**隐藏入口，所以只能补在界面节点上；并且用 IL 层面确认了「只要 `Add` 不被跳过，节点列表与模型永远同长同序」。

**你能看到的变化**：那只载体遗物在遗物栏里**不显示**了（图标会向左排紧）。
👉 如果你更希望它**留一个空格子**（图标不挪位），说一声，改成「透明但仍占位」即可（一行）。

## 五、已知边界

1. 「运行期不再卡死」的证据链是：索引不变量的**静态（IL 级）证明** + 生成形状自检 + 真编译 0 错误。**真游戏里的那一步只能由你验**（第三节点名的场景）；
2. 隐藏用的是 `Visible=false`（图标会排紧）；要「留空格子」就改成透明占位；
3. 校验器只拦了「勾了隐藏但没启用额外资源量」这种必错的组合（会编译不过），没加别的提示。
