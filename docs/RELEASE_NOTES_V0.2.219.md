# V0.2.219 —— 「每消耗 N 点能量 / 额外资源量」填 0 = 只要消耗就触发（这个范围里只触发一次）

> 来源：用户实测报的「触发时机的每消耗 N 点能量和额外资源量，数值填 0 的效果和 1 的效果是一样的，
> 把设 0 的效果变成只要消耗便触发，每回合或者每场战斗仅触发一次」。

## 1. 以前为什么 0 和 1 一样

「花掉能量 / 花掉额外资源量」这两条时机的数值走的是**按点数循环**那条路：

```csharp
for (int __energySpentIdx = 0; __energySpentIdx < amount; __energySpentIdx++) {
    if ((__spentBefore + __energySpentIdx + 1) % Math.Max(1, N) != 0) continue;   // 每 N 点一次
    …效果…
}
```

`Math.Max(1, N)` 把 **0 顶成了 1** → 填 0 和填 1 走的是同一条路（一张 3 费牌触发 3 次），
所以用户看到「0 和 1 效果一模一样」。

## 2. 现在填 0 是什么意思

| 填的数 | 生成的代码 | 语义 |
| --- | --- | --- |
| **0 / 留空** | `if (__spentBefore == 0) { …效果… }` | **只要消耗就触发一次**，而且是**本回合 / 本场战斗里只触发第一次**（窗口 = 下面那栏「本回合 / 本场战斗」） |
| **N（> 0）** | 还是按点数循环 + `% N == 0` | 每累计花掉 N 点触发一次（老行为，生成文本一个字都不变） |

「这一次之前花掉多少」不需要工具自己记计数器 —— 直接读**本体战斗历史**
（`EnergySpentEntry` / `StarsModifiedEntry`，本体是先记账再调钩子，所以「之前 = 累计 − 这一次的 amount」）。
它等于 0 就说明这是本窗口的第一次消耗，于是「换回合 / 换战斗自动重新算」是白送的，不会有脏标记残留。

同一个钩子上「0 档」和「N 档」混着配时：0 档跑在点数循环**外面**（每窗口一次），N 档照旧按点数各触发一次，
两档共用同一份「之前花了多少」（历史只扫一遍）。

## 3. 回读（从工程恢复）

- 0 档会在方法里多写一行 `// CET:TriggerAmount=0m CET:TriggerScope=Turn`，
  否则回读时 0 拿不到标记、会被默认值 1 顶掉（那就又变回「0 = 1」了）；
- **N > 0 的路径不写这行**（老存档生成文本逐字不变，数值仍由「// 数值：每累计花掉 N 点触发一次（范围：…）」回读）。

## 4. 验收

- 自检：遗物 / 状态两边「填 0 → 没有点数循环 + 有 `__spentBefore == 0` + 有回读标记」；
  混搭（0 + 3 同钩子）→ 0 档在循环外面、只算一次历史；
  生成 → 回读：遗物 / 状态的「0 + 范围」都认得回来（不会被默认值 1 顶掉）；
- 探针 `sacprobe spend0`：状态 `AfterStarsSpent` 生成 `if (__spentBefore == 0)`、遗物 `AfterEnergySpent` 同款，
  回读 `amt=0 scope=Combat / amt=0 scope=Turn`；
- 老存档逐文件对拍（新编译 Core ↔ 已发布 V0.2.218 的 Core，同一份输入各生成一遍）：
