# V0.2.225 —— 条件新增「本回合预见过 / 本回合已预见至少 N 次」

> 来源：用户要求「条件新增是否预见」→ 补充「这回合是否预见过，这回合预见的次数」。

## 1. 「预见」是工具自己拼的效果，所以次数也只能工具自己数

本体（StS2）**没有**「预见 Scry」这个机制（工具里的「预见」是拿
`PileType.Draw.GetPile(...).Cards.Take(N)` + `CardSelectCmd.FromSimpleGrid` + `CardCmd.Discard` 拼出来的），
战斗历史里自然也查不到「预见过几次」。所以和「每 N 个敌人死亡」一样，由工具自己记一个计数器。

## 2. 条件列表里多两条

| 条件 | 判据 |
| --- | --- |
| **本回合预见过** | 本回合（按**你自己的回合号**算）用过一次「预见」就成立 |
| **本回合已预见至少 N 次** | 填 N = 本回合至少预见 N 次；**填负数 = 反向**（本回合预见的次数少于 N 次） |

- 卡牌 / 遗物 / 药水 / 自定义状态（触发时机里的效果）都能用，锻造图的【条件】模块里也能选到；
- 生成的条件表达式走工具自己的计数器（`<角色>ForgeCombatCounters.ScryThisTurn(玩家) > 0` / `>= N`），
  **换回合 / 换战斗自动从 0 重新数**（按 `PlayerCombatState.TurnNumber` 认回合）；
- 卡面 / 悬停文案用的是条件表里的原文，填负数时印反向说法（「本回合预见的次数少于 N 次」）。

## 3. 什么时候会记数

只有**用到这两条条件**的存档才会记：

```csharp
// 「预见」那条效果里多一句（cs/<卡>.cs）
SevenForgeCombatCounters.BumpScry(base.Owner);   // 记一次「预见」（条件「本回合预见过 / 预见次数」靠它）
```

计数器本体在 `cs/CombatCounters.cs`（和「每 N 个敌人死亡」共用同一个类）：

```csharp
public static int BumpScry(Player? player) { … 换玩家 / 换回合自动从 0 开始 … return ++__scryCount; }
public static int ScryThisTurn(Player? player) { … 不是这个玩家 / 这一回合就是 0 … }
```

- **没用到这两条条件时**：`cs/CombatCounters.cs` 一个字节都不变（敌人死亡那部分照旧），
  「预见」那条效果也**不会**多写那一句 —— 老存档生成文本逐字不变；
- 只用到「预见次数」时，那个类里**只有**预见那部分（不会平白多出 `BumpEnemyDeath`）。

## 4. 顺带修的两处

1. **图上【条件】也算「用到」**：`UsesCondition` 以前只扫效果上的「条件选项」，锻造图【条件】模块里的
   条件不算 —— 于是「图上只用了『抽牌堆本回合洗过』」时那个记录器不生成，工程里直接 CS0103。
   现在图上的【条件】也扫（洗牌记录器和这次的预见计数器都受益）；
2. **回读**：新加的那句 `BumpScry` 在「预见」那一段实现里，回读的「整段跳过」名单里补上了它
   （不然跳过开关会在这一句被关掉，后面几行就变成「没认出来」）；
   两条新条件按生成出来的表达式认回来（`ScryThisTurn(...) > 0` / `>= N` / `< N`）。

## 5. 验收
