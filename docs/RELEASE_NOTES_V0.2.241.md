# V0.2.241 —— 参数弹出多一条：`ThisCardBlock`（本张牌这一次打出获得的格挡）

> 你问的：「自定义参数能不能加一个这张牌获得的格挡」。

## 1. 先说结论

能，已经加好了。它和上一版（V0.2.194）那条 `ThisCardDamage`（本张牌这一次打出造成的伤害）
是**一对兄弟读数**：同一套属性机制、同一套限制，只是取数换成了**格挡**。

参数参考窗的「内置实时读数」那一类、效果编辑器数值框右边「…」的**插入弹窗**里都能看到它：

* **`ThisCardBlock`** —— 「本张牌这一次打出获得的格挡（实际拿到多少；含敏捷等加成，只算「获得格挡」效果）」；
* 但它**不在**「自定义参数 / 组」的「取值来源」下拉里 —— 参数是「打出那一刻先算一次」的，
  选它会恒 0（这条规矩和 `ThisCardDamage` 一样）。

## 2. 口径（和本体对齐）

取的是本体 `CreatureCmd.GainBlock(...)` 的**返回值** —— 它是走完 `ModifyBlock` 之后**实际拿到**的格挡
（`CreatureCmd.cs:680-700`），所以敏捷 / 遗物 / 状态给的格挡加成都在内，**跟卡面写的数字不一定相等**。

* 只算「获得格挡」这一条效果真拿到的那部分（给队友 / 敌人的格挡也算）；
* 「失去格挡」（负数那种走 `LoseBlock`）、「下回合生效」（挂的是 `BlockNextTurnPower`）、
  牺牲伙伴换来的格挡、状态 / 遗物给的格挡 —— 都**不算**；
* 每次打出各算一次（打出时清零、之后每条格挡效果往上加）—— 回手再打 / 重放 / 复制出来的第二张互不影响。

## 3. 两种常用写法

| 想做的牌 | 效果栏怎么排 |
|---|---|
| 获得 5 点格挡，再施加**等量于获得格挡**的灾厄 | ① 获得格挡 `5`，作用对象 = **自己**；② 施加增益/减益 → 选灾厄，数值公式 **`ThisCardBlock`**，作用对象 = 指定敌人 |
| 获得 5 点格挡，再造成**等同于获得格挡**的伤害（本体「全身撞击」那种） | ① 获得格挡 `5`，作用对象 = 自己；② 造成伤害，数值公式 **`ThisCardBlock`**，作用对象 = 指定敌人 |

卡面会自动印成人话：前者「施加等同于本牌获得格挡的灾厄。」，后者「造成等同于本牌获得格挡的伤害。」
（都不印数字 —— 这条读数没有「现算预览值」可用）。

**顺序不能反**：读数记的是「到目前为止」的量，所以「获得格挡」必须排在前面（反了会得到恒 0，校验器给警告）。

## 4. 会静默失效 / 编不过的写法，一律拦住（不静默）

| 写法 | 结果 |
|---|---|
| 用在遗物 / 药水 / 自定义状态上（含它们的锻造图） | **错误**：读的是这张牌自己的属性 |
| 卡牌上但挂在「卡牌时机」钩子上（被消耗 / 被丢弃 / 被抽到 / 放回手牌 / 抽到减费） | **错误**：读到的是上一次打出留下的数 |
| 勾了「下回合生效」 | **错误**：延迟状态在下回合开始时才求值 |
| 写在**整张牌条件**里 | **错误**：那个条件在打出之前求值（`IsPlayable` / 描金边），恒 0 |
| 和别的量混写（`ThisCardBlock * 2`） | **错误**：只能光秃秃单独写（`(ThisCardBlock)` 可以）—— 卡面预览那个 lambda 只拿得到 `CardModel` |
| 这条效果**前面没有**「获得格挡」 | **警告**：恒 0 |
| 想当「自定义参数 / 组」的取值来源 | 下拉里**不提供**（参数是打出那一刻先算一次的） |
| 用在「伤害 / 格挡 / 生命」这几种效果上 | **提示**：能生效，但卡面那一栏印的是占位 0 —— 给它配一段「自定义描述」（「格挡 → 伤害」那种有专门文案） |

锻造页那块布上也能用：【数值】模块的公式里写 `ThisCardBlock`（只有【触发时机】=「卡牌被打出时」那块布才记账）。

# 追加（同一版）：四条「张数」读数 —— 这张卡消耗 / 丢弃 / 变化 / 生成的卡牌数

> 你问的：「这张卡丢弃的卡牌数、这张卡消耗的卡牌数、这张卡变化的卡牌数、这张卡生成的卡牌数有没有」。

**以前没有**：只有「本回合 / 本场累计」那几条（`DiscardedThisTurn` / `ExhaustedThisCombat` …），
而且「变化」连累计都没有。这一版补齐了四条**这张牌这一次打出**的张数读数。

## 6. 四条新读数

| 读数 | 是什么 |
|---|---|
| `ThisCardExhaust` | 本张牌这一次打出**消耗**的卡牌数（只算「消耗卡牌」这条效果；数值 0 = 消耗这张牌自己也算 1） |
| `ThisCardDiscard` | 本张牌这一次打出**丢弃**的卡牌数（只算「丢弃卡牌」；数值 0 = 丢弃自己也算 1） |
| `ThisCardTransform` | 本张牌这一次打出**变化**的卡牌数（只算「变化卡牌」） |
| `ThisCardGenerate` | 本张牌这一次打出**生成**的卡牌数（只算「生成卡牌」；**「复制卡牌」不算**） |

它们和 `ThisCardDamage` / `ThisCardBlock` 是同一套机制（卡片类上的属性：打出时清零、每个操作点记账），
限制也一字不差（只能卡牌 / 不能在「卡牌时机」钩子上 / 不能勾「下回合生效」/ 不能写进整张牌条件 /
不能和别的量混写 / 前面必须有对应效果 / 不进参数来源下拉）。

**为什么不用战斗历史**：本体那几张记录（`CardExhaustedEntry` / `CardDiscardedEntry` / `CardGeneratedEntry`）
**只带卡、不带「哪一次打出」**，分不出是谁干的；「变化」更是压根没有历史记录 —— 所以只能逐次记账。

## 7. 怎么用

| 想做的牌 | 效果栏怎么排 |
|---|---|
| 消耗 3 张手牌，再施加**等同于消耗张数**的灾厄 | ① 消耗卡牌 `3`（自己选，从手牌）；② 施加增益/减益 → 灾厄，数值公式 **`ThisCardExhaust`** |
| 生成 2 张「打击」，再施加**等同于生成张数**的虚弱 | ① 生成卡牌 `2`；② 施加状态，数值公式 **`ThisCardGenerate`** |

卡面会自动印成「施加等同于本牌消耗张数（丢弃 / 变化 / 生成张数）的 X。」（不印数字）。

## 8. 验过的

| 项 | 结果 |
|---|---|
| `--uicheck` | **4274 PASS / 0 FAIL**（本次再新增 13 条断言：四条读数 / 生成结果 / 卡面文案 / 回读 / 校验） |
| 真编译 | 一份探针存档（六张卡：消耗·丢弃·变化·生成的「自己选 / 随机 / 全部」各种分支）`--build` **0 错误** + 导出 PCK OK |
| 回读 | `--recover` 四条公式都认回来、`没认出来` 为 0 |

> 踩过并修掉的坑：计数**不能**包成 `{ stmt; 计数; }` 挤在同一行 —— 回读是按「这一行以
> `await CardCmd.Exhaust(` 开头」认效果的，包成块会让那条效果整条认不出来（探针实测报了 2 处

# 再追加（同一版）：「减益的个数」做成自定义参数（`DebuffCount`）—— 撕碎那种牌

> 你问的：「生成器里有减益的个数的参数吗」→「那可以做一个目标身上的减益个数吗」→「做成自定义参数」。

## 9. 现在有什么

「自定义参数 / 组」页的**取值来源**下拉多了一条：
**「减益的个数（几种负面效果）」** —— 取「从谁身上取」那个对象当前有**几种**减益状态
（和层数无关：10 层中毒也只算 1 种；按本体 `TypeForCurrentAmount == PowerType.Debuff` 判定）。

生成出来是 `ForgeFormulaRuntime.PowerCount(__fgTarget, "Debuff", null)`（就是锻造页【状态列表】
用的同一个运行时帮手，判据只有一份）。回读也认得回来（参数页那行会显示「M=指定敌人的减益的个数」）。

## 10. 撕碎（Rend）怎么复刻

| 在哪 | 填什么 |
|---|---|
| 「自定义参数 / 组」页 | 新建 `M`，取值来源 = **减益的个数（几种负面效果）**，「从谁身上取」= **指定敌人** |
| 「卡牌」页 | 一张攻击牌，效果「造成伤害」，数值公式写 **`10 + M * 5`** |

> 本体 `Rend.cs` 的三个参数在这里对上两个：`CalculationBase` = 公式里的常数 `10`
> （基础 10、升级 +2；每多一种减益的 5 点、升级 +3），`CalculatedDamage` 的倍率就是 `M`。

## 11. 注意

- **不是**「只能单独写」那种读数：参数是打出那一刻先算一次、存进 `__pM` 的，所以在公式里可以随便参与
  运算（`10 + M * 5`、`M * 2`…），这一点和 `ThisCardDamage` / `ThisCardBlock` 那 6 条**不一样**；
- 「从谁身上取 = 指定敌人」的牌**必须真的有目标**（打自己 / 打全体的牌用它会拿不到目标，校验器会提示）；
- 只数**减益**；要数「几种增益」/「一共几个状态」目前没有对应来源（可以改用锻造页【状态列表】）。

## 12. 验过的

| 项 | 结果 |
|---|---|
| `--uicheck` | **4374 PASS / 0 FAIL**（本次新增 11 条断言） |
| 真编译 | 撕碎探针（`M`=指定敌人的减益个数 + 伤害 `10 + M * 5`）`--build` **0 错误** + 导出 PCK OK |
| 回读 | `--recover` 认回「M=指定敌人的减益的个数」，没认出来的语句为 0 |

# 追加：状态触发时机里的「作用对象」以前被完全忽略（同一版一起发）

## 用户报的

「触发时机增加回复生命值时……」（消息只到这儿，按最可能的意思查的 —— 见最后一节）

## 病因

`CustomPowerGen` 里这四种效果以前**只有一句 `base.Owner`**：

| 效果 | 以前生成的代码 |
|---|---|
| 回复生命值 | `await CreatureCmd.Heal(base.Owner, N);` |
| 获得 / 失去格挡 | `GainBlock(base.Owner, …)` / `LoseBlock(…, base.Owner, …)` |
| 失去生命 | `Damage(…, base.Owner, …)` |
| 最大生命 | `GainMaxHp(base.Owner, …)` / `LoseMaxHp(…, base.Owner, …)` |

界面上「作用对象」这一栏明明摆着（`EffectFieldPolicy.UsesTargetSide` 对这四种都返回 true），
选了「全体友方 / 单体敌人 / 全体敌人 / 全体单位」**照样只对自己动手**，而且不报错、不提示 ——
静默忽略配置。探针实测（修复前，四条 Heal 换了四种作用对象，生成的却是同一句）：

```
Heal 5 自己      → await CreatureCmd.Heal(base.Owner, 5m);
Heal 6 单体敌人  → await CreatureCmd.Heal(base.Owner, 6m);   ← 明明选了敌人
Heal 7 全部友方  → await CreatureCmd.Heal(base.Owner, 7m);   ← 明明选了全体友方
Heal 8 全体单位  → await CreatureCmd.Heal(base.Owner, 8m);   ← 明明选了全体单位
```

## 修法

新增 `CustomPowerGen.EmitPowerTargets`（状态链专用：这里的 `base.Owner` 本身就是 `Creature`，
写 `base.Owner.Creature` 会 CS1061），口径和「造成伤害」（`EmitDamage`）完全一致：

| 作用对象 | 现在生成的形状 |
|---|---|
| 自己 | 老样子（`base.Owner`，**逐字节不变**） |
| 单体敌人 | 优先用触发器给的那个敌人（打出牌后 = 这张牌的目标、受伤后 = 打你的那个），否则取可打的第一个 |
| 全部友方 | `CombatState.Allies.Where(c => c.IsAlive && c != base.Owner)`，并支持「包括自己 / 不包括召唤物」两个勾 |
| 全体敌人 | `foreach (Creature other in base.Owner.CombatState.HittableEnemies)` |
| 全体单位 | `CombatState.Creatures.Where(c => c.IsAlive)` |
| 随机敌人 | 随机挑 N 个（N 可以是层数 / 生效次数） |
| 指定队友 | 状态链没有「玩家选中的目标」→ 和遗物 / 药水一致退回自己（校验器本来就提醒过） |

同一份判据用在 **回复生命值 / 获得·失去格挡 / 失去生命 / 最大生命** 四种上（同一条洞，一起补）。

## 顺带修掉的一个真 bug：最大生命的正负

状态触发链的「最大生命」以前是**按 `base.Amount`（状态自己的层数）的正负**决定加还是减 ——
层数基本恒为正 ⇒ 填「最大生命 -N」实际一直是**加** N。现在按效果数值的正负走（和卡牌 / 遗物 / 药水一致）。
对拍里唯一受影响的老存档是 WhiteCloak 的 `WhiteCloakPowerInsanity.cs`：它写「最大生命 = 本状态的层数」，
层数不可能为负 ⇒ 行为完全不变，只是少掉一段永远不会走的 `else`。

## 为什么按「作用对象被忽略」来查

消息只到「时」。翻过三种可能：① 作用对象被忽略（探针一跑就复现，界面摆了没人读）；
② 回复生命触发循环（本体的触发时机里**没有**「被治疗时」这一档，循环无从谈起）；
③ 回复生命数值不对（`CreatureCmd.Heal` 直接吃数值，没有会夹住的中间层）。只有 ① 是真问题。
