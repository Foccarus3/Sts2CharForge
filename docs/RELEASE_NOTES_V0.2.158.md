# V0.2.158 更新说明

> ⚠ 本版的 `XSpent` / `YSpent` **有个坑**：本体 `ResolveEnergyXValue()` / `ResolveStarXValue()`
> **不是 X 费就直接抛异常**，本版生成的是「直接调用」⇒ 普通牌上写一次就会在战斗中崩。
> **已在 V0.2.159 修好**（改成「先判再调」的三元，并补两条「用错地方 → 读数恒为 0」的警告）。
> 要装就用 V0.2.159。

> 回答你报的：「在次数填 Y（额外资源量）时，只会触发一次」。

## 一、真因：本体是**先扣费、再跑效果**

本体打一张牌的**顺序**（`PlayCardAction`）：

```
await _card.SpendResources()     ← 先把这张牌的费用扣掉（能量 / 额外资源量都在这一步）
   ↓
OnPlayWrapper(...)               ← 再跑这张牌的效果（你的公式就是在这里现算的）
```

所以效果跑的那一刻，公式里的 `X` / `Y` 读到的**不是**「这张牌花了多少」，而是**扣完剩下多少**：

- 「**Y 费**」的牌（资源量费用填 `Y` = 花光全部额外资源量）→ 那一刻额外资源量已经是 **0** →
  次数公式 `Y` 算出来 0 → 生成端 `Math.Clamp(__Y, 1, 20)` 把它**夹到 1** ⇒ 你看到的「只触发一次」；
- 「**X 费**」的牌同理（那一刻当前能量是 0）。

**这不是生成端算错**，是本体时序 —— 所以「让光秃秃一个 `Y` 自动变成花掉的那个数」做不到。

## 二、修法：给公式加两个「**这张牌花掉的**」读数

「可用量」蓝框里多了两个（三个公式框都能用，大小写不敏感）：

| 写法 | 意思 | 生成出来是 |
|---|---|---|
| **`XSpent`** | 这张牌**花掉的能量** | `(decimal)base.ResolveEnergyXValue()` |
| **`YSpent`** | 这张牌**花掉的额外资源量** | `(decimal)base.ResolveStarXValue()` |

这两个读的是本体**自己缓存的**「这张牌花掉了多少」，扣费之后再读也不会变 0。

> 例：Y 费牌，「生效次数（公式）」填 `YSpent` ⇒ 花掉几点额外资源量就重复几遍。

## 三、写错时不再静默

「配置检查」对「**X 费 / Y 费** + 效果公式里真的用了 `X` / `Y`」的牌给**警告**，写清
「本体先扣费再跑效果 ⇒ 那一刻读到 0（次数会被夹到 1）」，并直接指向 `XSpent` / `YSpent`。

判据是**标识符边界**匹配（`YSpent` 里的 `Y` **不算**用到 `Y`）—— 一开始用现成的标识符表，
把 `YSpent` 也当成了「用到 Y」，自己写的正例仍然报警告，已改成正则边界判据。
