## ⑩ 条件「卡牌时机」+ 6 个子时机

> 原文：`条件增加“卡牌时机”，当选择时在底下新增下拉栏，内包含“被消耗”、“被生成”、“被保留”、“被丢弃”、“被变化”，参考原版”战鼓“，再加一个”被给予自定义关键词“，当此卡被给予关键词时条件生效。`

**现状**：`EffectCatalog` 的 `ConditionOption` 表里有 20 个条件（斩杀 / 生命区间 / 洗牌 / 每 N 回合 / 每场一次…），
**没有**这一类。

### ✅ 已查证（2026-10-04）：本体「战鼓」的做法 —— 这一项**不是**「打牌时判断」，而是**挂钩子**

本体那张卡是 `DRUM_OF_BATTLE`（`localization/zhs/cards.json` 里 `"DRUM_OF_BATTLE.title": "战鼓"`），
实现在 `src\Core\Models\Cards\DrumOfBattle.cs`（很短，共 50 行左右）：

```csharp
public override async Task AfterCardExhausted(PlayerChoiceContext choiceContext, CardModel card, bool causedByEthereal)
{
    if (card == this && base.CombatState != null)   // ← 「这张牌被消耗了」
    {
        int playCount = await GeneratePlayCount(base.CombatState, null);
        for (int i = 0; i < playCount; i++)
            await PlayerCmd.GainEnergy(base.DynamicVars.Energy.BaseValue, base.Owner);
    }
}
```

**所以 ⑩ 的正确形态是**：带「卡牌时机」条件的**效果要挂到卡自己的那个钩子上**（`CardModel` 的
`AfterCardExhausted` 这类 override），而不是像现在所有条件那样「打出时算一个 bool」。

实现上要新加一条**生成路径**：把「卡牌时机 = X」的那几条效果，生成成对 `CardModel` 对应钩子的 override
（形如 `if (card == this) { …这条效果的代码… }`），而不是塞进 `OnPlay`。

**待查证（下一步第一件事）**：另外 5 个子时机在本体里各自的钩子名 —— 已确认「被消耗」= `AfterCardExhausted`；
「被生成 / 被保留 / 被丢弃 / 被变化」要在 `CardModel.cs` / `AbstractModel.cs` 里把钩子列表拉出来对上
（`AfterCardGenerated` / `AfterCardRetained` / `AfterCardDiscarded` / `AfterCardTransformed` 之类，名字要对准）。
「被给予自定义关键词」是我们自己的效果（`EmitGiveKeyword` / `EmitGiveKeywordTo`），本工具自己知道时机，
生成一个记账（照现有的 `<角色>ForgeShuffleTracker` 套路）或者直接在给关键词那一步触发即可。

### ✅ 已查证（2026-10-04）：药水 API 是现成的，而且**栏满可判定**

| 要什么 | 本体 API（`src\Core\Commands\PotionCmd.cs` / `Factories\PotionFactory.cs`） |
|---|---|
| 给指定药水 | `await PotionCmd.TryToProcure<T>(player)`（`T : PotionModel`，内部 `ModelDb.Potion<T>().ToMutable()`） |
| 给指定药水（带槽位） | `await PotionCmd.TryToProcure(PotionModel potion, Player player, int slotIndex = -1)`（-1 = 第一个空槽） |
| 失败判定 | 返回 `PotionProcureResult { bool success; PotionModel potion; PotionProcureFailureReason failureReason; }` —— **药水栏满就是失败**（源码注释：*Can fail if the potions bar is full*），所以「栏满要不要丢掉/跳过」由我们决定并写进描述 |
| 随机药水 | `PotionFactory.CreateRandomPotionInCombat(player, rng, blacklist)` / `CreateRandomPotionOutOfCombat(...)`；候选表：`PotionFactory.GetPotionOptions(player)` |
| 相关 UI/上限 | `PlayerCmd.GainMaxPotionCount(int, Player)` / `LoseMaxPotionCount`、遗物 `PotionBelt`、节点 `NPotionContainer` |

**所以 ⑨ 完全可做**，形态照「生成卡牌」那套两档：
- **指定药水** = 新的可搜索下拉（候选 = `EffectCatalog.Potions`，和「目标卡」`SpawnCardId` 完全同构，
  `SearchComboBox` 直接用），生成 `PotionCmd.TryToProcure<类名>(player)`；
- **随机药水** = `PotionFactory.CreateRandomPotionInCombat(player, rng, null)` 再 `TryToProcure(...)`；
  若要「按范围随机」，范围可以从 `GetPotionOptions(player)` 里筛（稀有度/是否战斗可用），先做最朴素的一档。
- 三个上下文都能用（卡牌/遗物/药水；`base.Owner` 是 Player，状态触发器里是 `base.Owner.Player`）。
- 药水栏满 → 写清行为（建议：什么都不发生 + 卡面描述里注明），不要静默。
