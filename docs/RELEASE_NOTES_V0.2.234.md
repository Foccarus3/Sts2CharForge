# V0.2.234 —— 修「开着生成调试日志时，全部友方 / 全体单位的效果让整个模组编译不过」（CS0103: ally）

> 来源：你发来的构建日志（`构建日志_20261019_190513.txt`，522 KB）。
> **40 条 error 全是同一个**：
> ```
> cs\Cards\VitaCard21.cs(48,160): error CS0103: 当前上下文中不存在名称"ally"
> cs\Cards\VitaCard23.cs(23,89):  error CS0103: 当前上下文中不存在名称"ally"
> ```

## 1. 真因：调试日志把「循环变量」写到了循环外面

「作用对象 = 全部友方 / 全体单位」这两档是**逐个动手**的 —— 生成的代码是

```csharp
foreach (Creature ally in base.Owner.Creature.CombatState.Allies.Where(…).ToList()) {
    await CreatureCmd.GainBlock(ally, …);
}
```

而「生成调试日志」（角色页那个勾，V0.2.142）那一行是在**循环外面**打的（先打「打谁、打多少」，
再进循环逐个动手）。以前那一行把目标名写成 **`(ally)?.Name`**：

```csharp
Godot.GD.Print("…；目标=[" + ((ally)?.Name ?? "?") + "]…");   // ← ally 在这一行还没声明
foreach (Creature ally in …) { … }
```

→ `CS0103 当前上下文中不存在名称"ally"`。**只要开着调试日志、又用了「全部友方 / 全体单位」就必定编译不过**
（你日志里那 4 张 VitaCard2x 就是），「全体单位」那档同样会报 `unit`。

> 说明：这是我们工具的问题，不是你的存档 / 环境问题 —— 也**不是**那两个「警告/提示」导致的（它们只是提示）。

## 2. 改法

多目标那几档的日志目标改成一句**固定说明**，不再引用循环变量：

```csharp
Godot.GD.Print("[模组调试] 卡牌「…」 → 获得格挡（负数 = 失去）；数值=…；目标=[全部友方（逐个动手）]");   // CET:DebugLog
```

- 覆盖：**获得 / 失去格挡、回复生命、失去生命、造成伤害、最大生命、临时增益**（卡牌链、遗物链、药水链同一份发射器）；
- 「施加状态 · 执行前 / 执行后层数」那两行本来就**在循环里面**（逐个人名），照旧会打出每个队友 / 每个单位的真实层数 —— 排查信息没丢；
- **红线**：单目标档（自己 / 指定敌人 / 全部敌人）的日志形状一个字没动；调试日志**关着**时仍然一个字符都不多写；
  老存档对拍依旧只差 `.sln`。

## 3. 你现在怎么做

1. 用新版重新生成一次（`生成 → 一键构建 + 安装`）——那 40 条 `ally` 错误就会消失；
2. 如果还开着「生成调试日志」排查别的，可以继续开着：现在它会正常把「打的是谁 / 几层」打进 `godot` 日志；
3. 排查完记得**把那个勾去掉**再生成一次（日志会变多，但不再影响编译）。
