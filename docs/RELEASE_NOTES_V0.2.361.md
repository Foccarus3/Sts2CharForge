# V0.2.361 — 清单版本 `apiVersion` 改成「自动迁移」，不再一不匹配就拒绝

以前 `apiVersion` 必须**正好等于**当前版本，否则整个插件被拒绝。这带来两个实际问题：

* 老插件**没写** `apiVersion`（早期规范里是可选的）→ 直接不加载，作者一脸问号；
* 编辑器一升级版本号，所有老插件**集体失效**，只能等作者改。

## 现在的规则

当前版本 = **2**，能自动迁上来的最低版本 = **1**：

| 插件写的是 | 结果 |
|---|---|
| **没写** | 按 v1 兼容加载，插件信息里给一条提示（建议补 `apiVersion: "2"`） |
| `"1"` | **自动迁移到 2**，记一条迁移提示；插件照常可用 |
| `"2"` | 正常加载，无提示 |
| 比 2 新（`"9"`） | **拒绝**并说明「请升级编辑器」 |

## 几个设计点

* 迁移**不改磁盘上的 plugin.json**（作者写的那句保持原样），只在内存里按当前版本处理；
* 新增 `PluginSpec.Notes`（非致命提示），界面上和「⚠ 有问题」分开显示 ——
  前者只是告诉你发生了迁移，后者才代表插件不生效；
* `PluginSpec.ApiVersion` 的默认值从 `"1"` 改成**空**，这样「没写」和「写了 1」能分开提示
  （这条是自检抓到的：默认值把「没写」变成了「写了 1」）；
* 以后加新版本：编辑器把版本加一，在 `TryMigrateApiVersion` 里补一段 `case` 做字段改名 / 补默认值，
  **老插件永远不用作者手动改**。
