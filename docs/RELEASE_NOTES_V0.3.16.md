# V0.3.16 — 变量页：战斗开始重置 + 写操作（四链 + 锻造节点）

接 V0.3.15（变量容器接进工程 + 校验），这一版把变量真正**跑起来**：战斗开始会复位，四种写操作
（`+ / - / = / 清零`）在卡牌 / 遗物 / 药水 / 自定义状态 / 锻造【效果】节点里都能用。

> ⚠ **变量页界面还没做**（下一版 V0.3.17）。这一版之后，变量仍然只能靠手改存档 JSON 建出来；
> 做出界面之前，普通用户还用不上它。这点我不含糊。

## 一、重置：战斗开始 + 新开一局

新增生成文件 `cs/<角色>VarsReset.cs`（只在有变量时生成）：

| 时机 | 挂法 | 调用 |
|---|---|---|
| 每场战斗开始时 | Harmony 前缀补丁打在 `Hook.BeforeCombatStart` 上 | `<角色>Vars.ResetCombat()` |
| 新开一局 / 读档进入时 | Harmony 后缀补丁打在 `RunManager.Launch` 上 | `<角色>Vars.ResetRun()` |

两个补丁都先判断「这一局里有没有我们这个角色」（`runState.Players.Any(p => p.Character is <角色>)`），
别的角色不会碰；整段包在 `try/catch` 里，重置失败只写一行 `Log.Warn`，不会连累模组加载。

**为什么不用「角色类 override BeforeCombatStart」**：本体 `Hook.BeforeCombatStart` 只遍历
`IRunState.IterateHookListeners` 里的模型（牌组里的卡 / 遗物 / 药水 / 修正 / 订阅者 / 战斗内模型），
**角色模型本身不在里面**（`RunState.cs` 的 IterateHookListeners 已核对）——写在角色类上永远不会被调用。

## 二、初值公式：能折成常数就按初值复位

`VarSpec.Formula` 现在真的参与生成：

* `cnt = 2` → `private static int _cnt = 2;`，`ResetCombat()` 里 `cnt = 2;`；
* `run_pts = cnt + 1` → 生成期先折出 `3`，字段初值 / `ResetRun()` 都是 `3`；
* 公式里含 **X / Y / 内置读数 / 自定义参数**（这些值战斗开始时还没有）→ 折不出来，重置按 `0`，
  并在校验器里给一条**提示**说清，不让用户以为「写了公式却没生效」。

## 三、写操作：`+ / - / = / 清零`（四链 + 锻造节点）

效果种类新增 **「变量（+ / - / = / 清零）」**：

* 选变量页里的变量 + 选怎么改；值走「数值（公式）」那一栏（留空 = 0，可以引用别的变量 / 参数 / X、Y / 内置读数）；
* 生成的是 **`<角色>Vars.<变量> += / -= / = (int)(表达式)`**，`清零` = `= 0`；
* 夹取（不允许负数 / 上限）由变量属性 setter 负责，生成端不重复夹；
* **五处都接了**：卡牌、遗物、药水、自定义状态、锻造【效果】节点（`SupportedEffectKinds` + 支持名单同步加）；
* 它**不声明卡牌动态变量**（值直接写进容器类），也没有「升级增量」、没有「作用对象」。

示例（卡牌链，`cnt` 是变量）：

```csharp
SevenVars.cnt += (int)(((1m) + (1m)));          // + 加
SevenVars.cnt -= (int)(2m);                      // - 减
SevenVars.cnt = (int)((SevenVars.cnt + (3m)));   // = 设为
SevenVars.cnt = 0;                               // 清零
```

## 四、顺手修的两个真缺口（V0.3.14 / V0.3.15 遗留）

1. **卡牌公式里读不到变量**：V0.3.14 只给 `InlineResolver`（遗物 / 药水 / 状态 / 锻造）加了变量，
   卡牌走的是 `CardResolver` —— 卡牌公式里写 `cnt + 3` 会退回 `base.DynamicVars["Value"]`，等于没读变量。
   这一版给 `CardResolver` 补上变量（和参数同一条查找顺序）。
2. **公式解析器不接受多字母变量名**：`ForgeFormula.TryParse` 以前对「超过 1 个字母、又不是内置量」的标识符
   直接判错，而变量名按规格最多 12 位（`cnt` / `run_pts` 都过不了）。现在 1~12 位的多字母标识符会当成变量名
   交给 resolver / 校验器；**超过 12 位的乱名字仍然当场报错**（老回归保留）。

## 五、校验（生成前拦住）

* 「变量」效果没选变量 → **错误**；
* 选了变量页里不存在的名字（改名 / 删除后）→ **错误**，说清「生成出来会引用一个不存在的变量」；
* 写操作不是四档之一 → 错误；
* 初值公式含运行时量 → **提示**（重置按 0，见第二节）。
