# V0.2.253 — 自定义状态里的「升级卡牌」：无玩家守卫 + 「全部」补上 + 调试日志

## 你澄清的

> 是自定义的状态具有升级卡牌的效果，但是用来升级能够无限升级的状态牌无效果

这和上一版说的「本体状态牌不能升级」是两件事 —— 你那张牌**已经**勾了「可被无限升级」（`MaxUpgradeLevel => int.MaxValue`），
所以 `c.IsUpgradable` 是 true。生成端那条链我也逐条查过（31 个触发时机全试了，都能生成出 `CardCmd.Upgrade`），
所以**这一版做的是把「为什么没反应」变成看得见**，外加两个真问题：

## 改了什么

### ① 状态挂在「没有玩家」的生物身上时会炸（现在拦住了）

状态里的「升级卡牌」要拿手牌：`PileType.Hand.GetPile(base.Owner.Player)`。
如果这只状态被贴在**敌人 / 召唤物**身上（或者你把它做成减益贴在对面），`base.Owner.Player` 是 `null` ——
以前直接把 null 传进去，运行时空引用、效果静默失败。现在生成的第一句是：

```csharp
if (base.Owner.Player is null) return;   // 这个状态挂在没有玩家的生物身上：拿不到手牌，直接跳过（不会炸）
```

### ② 状态里的「升级卡牌 + 全部」以前没实现

状态这条链只实现了「自己选 / 随机挑 N 张」；「取几张 = **全部**」会被当成「随机挑 N 张」。
现在补上了，和卡牌页一致：那一摞里**所有能升级的牌**一次全升级。

### ③ 开「生成调试日志」后，会打出候选数

```csharp
Godot.GD.Print("[模组调试] 状态「你的状态名」 → 升级卡牌（手牌）：可升级的牌 " + …Count(…) + " 张（状态牌 / 诅咒牌要勾『可被无限升级』才能升）");
```

**「没效果」九成就是这一行是 0**：手牌里那一刻没有状态牌，或者状态牌没勾「可被无限升级」。
打开方式：「路径 / 选项」→ 勾「生成调试日志」→ 重新生成 → 进游戏打一场，日志里搜 `模组调试`。

## 你可以这样排查（按顺序）

1. **状态在谁身上**：「升级手牌」这条效果只有在状态挂在**你自己**身上时才有意义 ——
   把它施加到自己身上（效果里「作用对象」= 自己），别贴在敌人 / 召唤物上；
2. **那一刻手牌里有没有状态牌**：本体的状态牌大多在抽牌堆 / 弃牌堆里。
   如果你手里没有，可以把效果的「从哪里选牌」改成**抽牌堆 / 弃牌堆 / 消耗牌堆**；
3. **那张状态牌勾没勾「可被无限升级」**：「诅咒 / 先古卡 / 状态」页 → 选中它 → 勾上；
   并且**填好「升级增量」**（不填的话，即使升级了，卡面数值也不会变 —— 看起来还是「没效果」）；
4. 以上都对还没反应 → 开「生成调试日志」，把 `模组调试` 那几行发我（特别是「可升级的牌 N 张」）。
