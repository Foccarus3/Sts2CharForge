# V0.3.136 — 修掉自检里长期挂着的 2 条 FAIL（卡牌页序号 / 行命中）

这一版**只改自检代码**，产品行为、生成结果、存档格式都不变。

## 一、现象

`--uicheck` 从 V0.3.130 之后一直固定挂两条失败（V0.3.135 里用改动前的 V0.3.134 原版二进制
对照确认过：同样是这两个）：

```text
FAIL  界面上真画出了「N.」序号（序号在卡牌名最左侧一列），而且是从 1 开始连续的下标  → 看到 2 个（1.,2.）/ 共 11 张
FAIL  CardRowAtPoint 能按行号认出鼠标下面是哪张卡（拖动起手 / 落点都用它）        → (没有容器)
```

## 二、根因

两条都在卡牌页「序号列 / 可拖动」那一段，测的是**界面上真的实化出来的行**：

- 卡牌列表默认**虚拟化**，只给视口内的行建容器；
- 自检窗口里那一块列表实测只有 `380×50`（脚本没把窗口布局到全尺寸），只放得下 2 行；
- 于是「序号文字」只数到 2 个（断言要求 ≥3），第 3 行的容器是 `null`（`(没有容器)`）。

**不是界面真的只显示两行**：同一份自检后面那段（「每 5 个一块 + 空槽」，要求看颜色 / 命中）
本来就写了这个坑，并临时关掉虚拟化，所以那边 5 / 10 / 15 行都能数到、`CardRowAtPoint`
点空槽行也是通过的。这次就是把同样的做法补到前面这一段。

## 三、改法

`MainWindow.xaml.cs` 卡牌页「序号列 / 可拖动」这一段：

```csharp
// V0.3.136：这一段要看「界面真的画出来的行」，列表默认虚拟化 → 临时关掉，跑完 finally 还原
bool cardVirtWas = VirtualizingPanel.GetIsVirtualizing(CardList);
try
{
    VirtualizingPanel.SetIsVirtualizing(CardList, false);
    SelectTabRoot("卡牌");
    ...
}
finally
{
    VirtualizingPanel.SetIsVirtualizing(CardList, cardVirtWas);
    ...
}
```

同时**收紧**了序号那条断言（不是放宽）：

- 以前：`可见序号数量 >= 3` 且从 1 连续；
- 现在：`可见序号数量 == 列表行数`（这一段关掉虚拟化后，全部行都必须实化）。

行命中那条的失败信息也补上了列表实际尺寸和行数，以后再出问题一眼能看出是「没实化」还是「点偏了」。

