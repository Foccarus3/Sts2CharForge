# V0.2.141 更新说明

> 这一版修你报的「**在生成器填负值的力量不生效**」。真因**不在生成端**，在「**从工程恢复存档**」的回读。

## 一、真因：回读把「升级增量」加了两次

一张牌的「升级增量」在生成出来的产物里写了**三处**：变量构造的第二个参数、打出时那个三元式、`OnUpgrade` 里的 `UpgradeValueBy`。回读时**前两处就已经算出增量了，第三处又相加一次** —— 你那张「闪耀登场」的升级增量因此从 **1 变成 2**（实测）：

```
产物原文:  ForgeFormulaPowerVar<StrengthPower>(..., 1m)
           Apply<StrengthPower>(..., (base.IsUpgraded ? 2m : 1m), ...)
           base.DynamicVars["StrengthPower"].UpgradeValueBy(1m)     ← 增量是 1
回读(旧):  升级增量 = 2      ← 错，多算了一份
回读(现在): 升级增量 = 1     ← 对
```

于是你把「数值公式」填成 `-2` 之后生成出来是：

```
Apply<StrengthPower>(..., (base.IsUpgraded ? 0m : -2m), ...)   ← 升级后 = -2 + 2 = 0 层
```

**升级过的那张打出去 = 施加 0 层 = 什么都没发生**（没升级的那张才是 -2）。这就是你看到的「填负值不生效」。

**修法与边界**：回读时三元式给过的增量就不再累加 —— 两边相等就跳过，不等就以 `UpgradeValueBy` 为准覆盖，**绝不相加**。两条老路一行没改：没有公式的 `new DamageVar(6)` + `UpgradeValueBy(3m)` 照旧得 3；真·现算公式（`M*2` + 3m）照旧得 3 且公式原文 `M*2` 原样回来。**生成端一个字节没动**。

## 二、顺手加的三处可见性（这次让你一眼看见）

1. **校验器新增警告**（是**警告**，不是错误 —— 绝不会拦住老存档生成）：
   > 「施加增益/减益（负数 = 扣除层数）」：升级增量 +2 把数值公式里的 **-2** 抵成了 **0**：**升级后的这张牌打出去不会有任何效果**（没升级的那张才是 -2）。想让升级后照样有 2，请把「升级增量」清成 0。
2. **效果列表的摘要行**直接写结果：`增益/减益 StrengthPower 数值公式 -2（升级后 0） → 自己` —— 不用点开逐条看。
3. **真·现算公式不写假数字**（折不出常数就不写「升级后 X」），照旧只显示公式本身。

## 三、你现在怎么用

- 升级到这一版后，**之前从工程恢复过的那张「闪耀登场」的升级增量会自动变回 1**（不用手动改）。
- 想让它**升级后扣 2 层力量**：数值公式填 `-2`，**「升级增量」清成 0**。
- 「升级增量」留着 `2` 的话，生成器现在会**明确警告**你「升级后是 0 层」，不会再默默不生效。
