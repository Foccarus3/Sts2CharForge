# V0.2.229 —— 卡面「缩小档」重做：上一版那个勾选框**实测等于没缩**（这次给能看出区别的 2× 档）

> 来源：你回「**卡面过大时高质量缩小到游戏显示尺寸** 这个好像没什么区别」。
> 你是对的 —— 我把上一版那个勾选框的数值算错了，这里把实测数据和真因一起写清。

## 1. 为什么上一版「没区别」：4× 和不缩在数学上一模一样

游戏里卡面是这么画的（本体 `scenes/cards/card.tscn`）：

| 部位 | 节点尺寸 | 备注 |
| --- | --- | --- |
| 普通卡 `%Portrait` | **250×190**（游戏单位） | `expand_mode = 2` / `stretch_mode = 5`（`KEEP_ASPECT_CENTERED`） |
| 先古卡 `%AncientPortrait` | 598×842 × **scale 0.5** ⇒ **299×421** | 本体先古卡素材 606×852 ≈ 2× |

而卡面这张纹理**没有 mipmap**（生成的工程里没有 `.import`，Godot 4.5 默认
`mipmaps/generate=false`、`compress/mode=0` 无损、滤镜是 `Linear`）。也就是说引擎缩小的时候，
**每个输出像素只用双线性采样 4 个纹素**：

- 你传 2000×1520、卡面画在 250×190 上 ⇒ 缩小 8 倍，16 个纹素里只用到 4 个；
- 预缩到 1000×760（上一版那个 4×）⇒ 缩小 4 倍，**还是 16 个里只用到 4 个**；
- 预缩到 **500×380**（2×）⇒ 缩小 2 倍，4 个纹素**刚好全部用到**；
- 预缩到 250×190（1×）⇒ 1:1，引擎不缩。

用探针 `sacprobe imgcmp` 拿本体的卡面（`strike_ironclad.png`）算「和理想面积平均的 RMSE」：

| 做法 | RMSE（越小越接近理想） |
| --- | --- |
| 直接让引擎缩（= 不缩 / 上传大图） | **3.42** |
| 预缩 4× → 1000×760（**上一版那个勾选框**） | **3.42** ← 一模一样，所以「没区别」 |
| 预缩 3× → 750×570 | 5.53（更差：像素网格对不上） |
| 预缩 2× → 500×380 | **0.27** |
| 预缩 1× → 250×190 | 0.00 |

结论：**只有「缩到显示尺寸的 2 倍」这一档真的能改善画质**；上一版缩到 1000×760 只省文件体积。

## 2. 这一版改成下拉框，四档

「美术资源」页：**卡面过大时缩小到（游戏实际显示尺寸的几倍）**

| 档位 | 普通卡 / 先古卡 | 说明 |
| --- | --- | --- |
| **原样拷贝（不缩）** | 不动 | 默认。工具一个字节都不压缩、原样拷进工程 |
| **缩到显示尺寸的 2 倍（500×380，推荐）** | 500×380 / 598×842 | 引擎缩 2 倍时 4 个纹素刚好用满 —— **唯一看得出区别的一档**（RMSE 0.27） |
| 缩到显示尺寸（250×190） | 250×190 / 299×421 | 1:1，1080p 满屏最锐利；窗口再放大就会糊 |
| 缩到显示尺寸的 4 倍（1000×760） | 1000×760 / 1196×1684 | 本体素材口径；明确标注「和没缩几乎一样，只省体积」 |

- **老存档**：V0.2.228 那个勾选框（`FitCardArtToFrame = true`）会被当成 **2×** —— 也就是你之前勾的那个
  现在会真的生效（不用再点一次）；勾选框本身已经换成下拉框；
- 下拉框下面那行小字会写出**每一档的实际效果**（4× 那档直接说「和没缩观感几乎一样，想要区别请选 2×」）；
- 预览下面那句分辨率说明也会跟着档位变（现在是 2× 就写「已设成 2×」，是 4× 就提醒你选 2×）；
- 规矩没变：**只缩不放大**（比目标小的图一个字节都不动）、**缩的是拷进工程那份副本**、原图永远不动、
  生成日志写清 `卡面 xxx：2000×1520 → 500×380（…面积平均，原图不动）`。

## 3. 顺带纠一处文档错误

上一版和更早的注释把 `%Portrait` 写成了 `KEEP_ASPECT_COVERED`（会裁边）。实测 `card.tscn` 里是
**`stretch_mode = 5` = `KEEP_ASPECT_CENTERED`**（按比例装进去、不裁边），先古卡那块也是「装进去 + 节点 0.5 缩放」。
`AspectNoteOf` 那行「比例不对会留黑边」的结论本身没错（留边正是 contain 的行为），这里只把注释改正。
