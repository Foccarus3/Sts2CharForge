# 插件市场发布指南（作者 / 维护者）

适用版本：Sts2CharForge **V0.3.73+**、MarketAdmin **V0.3.74+**。

插件本地能加载，不代表能直接上架。市场包有自己的目录、元数据和审核规则。

---

## 1. 本地插件和市场的区别

| 项目 | 本地插件 | 市场包 |
|---|---|---|
| 放哪 | `程序目录\plugins\<id>\` | GitHub `market\packages\<id>-<version>.zip` |
| 谁读 | 生成器启动时扫描 | 用户在「插件市场」下载安装 |
| 用途 | 开发 / 自用 | 公开分发 |
| 额外要求 | 能加载即可 | SHA256、许可证、分类、版本规则、审核 |

市场安装后仍然解压到：

```text
程序目录\plugins\<id>\
```

所以插件代码和运行方式不变，变的是**打包和发布**。

---

## 2. 市场包结构

市场包必须是 ZIP。作者拿到 RAR 时，用 MarketAdmin 的「RAR 转 ZIP」入口先转换；最终上架仍然是 ZIP。

ZIP 根目录必须能看到 `plugin.json`，或者只套一层文件夹：

```text
card_gif_swap-1.5.0.zip
  plugin.json
  README.md
  CHANGELOG.md
  cs/CardGifSwap.cs
  cs/CardGifDecoder.cs
  assets/card.gif
```

允许：

- `plugin.json`
- `cs/**`
- `assets/**`
- `README.md` / `CHANGELOG.md` / 其他文档
- 图片、GIF、音频等插件资源

不允许：

```text
.dll
.exe
.bat
.cmd
.ps1
.vbs
.scr
```

安装辅助脚本（例如「安装GIF到用户目录.bat」）**不要放进市场包**：

- 插件运行时不需要它们；
- 把它们放到 GitHub Release 的附加文件里；
- README 写手动步骤；
- 需要真正的一键操作，做成插件扩展页里的按钮。

---

## 3. plugin.json 和市场元数据

### plugin.json 负责

```json
{
  "id": "card_gif_swap",
  "name": "卡牌 GIF 替换",
  "version": "1.5.0",
  "apiVersion": "2",
  "author": "作者",
  "description": "一句话说明"
}
```

注意：

- `id` 发布后**不要改**。改 id 等于新插件，旧用户不会自动迁移。
- `version` 每次发布必须提升；同 id + 同版本不能覆盖。
- `apiVersion` 当前是 `"2"`。
- 不要在 `plugin.json` 里塞市场专用的 `categories` / `keywords` / `license` 字段。它们写在市场索引里。

### 市场索引负责

```json
{
  "id": "card_gif_swap",
  "name": "卡牌 GIF 替换",
  "author": "作者",
  "description": "一句话说明",
  "license": "MIT",
  "apiVersion": 2,
  "minGeneratorVersion": "V0.3.73",
  "homepage": "https://...",
  "categories": ["animation", "assets"],
  "keywords": ["gif", "动画", "逐帧"],
  "versions": [
    {
      "version": "1.5.0",
      "download": "https://raw.githubusercontent.com/.../market/packages/card_gif_swap-1.5.0.zip",
      "sha256": "小写十六进制",
      "notes": "更新说明",
      "gameVersion": "v0.113.x",
      "publishedAt": "2026-11-15T19:00:00Z"
    }
  ]
}
```

## 4. 分类

分类 id 只能从下面选，可多选，最多 4 个：

| id | 显示 |
|---|---|
| `effects` | 效果种类 |
| `conditions` | 条件 |
| `triggers` | 触发时机 |
| `forge` | 锻造模块 |
| `animation` | 动画 / 视觉 |
| `ui` | UI / 页面 |
| `content` | 卡牌 / 遗物 / 药水扩展 |
| `tools` | 工具 / 自动化 |
| `assets` | 资源包 |
| `other` | 其他 |

一个插件可以同时属于多个分类，例如：

```json
"categories": ["animation", "assets"]
```

不要为了搜索乱填分类。

---

## 5. 关键词

规则：

- 最多 **10 个**；
- 去重、去首尾空格；
- 不要堆砌无关词；
- 建议覆盖：功能、对象、机制、素材类型。

示例：

```json
"keywords": ["gif", "动画", "逐帧", "卡牌", "替换"]
```

---

## 6. 许可证

市场条目必须填 `license`，例如：

```text
MIT
Apache-2.0
CC-BY-4.0
GPL-3.0
```

没有许可证的插件不接收。

同时确认：

- 代码 / 图片 / 音频是你自己做的，或有明确授权；
- 不包含游戏本体的卡图、音频、字体、场景等资源；
- 不使用别人的付费素材。

---

## 7. 版本规则

### 新插件

```text
0.1.0
```

### 更新

```text
1.5.0 → 1.5.1
```

要求：

- 同 id + 同版本不能重复；
- 不能覆盖已发布版本的包；
- 旧版本保留在 `versions[]` 里；
- 版本号建议语义化：
  ```text
  1.5.0  功能版本
  1.5.1  修复版本
  ```
- 改了插件内容就必须提升版本。

## 8. 包大小和托管

| 包大小 | 放哪 |
|---|---|
| ≤5 MB | `market/packages/<id>-<version>.zip`，随 git 提交 |
| >5 MB | GitHub Release，不塞仓库 |

MarketAdmin 当前只支持小包进仓库；大于 5 MB 会拒绝并提示走 Release。

大包手动流程：

1. 上传 ZIP 到 GitHub Release；
2. 在 `market/index.json` 写版本；
3. `download` 填 Release 地址；
4. SHA256 用 `Get-FileHash` 计算。

---

## 9. SHA256

Windows：

```powershell
Get-FileHash .\card_gif_swap-1.5.0.zip -Algorithm SHA256
```

索引里写小写：

```json
"sha256": "8af0e2f87be66c34f380168315d7da09b65bef39a28b7e52673efe140233bfdc"
```

生成器安装前会重新计算并比对，不一致直接拒绝。

## 10. 发布流程

### 方式 A：MarketAdmin（维护者本机）

1. 打开 `启动_MarketAdmin.bat`；
2. 选择插件 ZIP；
3. 解析并修改名称 / 作者 / 版本 / 简介 / 许可证 / 分类 / 关键词；
4. 点「生成市场包 + 写索引」；
5. 检查 `market/index.json`；
6. 点「提交并推送 git」。

### 方式 B：GitHub PR（作者）

1. fork 仓库；
2. 把 ZIP 放到 `market/packages/`；
3. 修改 `market/index.json`；
4. 提 PR；
5. CI / 维护者审核；
6. 合并后用户刷新市场即可看到。

---

## 11. 审核清单

维护者合并前检查：

- [ ] `plugin.json` 的 id / 版本和索引一致；
- [ ] id 合法且唯一；
- [ ] 版本没有重复；
- [ ] 有明确许可证；
- [ ] 没有 `.dll / .exe / .bat / .ps1`；
- [ ] 没有游戏本体资源；
- [ ] 没有路径穿越 / 超大文件；
- [ ] SHA256 一致；
- [ ] 分类 / 关键词合理；
- [ ] 本地安装一次能加载；
- [ ] 更新版本说明清楚。

---

## 12. 删除 / 下架

### MarketAdmin

- 顶栏「已有插件」搜索 / 选择已上架插件和版本；
- 「删除当前版本」：删除 id + 当前版本，并删除对应本地包；
- 「删除整个插件」：删除整个条目和该 id 的所有本地包；
- 都会先备份 `market\index.json.bak`；
- 不会自动提交 git，也不会删除 GitHub Release 附件；
- 删完要再点「提交并推送 git」才会影响远程市场。

### 手动

1. 从 `market/index.json` 删除条目或版本；
2. 删除 `market/packages/<id>-<version>.zip`；
3. `git add / commit / push`；
4. 包在 Release 的，再去删 Release asset。

已安装用户不会被远程卸载，需要自己卸载插件。

## 13. 常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| 索引写入了但市场看不到 | 还没 git push | 推送后刷新 |
| 安装失败 SHA 不一致 | 索引和包不是同一份 | 重新计算并更新 |
| 同版本被拒 | 已经发布过 | 提升版本 |
| 包超过 5 MB | 资源太大 | 精简或走 Release |
| 下载 404 | `market/packages` 里没有这个包 | 先提交包再合并索引 |
| 插件加载失败 | ZIP 里 `plugin.json` 位置不对 | 放到根或一层目录 |
| 安装后没有脚本 | 市场包会移除 `.bat/.ps1` | 按 README 手动操作 |
