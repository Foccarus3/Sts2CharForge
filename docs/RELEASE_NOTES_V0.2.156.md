# V0.2.156 更新说明

> 回答你报的：「**在卡牌列表拖动卡牌后，卡面会变成其他卡**」。修好了 —— 而且这次挖出来的是一条
> 挺深的链：一个 bug 叠了**三层**，只修一层都还是错的。

## 一、为什么会「卡面变成别的卡」

卡面是**按类名**存的（`Art.CardPortraits["SevenCard3"] = 你上传的图`），而自动英文类名是
**按列表行号**算的（第 3 行 = `SevenCard3`）。所以拖动之后，**名字没跟着卡走**就等于「图跟错了人」。

三层叠在一起：

1. **改号的时机不对**（V0.2.156 修）：拖动的落点逻辑是
   `Cards.Move(...) → RefreshCardOrdinals() → SyncDetail()`，而 `RefreshCardOrdinals` 会把每张卡的
   `LastAutoOrdinal`（= 它**上一次**的号）就地改成**新**行号 —— 可「旧名 → 新名」这张映射表正是
   靠 `LastAutoOrdinal` 算出来的。先覆盖 → 映射永远算不出来 → 卡面原地不动。
   现在把「搬引用」挪到它**前面**（`RefreshCardOrdinals` 的第一件事）。
2. **界面重入把一次搬迁拆成了好几次**（V0.2.156 修）：搬迁过程中会改 `ClassName` /
   `LastAutoOrdinal` / 效果里的 `SpawnCardId` → 触发 `PropertyChanged` / `CollectionChanged` →
   界面那几个处理器**重入**刷新（`RefreshCardChoices` → 又搬一次）。重入时号只改了一半，
   于是它算出一张**部分映射**又搬一遍 —— 实测一次拖动搬了 **4 遍、每次只搬一张**，几张卡面互相覆盖。
   现在：① 搬迁期间**重入一律直接返回**（最外层那一次负责把整张表搬完）；
   ② `Naming.RenumberCardClassNames` 改成**两趟**（先把整张「旧名 → 新名」表算完，再动手改卡），
   即使有重入也不会算出半张表。
3. **搬卡面用的是「顺序搬」**（V0.2.156 修）：把牌往上拖会形成名字的**环**
   （`[A,B,C] → [C,A,B]` 时 `12→13`、`13→14`、`14→1`），顺序搬 + 「目标已有图就跳过」在环上会把
   先搬进去的那张图**删掉**（原 12 的那张整个丢了）。现在改成**从零重建一张新表**
   （每个旧键各自搬到它的新键），对环天然正确。

## 二、自检怎么钉住它

新增 3 条断言，**走的是真实那条路径**（`RefreshCardOrdinals` + `Cards.Move`，不是另写一套模拟）：

- 拖动卡牌之后，三张卡的卡面跟着**各自那张卡**一起走（一张都不能错位、不能丢）；
- **反向说明**断言：拖动前的旧名字现在确实属于**另一张卡**（不搬就是「卡面变成别的卡的图」，
  把你看到的现象钉死）；
- 把牌**往上拖形成「名字成环」**时也搬得对。

**反向验证**：把「重入保护」那一行临时关掉 → 这 2 条立刻 FAIL（`拖动探针1 拿到的是（没有卡面）`），
打开即 0 FAIL。
