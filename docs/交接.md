## 七、操作坑（V0.2.303 / V0.2.304 踩到）

1. **部署目录跑完 `--uicheck` 会在 `程序文件\自定义角色` 留一个角色工程**（带 `libs\sts2.dll`），
   而 `make_update.ps1` 的自检「包里不许有游戏文件」会因此直接失败、打不出更新包。
   V0.2.304 起 `make_update.ps1` 打包前会把它整份挪到
   `自定义角色存档\_旧位置残留_同名没搬\`（不删、不进包），不用再手工处理。
2. **PowerShell 调 GUI 子系统的 exe 不会等它**：跑部署版 `--uicheck` 要用
   `Start-Process -FilePath .\Sts2CharForge.exe -ArgumentList '--uicheck' -PassThru` + `$p.WaitForExit()`，
   然后读 exe 旁边的 `uicheck_result.txt`（UTF-8，用 `Get-Content -Encoding UTF8` 读，不然全是乱码）。
   一次大约 5~15 分钟（V0.2.303 885 秒 / V0.2.304 约 13 分钟）。
3. **`edit` 工具改 `.ps1` 会把 UTF-8 BOM 弄丢** → `powershell.exe`（5.1）按 ANSI 读中文，整份脚本解析失败
   （报 `Unexpected token '}'` 一堆）。V0.2.304 改 `make_update.ps1` 时踩到，差点把发版流程搞坏。
   **改完 `.ps1` 必须补 BOM**：
   ```powershell
   $p='...\tools\xxx.ps1'; $t=[System.IO.File]::ReadAllText($p,[System.Text.Encoding]::UTF8)
   [System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding $true))
   ```
   验证：`(Get-Content $p -Encoding Byte -TotalCount 3)` 应该是 `239 187 191`。

   `D:\ds\s\_备份\部署残留_20261027\`，可以直接删。

## 十一、V0.2.341 已修完：「每 N 张牌触发一次」整体晚一张（**别再当待办查**）

用户报：手刃形态写着「每打出两张牌，获得一点临时力量临时敏捷」，实际**第三张**才给。

真因（对着本体源码 `src\Core\Models\CardModel.cs` 的 `Play` 核过，本地解包工程在 `D:\download\slay\1`）：

1. 「打出一张牌时」挂在 `BeforeCardPlayed`，本体顺序是
   `await Hook.BeforeCardPlayed(...)` → `History.CardPlayStarted(...)` → `OnPlay(...)` → `History.CardPlayFinished(...)`。
   **那一刻历史里没有正在打出的这一张**；生成端从 V0.2.173 起一直当它「含这一张」（旧注释就是错的）
   → 每累计 N 张触发一次整体晚一张（N=2 打 3 张、N=3 打 4 张）。遗物链没有基准值抵消，肉眼可见。
2. 状态链基准值字段的哨兵用 `-1`，而「本回合第 1 张牌」算出来的基准**正好也是 -1**
   （历史累计 0 → 基准 = 0-1 = -1）→ 下一张牌又当成「还没记过」再重置一次，**每回合第一张被吞掉**
   （所以是第 3、5、7 张触发，不是第 2、4、6 张）。

修法：

* `CSharpCodeGen.CountExpr("CardPlayed", …)`：计数 `+ 1`（含正在打出的这一张）；
  有「只对哪类牌生效」时补的那一张也按同一筛选判 → `+ (cardPlay.Card.Type == CardType.Skill ? 1 : 0)`
  （新增 `CardFilterExpr`，`CardFilterCond` 改成它的 `&&` 包装；不然「只对技能牌、每 2 张」打攻击牌也会给技能计数 +1）。
* `CountExpr` / `TriggerAmountCond` / `TriggerAmountLines` 多了 `currentCardExpr` 参数，
  状态链和遗物链都传 `cardPlay.Card`。
* 状态链基准字段哨兵 `-1` → `int.MinValue`（字段名一个字符不变）。
* 「一张牌结算完毕时」(`CardResolved`) **不动** —— 本体先记 `CardPlayFinished` 再调钩子，本来就含这一张。

现在：N=2 → 第 **2、4、6** 张触发；状态是某张牌施加的时，那张算进基准、不参与计数（之后要再打 2 张）。

自检 +9 条（`V0.2.341：`），其中一条是「从生成文本里把步长抠出来、按生成的那三行原样模拟 → 第 2、4、6 张」。
另外 9 条 V0.2.168 / V0.2.211 的旧断言因为**生成文本变了**（`+ 1)` / `int.MinValue`）同步更新过 —— 语义没放宽。

⚠ **未解**：用户同时说「第二张是技能才行」。生成的 `yinsushouren.cs` 里**没有任何牌型判据**
（整份文件搜不到 `CardType`），所以这条对不上代码，等用户给精确用牌顺序（哪几张 / 什么类型 / 手刃形态是第几张施加的）。

## 十二、V0.2.342 已修完：「打出的牌浮在空中」的兜底（**别再当待办查**）

用户报：**破解这张牌打出后浮在空中**（存档 `rukayukiking.json` = 月雪）。

查证结论（**牌本身没问题**）：

* 生成的 `cs/Cards/Hikii.cs` 里没有 `cardPlay.Target` —— 不是 V0.2.217 / V0.2.243 那个
  「多目标牌读到空目标 → `ThrowIfNull` → OnPlay 中断 → 牌停在出牌位浮空」的洞。
* 卡面 / 动画：`Animation` 全默认（Scale 0 / YOffset 0），`CardArtShrink` 空；破解用的 PNG 与另外三张牌同一张 → 不是美术。

**浮空的机制**：本体 `CardModel.Play` 是「先 `await` OnPlay 返回，之后才 `CardPileCmd.Add(this, resultLocation.pileType…)`」
→ 牌悬着 = OnPlay 里的 `await` 链没结束（或抛异常）。破解一次给**所有敌人**上「骇入」，
把每个敌人身上那些「给予骇入时」的状态各触发一遍；其中 `自动攻击程序` 造成伤害 → `BeatDown`「造成伤害时给所有敌人骇入」
→ 又给骇入 → 再触发一遍 —— **自己咬自己**，还可能弹出成串的选牌框（`程序杀毒` 每次给骇入都弹手牌 / 抽牌堆 / 弃牌堆）。
用户实测：把这些状态拿掉后**不再浮空**。

做法（两件）：

1. **运行时兜底** `Generation/RecursionGuardGen.cs` → 生成 `cs/ForgeRecursionGuard.cs`：
   Harmony 前缀打在 `Hook.AfterPowerAmountChanged` 上，`[ThreadStatic]` 记嵌套深度，
   超过 **12 层**就跳过这一次派发 + `Log.Warn("[ForgeRecursionGuard] …")`（用户就是靠这行日志验证有没有环）。
   正常嵌套 2~4 层；只在「有启用自定义状态」时生成（`Needed()`），业务代码一个字不动。
2. **校验器** `ProfileValidator.ValidateTriggerCycles`：A 的触发里给 B 叠层数、B 的又给 A（或自己给自己）
   → **警告**并写清后果（牌停在出牌位浮空 / 回合卡住）。
   ⚠ **只算「会加层数」的边**：`-B/2` 这种「回合结束层数减半」不算环（不判方向会把
   `骇入` / `狱炎` / `少女的秘密` 三条正常递减全误报 —— 实测过）。
   这个检查只覆盖「状态 ↔ 状态」；「伤害 → 给状态 → 又伤害」这类跨事件的环靠 ① 兜。

自检 +5 条（`V0.2.342：`）：环要报 / 负数衰减不误报 / 递归保护源码形状 / 没有状态不生成 / 真生成工程里有那份文件。

## 九十五、V0.3.19：试算框跟着公式走 + 初值里的固定值参数（**别再当待办查**）

用户截图：变量 `a` 的公式写成 `A+3`，右边「试算」框却还是 `0`，点试算 `= 0`。
