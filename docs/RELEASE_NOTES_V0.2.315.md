# V0.2.315 — 插件机制：`plugins\` 文件夹 + 「插件」页 + 效果种类扩展 + 随 mod 打包

你要的三件事都做了：**插件文件夹 / 编辑器识别并单开一栏 / 给 AI 的提示词与开发规范**；
扩展点先接**效果种类**（5 条生成链全接），另外三类（触发时机 / 条件 / 锻造模块）清单已认、编辑器已经列出来，生成端接线放到下一版（原因见最后）。

## 1. 放插件的地方

```
程序文件\
├─ Sts2CharForge.exe
├─ plugins\                    ← 插件放这里（每个插件一个子文件夹）
│  └─ 示例插件\
│     ├─ plugin.json
│     └─ cs\PluginDemo.cs
└─ docs\
   ├─ 插件开发规范.md           ← 完整规范（字段 / 占位符 / 打包 / 兼容约定）
   └─ 插件AI提示词.md           ← 直接发给 AI 的提示词（含文件位置定位）
```

「示例插件」默认就带着，能直接看到效果；不需要可以整份删掉。

## 2. 编辑器里怎么识别

主界面多了一个 **「插件」页**：

* 左边列出所有插件（坏掉的标 ⚠），右边显示：清单版本 / 作者 / 目录 / 它贡献的效果（含数值范围与字段开关）/
  触发时机·条件·锻造模块（本版标注「仅登记」）/ 自带文件与其在生成工程里的落点 / 插件自述 / **额外内容页（Markdown）**；
* 按钮：**重新加载插件**（改完清单不用重启）、**打开插件文件夹**；
* 插件贡献的效果种类会**直接出现在「效果种类」下拉里**（卡牌 / 遗物 / 药水 / 自定义状态 / 锻造图都有）。

## 3. 插件效果怎么变成代码

清单里写一段 C# 模板，生成时替换占位符：

```json
{ "kind": "PluginHealAndBlock", "display": "插件示例：回复生命并给等量格挡",
  "unit": "点", "min": 0, "max": 99,
  "emit": "await CreatureCmd.Heal({self}, {amount});\nawait CreatureCmd.GainBlock({self}, {amount}, ValueProp.Move, null);" }
```

可用占位符：`{amount}` `{self}` `{player}` `{foe}` `{choice}` `{cardSelf}` `{power}` `{card}`。
每条链会自动填好「自己 / 玩家 / 指定敌人 / choiceContext」，所以同一份模板在卡牌、遗物、药水、状态、锻造图上都能生成对的目标表达式。

上面那条效果在卡牌上生成出来是：

```csharp
await CreatureCmd.Heal(base.Owner.Creature, 5m);
await CreatureCmd.GainBlock(base.Owner.Creature, 5m, ValueProp.Move, null);
```

## 4. 随 mod 打包（互不干扰）

* 插件自带的 `csFiles` → 生成工程 `cs\Plugins\<插件 id>\`，**和模组一起编译进 dll**；
* `assetFiles` → 生成工程 `plugin_assets\<插件 id>\`，随工程一起打包；
* 插件效果和自带效果混在同一个效果列表里互不影响（需要额外类就写进 `csFiles`，模板里直接调用）。

## 5. 兼容性（编辑器升级不失效）

插件**不加载 DLL、不反射编辑器类型**：只读 JSON 清单里的字符串 + 代码模板。
清单结构变了才升 `apiVersion`（当前 `"1"`）；老清单在新编辑器里照旧能读。
写错的插件只影响它自己（「插件」页标 ⚠ + 写明原因），编辑器照常启动。
