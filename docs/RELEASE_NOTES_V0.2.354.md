# V0.2.354 — 修 CS0136：锻造图生成的 `__fgXXXXXX` 局部变量在同一段里声明两次

你贴的（别人的工程 `Lihuazou`）：

```
Powers\ZouPower16.cs(30,21): error CS0136: 无法在此范围中声明名为 '__fg5ed68d' 的局部变量…
Powers\ZouPower16.cs(31,21): error CS0136: … '__fg8970c3' …
```

## 原因（代码里能直接看出来）

锻造图里每个模块的代码都会生成一个局部变量（`decimal __fgXXXXXX = …`，XXXXXX = 模块 Id 的哈希）。
为了避免重复声明，`ForgeGraphGen.ValueVar` 会记「这个模块的变量是在**哪个作用域**里声明的」：

* 声明处**罩得住**当前作用域 → 直接复用那个变量（不重复声明）；
* 罩不住（例如声明落在「真支」、现在在「假支」）→ 在当前这一段**重新声明一次**（兄弟块同名是合法的）。

问题出在第二种的**另一个方向**：如果那个变量先是在**更深的块里**声明（比如 `if` 里面），
后来又要在**外层**用它，代码就重新在外层声明了一个**同名**变量 —— 而 C# 的 **CS0136** 明确禁止
「外层块里出现和内层同名的局部变量」，**即使先内后外**。于是就报了你看到的这两条。

## 改法

`ValueVar` 在「重新声明」这一步先问一句 `GenState.UniqueDeclName(name)`：

* 如果同名变量**已经在当前作用域的里面**声明过 → 换名（`__fg5ed68d_2` / `_3`…）；
* 如果只是**兄弟分支**之间撞名 → 保持原名（这种情况 C# 合法，老工程生成文本一个字都不变）。

所以这个改动**不可能改变任何原本能编译的工程的生成文本**：换名只在「原本会 CS0136」的场合发生。
