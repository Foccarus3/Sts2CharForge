# V0.2.252 — 「升级手上的状态牌」为什么不生效：本体状态牌**天生不能升级**

## 你报的

> 自定义状态为升级手上的状态牌不生效

## 查证（不是生成端漏了，是本体规则）

* 生成端「升级卡牌」本来就带 `c.IsUpgradable` 过滤 —— 和本体「武装 Armaments」一模一样
  （`Armaments.cs:28`：`PileType.Hand.GetPile(...).Cards.Where(c => c.IsUpgradable)`）：
  不能升级的牌**根本不会被挑中**，所以效果看起来「什么都没做」；
* 而**本体状态牌 / 诅咒牌是 `MaxUpgradeLevel => 0`**：
  `Dazed.cs:8` 就是 `public override int MaxUpgradeLevel => 0;`，本体「粘液 / 伤口 / 灼伤 / 晕眩」全部如此。
  `CardCmd.Upgrade` 第一句就是 `if (!card.IsUpgradable) continue;` —— 升级它们**一件都不会做**；
* 工具给**你自建的状态牌**也照抄了这条（`CSharpCodeGen` 里状态牌写死 `MaxUpgradeLevel => 0`），
  除非你在「诅咒 / 先古卡」页勾了「**可被无限升级**」（V0.2.223 就是这个原因加的开关）。

也就是说：这条效果**逻辑是对的**，只是它挑不到能升级的牌 —— 以前工具对此**一声不吭**。

## 这一版做了什么

校验器现在会对「升级卡牌 / 升级卡牌（全局）」这条效果**直接说出来**：

> 范围是**状态牌**：本体这一档**天生不能升级**（状态 / 诅咒牌生成时写死 `MaxUpgradeLevel => 0`，
> 本体「粘液 / 伤口 / 灼伤 / 晕眩」全都一样），生成端会像本体「武装」那样跳过不可升级的牌 ——
> 所以这条效果对它们**一件都不会做**（不会报错，只是没反应）。
> 想让**你自己建的状态牌**能局内升级：到「诅咒 / 先古卡」页勾「可被无限升级」，
> 并在它的效果里填好「升级增量」（不填的话即使升级了数值也不变）。

（范围选「诅咒牌」，或者「只升级这张卡」点名了某张状态 / 诅咒牌时，同样会提示。）

## 你要怎么让它生效

1. 打开「诅咒 / 先古卡 / 状态」页，选中那张**你自己的状态牌**；
2. 勾上「**可被无限升级（每次升级数值再涨一次）**」—— 生成出来就变成
   `public override int MaxUpgradeLevel => int.MaxValue;`（本体这才允许升级它）；
3. 在它的效果里填「**升级增量**」（例：格挡 3 → 升级后 +2）；
4. 重新生成。

⚠ 本体那几张状态牌（伤口 / 灼伤 / 晕眩 / 粘液…）**没办法**被升级 —— 这是本体写死的，
任何工具都改不了；如果你的状态是「往手上塞本体状态牌然后升它们」，那条路走不通。
