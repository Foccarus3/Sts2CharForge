# V0.2.220 —— 抽牌 / 拿牌时也能「为抽到的牌加永久 / 临时关键词」了

> 来源：用户要求「在抽牌/拿牌等效果下额外填加一条『为抽到的牌添加永久/临时关键词』的选项」。

## 1. 加在哪几档

| 效果 | 说明 |
| --- | --- |
| **抽牌** | 抽到的这几张牌都带上关键词 |
| **刮削**（抽 N 张 → 对其中符合条件的牌动手） | 抽到、并且这一条效果挑中的那几张带上关键词（在「丢弃 / 消耗 / 升级」之前加） |
| **从抽牌堆 / 弃牌堆 / 消耗牌堆拿牌到手牌** | 拿到手的那几张带上（「自己选」和「全部」两档都支持） |
| **用目标卡填满手牌** | 填进来的那几张带上 |

其它效果**不显示这一栏**（生成端也不读它）—— 界面显示的栏位一定被用到，藏起来的
一定没被用到（这条由自检的机械测量逐条钉住，67 种效果 × 三条链）。

## 2. 界面上长什么样

「效果」编辑区里多两行（紧跟在「给予关键词 / 临时关键词」下面）：

- **为抽到的牌加关键词**：下拉，候选 = 本体那 7 个关键词 + 你在「自定义关键词」页造的那些，
  第一项是「（不加关键词）」= 默认档；
- **抽到的牌的关键词只是临时的**：勾上 = 只这一回合（保留 / 奇巧走本体的单回合标记，
  其它关键词含自定义的在回合结束时被摘掉）。

列表里那一行也会写出来：`抽牌 2 ｜ 抽到的牌带上「保留」（临时）`。

## 3. 生成出来是什么

没选关键词 → **就是原来那一句**（`await CardPileCmd.Draw(choiceContext, N, base.Owner);`，
老存档生成文本逐字不变）。选了才变成：

```csharp
// CET:DrawnKeyword=Retain CET:DrawnKeywordTemp=0
IEnumerable<CardModel> __drawnBatch = await CardPileCmd.Draw(choiceContext, base.DynamicVars.Cards.BaseValue, base.Owner);
// 给这一条效果抽到 / 拿到手的牌加上永久关键词「保留」
foreach (CardModel __drawnKw in __drawnBatch) {
    __drawnKw.AddKeyword(CardKeyword.Retain);   // 本体 API：卡面文字会立刻刷新
}
```

- 作用的是**这一条效果真的抽到 / 拿到手的那几张**（用 `CardPileCmd.Draw` 的返回值 / 选牌结果），
  不是整个手牌；
- 临时档：保留 → `GiveSingleTurnRetain()`、奇巧 → `GiveSingleTurnSly()`，其它关键词（含自定义）
  挂生成的临时关键词 Power，回合结束自动摘掉；
- 自定义关键词走同一套（`AddGivenCustomKeyword` + 卡面 / 悬停补丁），所以
  「用了它就会生成那个注册表」这两处判据也一起算上（`UsesGivenCustomKeyword` / `UsesTempKeywordPower`）；
- 锻造图里也能用（【效果】模块就是同一份效果编辑器）：图上的抽牌 / 拿牌照旧套「生效次数 / 概率」，
  只是多出加关键词那一段。

## 4. 不会静默失效的两条

- 「抽牌」勾了**下回合生效**再配关键词 → 牌是下回合开始时由本体 `DrawCardsNextTurnPower` 抽的，
  那一刻不在这一条效果的代码里 → 校验器**明确警告**「这一项不会生效」；
- 把关键词配到**不抽牌也不拿牌**的效果上（手改 JSON / 换了效果种类没清干净）→ 校验器
  **警告**「这一项会被忽略」，并指路「改用单独一条『给予卡牌关键词』」。

## 5. 回读（从工程恢复）

生成端在那条效果自己的识别行前面写一行
`// CET:DrawnKeyword=<本体枚举名 或 自定义关键词的键> CET:DrawnKeywordTemp=0/1`，回读时由紧跟着的
那条效果认领；加关键词那几行（`foreach (CardModel __drawnKw in …)`）整段跳过，不会被误认成
「又一条给予关键词」。`0`（不加）时一个字符都不写。
