# V0.2.83 更新说明

> 这一版就一件事：遗物触发时机多了一条「**战斗结束时（房间结算之前）**」。

## 新触发时机：战斗结束时（房间结算之前）

遗物页的「触发时机」下拉里多了一条，对应的本体钩子是 `AfterCombatEnd(CombatRoom room)`。
它和原来那条「战斗胜利时」**不是同一个时间点**——本体的执行顺序是：

```
CombatManager.EndCombatInternal：
  Hook.AfterCombatEnd        ← 这一条（战斗结束时）
  room.OnCombatEnded()
  Hook.AfterCombatVictory    ← 「战斗胜利时」
  发奖励 / 写存档 / 结算
```

所以：

- 「**必须在结算之前做完**」的事（清掉本场留下的临时状态、结算前补一笔金币等）挂这一条；
- 「要和结算 / 奖励一起做」的事挂「战斗胜利时」——「获得卡牌奖励」那条路径就在那里（`room.AddExtraReward`）。

> ⚠ 两点必须说清楚：
> 1. **和「战斗胜利时」一样，它只在打赢那条路上触发。** 打输走的是本体的 `ProcessPendingLoss`
>    （那里只发一个 `CombatEnded` 事件、**不调任何模型钩子**），所以「无论输赢都触发」在遗物上做不到。
>    如果你要的是那个，得再加一条补丁（在败北路径上派发我们自己的钩子）——告诉我一声就做。
> 2. 它**没有 `choiceContext`**：「召唤伙伴」这类需要上下文的效果会被配置检查拦住并说明
>    （和「战斗胜利时 / 获得金币时」同一档）。

**回读**：这个时机和「每场战斗只触发一次」的清理钩子用的是**同一个** `AfterCombatEnd`，
所以生成时会写一句 `// 触发时机：战斗结束时（房间结算之前）`；回读先按钩子签名认、
认不出来时按这句注释兜底 —— 探针实测：生成 → 回读的触发时机是 `CombatEnd`，
效果条数一致，没认出来的语句为 0。
