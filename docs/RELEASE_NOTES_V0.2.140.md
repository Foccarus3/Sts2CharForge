## 一、序号列改成「每 5 个一块 + 空槽灰序号」（三页共用同一份实现）

- 1 张卡 → 列 1~5 行（2~5 是空槽）；6 张 → 1~10 行；11 张 → 1~15 行；从 6 张删回 5 张 → 回到 5 行，**一个空槽都不剩**。
- 空槽行：序号**灰色**（`#AAAAAA`，真卡是 `#1F4E79` 加粗）、没有卡名、没有悬停说明、**选不中**（点它右侧详情保持原来那张卡不塌）、**不进「全选」**、**可以当拖放落点**（拖到空槽 = 放到末尾）。
- 序号只活在界面：自动类名照旧按**本页位置号**拼 `Card<n>` / `Curse<n>` / `Ancient<n>`（手填过的类名一个字符都不动）；存档（`Profile.Cards` / `Curses` / `AncientCards`）里**没有**任何占位项，生成出来的产物里也搜不到「空槽」痕迹（真生成 112 个文件核过）。
- 三页共用新增的一份 `SlotRowMirror<T>`（没有复制三份），遗物页 / 药水页**一行没动**。

## 五、另外：你报的「填负值的力量不生效」已定位到真因（下一版修）

真因**不在生成端**，在**「从工程恢复存档」的回读**：同一个「升级增量」在产物里写了三处（变量构造参数、打出时那个三元式、`OnUpgrade` 里的 `UpgradeValueBy`），回读时**前两处已算出增量，第三处又加了一次** —— 你那张「闪耀登场」的升级增量因此从 1 变成 2，于是你把数值公式填成 `-2` 之后生成出来是：

```
Apply<StrengthPower>(..., (base.IsUpgraded ? 0m : -2m), ...)   ← 升级后 = -2 + 2 = 0 层
```

**升级过的那张打出去 = 施加 0 层 = 什么都没发生**（没升级的那张才是 -2）。

**现在就能绕过**：把那张牌的「升级增量」清成 0（或 1）再生成，升级后就是 -2（或 -1）。下一版（V0.2.141）修回读的重复累加，并加一条警告「升级增量把负值抵成了 0：升级后打出去没有任何效果」。
