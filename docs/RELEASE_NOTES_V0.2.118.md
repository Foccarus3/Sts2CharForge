# V0.2.118 更新说明

> 这批需求里的第 ⑪ 条（最后一项）：**「只对哪类牌生效」增加选择范围**。

## 一、从 4 档扩到「任意 / 攻击 / 技能 / 能力 / 诅咒 / 状态 + 你自己配的关键词组与组」

「自定义状态」的触发时机「**打出一张牌后**」下面那一栏原来只有 **任意 / 攻击 / 技能 / 能力**，现在多了：

| 新档 | 生成出来的判据 |
|---|---|
| **诅咒** | `play.Card.Rarity == CardRarity.Curse` |
| **状态** | `play.Card.Type == CardType.Status \|\| play.Card.Rarity == CardRarity.Status` |
| **关键词：XXX** | 你给的「自定义关键词」那一组牌（生成时展开成这些牌的 `ModelId` 比较） |
| **组：XXX** | 你在「自定义参数 / 组」页建的**组**（同样展开成显式判据） |

- 候选取自**卡牌那边同一份「范围界定」选项表**，所以「自定义关键词 / 组」加一个 / 改个名字，
  这里跟着变（共用一份登记表，不会漂移）；
- 新的几档判据直接复用卡牌那边那套 `ScopeCondForFilter`（所以「关键词组 / 组里有哪些牌」的算法只有一份）；
- **老的四档生成文本一个字都不变**（`if (cardPlay.Card.Type == CardType.Attack) {`，老存档红线照旧）；
- 旧的筛选值 `Any` 保留（老存档 / 老工程回读不受影响）。

## 二、顺手修掉一个「悄悄丢配置」的老坑

一个状态上可以放**多条**「打出一张牌后」（攻击一条、技能一条，或者按组筛的各一条），
它们生成在**同一个** `AfterCardPlayed` 方法里 —— 而回读以前是「一个方法 = 一条时机」，
于是**只有第一条能认回来，后面几条连同它们的效果一起悄悄丢掉**（界面上还不会提示）。

这一版把那个方法体**按筛选判据切成几段**，每段各自成一条触发时机、各自解析自己的效果：

```
recovered 筛选 = Curse(1条效果) / Status(1条效果) / Group:Grp1(1条效果) / Attack(1条效果)
```

- 段首识别两种写法：老的 `if (cardPlay.Card.Type == CardType.X) {`，和新的 `// CET:CardFilter=X` + 紧跟的 `if`；
- 方法开头那几行（`if (cardPlay.Player != base.Owner.Player) return;` 之类）不会再多出一条空时机；
- **只有一段时走原来的单条路径** —— 老工程回读行为完全不变。

## 三、校验

- 选了「关键词组 / 自定义组」但**那一组里一张牌都没有** → **错误**拦住（生成出来会是 `if (false)`，
  这条时机永远不会触发）：提示里说清去哪把牌勾进这个组，或者把筛选改回「任意 / 攻击 / 技能 / 能力」；
- 新的筛选档会写一行 `// CET:CardFilter=<筛选值>` 供回读（判据是展开出来的，从代码反推不回来）。
