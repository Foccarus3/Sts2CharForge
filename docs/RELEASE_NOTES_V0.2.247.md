# V0.2.247 — 两条新条件：「上一张打出的牌带有某关键词」/「上一张打出的牌是某范围（可按组）」

## 用户要求

> 条件增加「上一张打出的牌带有某关键词」，「上一张打出的牌是某范围」，范围内可以填组。

## 加了什么

「条件」下拉里多了两条（卡牌 / 遗物 / 药水 / 自定义状态四条链都有；锻造图的【条件】模块里也有）：

| 条件 | 底下多出来的下拉 | 判据（生成出来的样子） |
|---|---|---|
| **上一张打出的牌带有某关键词** | 「关键词」：本体那 7 个（消耗 / 虚无 / 固有 / 保留 / 不能被打出 / 奇巧 / 永恒） | `History.CardPlaysFinished.LastOrDefault(e => e.CardPlay.Player == 玩家)?.CardPlay.Card.Keywords.Contains(CardKeyword.XXX) == true` |
| **上一张打出的牌是某范围（可按组）** | 「牌的范围」：不限 / 攻击 / 技能 / 能力 / 诅咒 / 状态 / 任务 / **自定义关键词那一组** / **每个组** | `…?.CardPlay.Card.Type == CardType.Attack`、`…?.CardPlay.Card.Id == ModelDb.Card<某卡>().Id \|\| …`（组会展开成「组里每张牌各一条」） |

* 数据源和本体「历史课 HistoryCourse」用的是同一份：`CombatManager.Instance.History.CardPlaysFinished`，
  按**你自己**（`e.CardPlay.Player == 玩家`）过滤，**不限回合** —— 就是「最后一张打出的牌」。
  本场还没打过牌时是 `null`，`?.` 短路后判据为假 ✓。
* 「范围」和「范围界定 / 刮削条件」**共用同一份候选表**（`EffectCatalog.SpawnFiltersFor`），
  所以「组」和「自定义关键词：××（带这个关键词的那一组牌）」都在里面 —— 你要的「范围内可以填组」就是这个。
* 想判**自定义关键词**：用第二条 + 选「自定义关键词：××」那一项（本体 `CardKeyword` 是封闭枚举，
  第一条只列本体那 7 个；下拉的说明里也写了这一句）。

## 界面上在哪

「效果」→那条效果下面的「条件选项」方块里，选了这两条之一就会多出对应那一行：

* 卡牌模板：条件 / 数值 N / 状态 / 指向对象 / **关键词** / **牌的范围**（新一行，按需出现）
* 遗物 / 药水 / 自定义状态模板：同上
* 锻造页【条件】模块：字段里多了「关键词（上一张打出的牌带有某关键词用）」「范围（上一张打出的牌是某范围用）」

## 不静默

* 选了这一条却没选关键词 → 校验器报**错误**（`还没选关键词`），不会生成一个恒假条件；
* 范围**留空** → 校验器给**提示**：「留空 = 任意牌，这条条件等于没判」；
* 范围选了组、但那个组里**一张牌都没勾** → 校验器**警告**：「判据永远不成立，这条效果等于永远不生效」；
* 从工程回读（「从工程恢复」）也认这两条：关键词直接读回来；范围读回攻击/技能/能力/诅咒/状态/任务，
  组 / 关键词组则拿生成出来的那串卡去和存档里的组比对（完全一致才认回来，认不出就留空让你重选）。

## 一个实现细节（避免 CS0128）

判据里**不声明局部变量**（没有 `is { } __lastCard` 那种写法）：同一张牌的两条效果都带这个条件时，
会在同一个 `OnPlay` 里出现两个同名局部变量 → `CS0128`。所以改成把「取上一张牌」那一长串直接内联进判据
（`?.` 会短路整条成员链）。真编译自检里专门塞了**同一张卡的 3 条**这种效果，`dotnet build` **0 个错误**。
