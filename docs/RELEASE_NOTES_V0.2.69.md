# V0.2.69 更新说明

## 修掉「全体敌人 + 命中次数」被当成「每个敌人各打 N 下」的 bug（你报的）

**现象**：锻造图里【造成伤害】+【对象：**全体敌人**】，「命中次数」填 4 ——
生成出来的其实是**每个敌人各挨 4 下**（`foreach (foe) Attack(…).WithHitCount(4)`），
而你要的是「**一次打全体、命中 4 次**」。

**根因**：【对象】模块解出来的目标一直只有「逐个动手」一种形态（列表 + `foreach`），
所以【全体敌人】被当成了「列表里每一个都单独打一次」。而本体**有群体版本的一次性命令**
`DamageCmd.Attack(…).TargetingAllOpponents(base.CombatState)` —— 只有它能表达「一次打全体」。

**修法**：给目标模型加一个「是逐个动手、还是一次动全体」的标记，
【全体敌人】标成**一次动全体**，【造成伤害】走 `TargetingAllOpponents` + `WithHitCount(N)`；
其余（【随机敌人】/【指定敌人】/【全体友方】…）仍然是逐个动手，一个字没变。

| 对象 | 命中次数 4 现在生成的是 | 游戏里的表现 |
|---|---|---|
| 全体敌人 | `Attack(…).TargetingAllOpponents(base.CombatState).WithHitCount(4)` | **一次打全体，每个敌人挨 4 下** ← 你要的 |
| 随机敌人 | `foreach (foe) Attack(…).Targeting(foe).WithHitCount(4)` | 随机挑中的那个挨 4 下（本体语义） |
| 指定敌人 | 同上 | 选中的目标挨 4 下 |
| 全体敌人 + 命中 1 | `Attack(…).TargetingAllOpponents(…)`（**不写** `WithHitCount`） | 一下打全体（和以前一致） |

> 顺带说明：**卡牌页**那栏（叫「对群数/命中次数」）在「全体敌人」这一档本来就被忽略
> （生成的就是一次打全体），所以这个 bug 只影响**锻造图**里的「命中次数」。

## 修掉一个会把玩家扣到死的无限循环（你报的「会循环到死」）

**现象**：自定义状态配「自己受到伤害后」或「自己失去生命时」，效果是「失去 1 点生命」
→ 一进战斗就无限扣血，直接扣到死。

**根因**：本体的伤害管线**每打一下**都会调两个钩子 ——
`Hook.AfterDamageReceived`（= 「自己受到伤害后」）和 `Hook.AfterCurrentHpChanged`（= 「自己失去生命时」）。
而状态自己的「失去生命」效果走的正是 `CreatureCmd.Damage`，于是：

```
敌人打你 1 下
  → AfterDamageReceived 触发状态
    → 状态「失去 1 点生命」（CreatureCmd.Damage）
      → 这 1 点生命**又是一次受到伤害** → AfterDamageReceived 又触发 → …
```

**为什么本体自己不踩这个坑**：本体那些「生命少了才触发」的状态（肉骨头 MeatOnTheBone /
亡灵契约师的 NecroMasteryPower / 原体黏土 SelfFormingClay）效果里**都没有再造成伤害 / 失去生命**，
循环起不来 —— 这是「你能配出本体配不出的组合」带来的新问题。

**修法**：给这类状态生成一道**重入闸**（只在「受伤/掉血触发」+「效果会改生命」这个组合上开）：

```csharp
private bool __inHpLoss;   // 闸：本状态自己的效果正在跑

public override async Task AfterDamageReceived(…) {
    if (target != base.Owner) return;
    if (result.UnblockedDamage <= 0) return;
    if (__inHpLoss) return;        // ← 本状态自己造成的这次掉血，不再触发自己
    __inHpLoss = true;
    try { …你配的效果… }
    finally { __inHpLoss = false; }
}
```

- 用 `try/finally` 而不是「跑完再置 false」：效果里可能 `await` 到一半被打断（战斗结束 / 取消），
  那种情况也必须把闸放掉，否则这只状态之后**再也不响应受伤**（比循环更难查）。
- **效果照旧生成**（不是把那条效果删掉），真实的下一次受伤照样触发；
- 「自己受到伤害后」和「自己失去生命时」两条都有闸；
- **没这个组合的状态一个字节都没变**（自检里专门有一条对照：受伤后只抽牌 → 不带闸）。

## 临时增益也能填负数了：让敌人「失去 5 点临时力量」

以前「临时增益」的数值被限死在 0~99，填负数会被校验拦下，理由写的是
「它的机制是『本回合 +X、回合结束撤掉』，负数含义会变样」。**那个理由是错的** ——
生成端本来就是「到点撤 `-base.Amount`」，负数档正好把扣掉的层数加回来。

现在：

- 数值范围改成 **-99 ~ 99**，效果种类名字改成「**临时增益 / 临时减益（本回合 ±X，到点还原）**」；
- **填负数 = 让目标先失去 |N| 层，到点再加回来**。例：想让敌人「失去 5 点临时力量」
  → 效果「临时增益 / 临时减益」+ 数值 `-5` + 「增益 / 减益」选力量 + 作用对象选敌人
  + 「什么时候撤」选「下回合开始时才撤掉」= 这一回合和敌人的回合都少 5 点力量，你下回合开始时加回来；
- 负数档的生成代码和正数档**不一样**（所以才需要各自一个类）：
  - 正数档：`PowerCmd.Apply<状态>(…)` 直接加层；
  - 负数档：`GetPower<状态>()` + `PowerCmd.ModifyAmount(…, -N)` **扣层** —— 和全项目
    「负数 = 扣掉身上已有的层数」的约定一致（本体 `PowerCmd.Apply` 收到负数会凭空挂一个负层数状态，
    那是不能用的）；
  - 到点还原**两个方向共用一句 `-base.Amount`**：正数档撤成负数、负数档撤成正数，都对。
- 类名带上正负标记，回读认得回来：`…ForgeTemp力量Power`（正）/ `…ForgeTemp力量PowerAbs`（负）/
  各加 `NextTurn` 尾巴（下回合开始时才撤）。
- ⚠ 顺带修掉一个**会串档的真 bug**：去重键原来只有「状态 + 什么时候撤」，没带正负号 ——
  同一只状态同时有 `+5` 和 `-5` 两种写法时会**合成一个类**，后写的那份覆盖前一份，
  于是两张牌里有一张行为是错的。现在键里带上正负号。
- 卡面与状态栏文案按正负分开写：负数档印「本回合内失去 5 层力量（下回合开始时加回来）」，
  不再印「获得 -5 层」；状态栏说明印「本回合内力量 -5，下回合开始时加回来。」
- 校验器那条**错误**降级成**提示**，并说清「先失去 N 层、到点加回来」以及
  和「施加增益/减益填负数」（**永久**扣、不还原）的区别。

## 临时增益多了「下回合开始时才撤」这一档

以前「临时增益（本回合 +X，回合结束消失）」只有一种撤法：**这一回合结束就撤掉**。
现在多了一档，效果编辑器里多一行「**临时增益什么时候撤**」（只有选到「临时增益」才显示）：

| 这一档 | 什么时候撤 | 例 |
|---|---|---|
| 本回合结束时撤掉（默认） | 你的这一回合结束 | 「本回合 +5 力量」——打完这张牌这个回合有效，回合结束就没了 |
| **下回合开始时才撤掉** | **撑过你的这一回合 + 敌人的回合，到你的下一个回合开始时才撤** | 「获得临时 5 点力量 → 下一回合开始时失去 5 点力量」 |

也就是你要的那种「下回合失去」：这一回合加了 5 点，敌人的回合里还在，等你下回合一开始就掉回去。

实现和本体的写法一致（两端都挂在同一个临时 Power 上，只是换了个钩子）：

- 默认档：`AfterSideTurnEnd`（这一回合结束）→ 撤 `-base.Amount`、自己消失；
- 新档：`AfterPlayerTurnStart`（你的下一回合开始，本体在 `CombatManager` 里是「抽完牌之后」那一步）
  → 同样撤 `-base.Amount`、自己消失。

**同一只状态的两档会生成两个类**（`<角色>ForgeTemp<状态>Power` 和 `<角色>ForgeTemp<状态>PowerNextTurn`），
所以同一张牌上可以同时用两档、同一条状态互不影响。回读（从工程反推存档）按类名尾巴上的
`NextTurn` 认出是哪一档。

> 顺带修掉一处会骗人的文案：状态栏 / 悬停提示里那句说明以前**写死**成「回合结束时消失」，
> 「下回合开始才撤」那一档挂上去会显示错。现在两档各说各的
> （新档写「撑过这一回合和敌人的回合，下回合开始时消失。」）。

## 自定义状态的触发时机：补上「清除状态 / 清除所有减益 / 牺牲伙伴」

以前往「自定义状态」的触发时机里放这三个效果，会被校验拦下，报的是「这种效果需要卡牌上下文（选牌 / 结束回合），
状态触发器里用不了」。**那句话是错的**（用的是同一句模板文案）：

| 效果 | 以前被拦的理由 | 真实情况 |
|---|---|---|
| 清除目标的指定状态 | 「需要卡牌上下文」 | 本体只写 `PowerModel? p = foe.GetPower<T>(); if (p is not null) await PowerCmd.Remove(p);` —— **一个 choiceContext 都不传**，只要「选哪个单位」，而状态那条链早就有目标解析了 |
| 清除目标的所有减益 | 「需要卡牌上下文」 | 同上：`foreach (p in foe.Powers.ToList()) if (p.TypeForCurrentAmount == Debuff) await PowerCmd.Remove(p);` |
| 牺牲伙伴换收益 | 「需要卡牌上下文」 | 三档收益里**只有两处**用到：收益 = 造成伤害时 `.FromCard(this, cardPlay)` + `.Targeting(cardPlay.Target)`；收益 = 获得格挡时 `GainBlock(..., cardPlay)`。「获得增益 / 减益」那一档本来就只挂状态、不碰 cardPlay |

这一版把它们都补进了 `CustomPowerGen.EmitEffect`，**不是给你某一张卡打的补丁**，而是通用能力：

- **清除指定状态 / 清除所有减益**：生成原文本体那两行，目标是「自己 / 全体敌人 / 随机敌人 / 可打的第一个敌人」
  （和「施加状态」「击晕」共用同一套目标解析）。
- **牺牲伙伴**：先按本体那套查宠物（`XxxCmd.Get(base.Owner.Player)`），用 `if (__pet is not null)` 包住
  （伙伴不在场就整条静默跳过，和卡牌一致）；三档收益都能用：
  - 获得增益 / 减益 —— 原样可用（只挂状态）；
  - 获得格挡 —— 改为 `CreatureCmd.GainBlock(base.Owner, gain, …, null)`（状态里 `base.Owner` 本身就是 Creature，
    而且没有 cardPlay 可当来源）；
  - 造成伤害 —— 只「选目标 + 用扩展方法把攻击者换成宠物」：`DamageCmd.Attack(dmg).Targeting(foe).FromPetAttacker(pet)`。
    为什么不能像卡牌那样写 `.FromCard(...)`：那个方法的第一个形参是 `CardModel`，传 Creature 直接 CS1503；
    也不能用 `.FromMonster(pet.Monster)`（它内部顺手 TargetingAllOpponents，之后再 Targeting 会抛
    「Targets already set」）。
- **校验文案按真实原因分档**：真需要「打出这张牌」上下文的（复制 / 重放 / 回合结束自动打出）说「要的是打出这张牌那一刻的上下文」；
  其余还没实现的种类说「生成端还没给自定义状态那条链实现这个效果种类」。不再一律甩「需要卡牌上下文」。

> ⚠ 顺带修掉一个会漏生成的坑：「有伙伴攻击效果就要生成 `cs/PetAttackExtensions.cs`」那份判断以前**只看卡牌** ——
> 状态里「牺牲伙伴 + 收益 = 伤害」也走 `.FromPetAttacker(...)`，漏了就会生成一个引用不存在扩展方法的
> 状态源码 → CS1061、整个模组编译不过。现在两个来源都看。

## 这一版还做了什么：锻造页的「积木」视图从「只能看」变成**能拖的编辑器**

上一版把节点图排成了一摞积木（只读观感版）。这一版把它做成了像 Scratch 那样的编辑器：

- 标签从「积木（只读）」改成「积木（可拖）」；
- **拖块换位置**：把一块拖到别的块中间 = 放进它里面（【if】/【对象】那种 C 形块）；
  拖到上/下边缘 = 插到它前面 / 后面。拖的时候有半透明预览块，目标位置会变色提示
  （橙色 = 插在旁边，绿色 = 放进里面）；
- **✚ 加一块**：点某一块右边的 ✚ 弹一个小菜单挑种类，它会插在那一块后面（或里面）；
- **✕ 删一块**：删掉它和它的内容；同一支里后面的块会接回来，不留洞；
- 空布上直接点调色板也能从零搭：会自动补一个【触发时机】当起点；
- 颜色沿用节点图那套：帽子块（触发时机）橙色、C 形块蓝色、报告块（数值 / 条件）淡蓝圆角、
  堆叠块浅灰 + 左边一条色条；缩进 = 在谁里面，「是 / 否」两支有分支标题和「（if 到这里结束）」收口。

## 关键点：改完立刻写回节点图

积木视图和节点图是**同一块布的两种看法**（存档格式没变，还是原来那张节点图）：

- 打开积木视图时，把节点图读成一棵「执行树」；
- 拖 / 加 / 删只改这棵树；
- 松手就把这棵树**写回图的连线**（节点对象还是同一批，字段、位置都不动）；
- 所以切回「节点图」看到的就是改完的样子，生成器读到的也是改完的图。

「写回」还保证了一件事：**生成端走出来的执行顺序 = 积木视图从上往下读的顺序**。
自检里专门有一条是这么比的（拿一张带 if / 对象 / 数值槽的图，读一遍写回去，
再照着生成端的读法走一遍，前后顺序必须一模一样）。

## 顺手修掉的两个真问题

**① 视图切换的单选按钮被挤出窗口**（用户反馈「点右上角视图没反应」）：
那一行原来是「先声明左边两个分页 + 一段很长的说明文字、最后才声明右边的视图框」，
`DockPanel` 从右往左排，轮到视图框时已经没宽度了 —— 界面上只剩「视图：」三个字，
两个单选按钮被挤到窗口外，所以「没反应」。
现在把视图框**放到这一行最前面**声明，并把那段说明缩短成一行。
自检里加了一条断言量它的**真实宽度**（节点图 52px / 积木 85px），
另有 `--forgeshot` 把整页渲染成图给肉眼确认（`docs/锻造页_视图切换.png`）。

**② 积木编辑器的树和节点图之间有个坑**：**图里一个出口只能接一条线**，
所以「执行链上排在自己后面的那些块」必须**一个一个嵌着**接（第一块接在上一块上，
后面的接在前一块的出口 0 上），不能并排躺在同一个出口上 ——
并排的话第二块起会被生成端当成「重复出口」丢掉（表现就是「加了块但游戏里不执行」）。
这一版把读写两边都对齐到这条规则上了。

## 另加一栏「数值公式」（你要求的）

「数值」那一栏只能填一个**死的数字**，而你要的是「打出这张牌那一刻现算」——
比如「造成自己最大生命 ×3 点伤害」「给目标上等于它易伤层数的中毒」。
所以「数值」下面新加了一栏「**数值公式**」：

- **留空 = 用上面那个固定数字**，老存档生成的代码**一个字符都不变**；
- 写了公式 = 打出这张牌时现算，算出来的结果**取代**那个数字；
- 写法沿用锻造页【数值】模块那一套（`M*3`、`max(1, N/2)`、`X`、`Y`、`+ - * / % ( )`、
  `min/max/floor/ceil/round/abs`，最前面可以写 `=`）。`X` = 打出这张牌那一刻的当前能量，
  `Y` = 当前额外资源量，其它字母是「自定义参数 / 组」页里定义的参数。

**只有这 5 种效果能写**（它们的数字是打出时才读的）：
造成伤害 / 获得格挡 / 失去生命 / 回复生命 / 施加增益减益。
其它种类（抽几张 / 生成几张 / 消耗几张）的数字必须**生成时就定下来**
（要提前分配卡面变量、算好选牌上限），所以那些种类上这一栏**根本不出现**。

**这一版只做在卡牌上**（含挂在「卡牌时机」钩子上的那几条 —— 被消耗 / 被丢弃 / 被保留 / 被变化…都能用公式）。
遗物 / 药水 / 自定义状态的触发时机、诅咒牌上填了会**报错拦住**并说清原因
（那几条链没有「打出这张牌」这一刻的上下文：拿不到「打出的那张牌 / 玩家选中的目标」）——
拦住而不是静默忽略，是因为静默忽略最难看懂：公式填了、游戏里还是那个固定数字。

几个写明白的行为：

- 卡面上印的是**公式本身**（「造成 M*3 点伤害」），不是那个占位数字 —— 印占位数字等于骗人。
  想要具体数字就自己写「自定义描述」；
- 效果列表里显示成「数值公式 M*3」，一眼看得出它不是固定数字；
- **升级增量对公式那条不生效**（公式取代了数值），校验器会给一句提示；
- 公式算出来的**正负要到打出时才知道**，所以生成端一律按「正面效果」写
  （伤害 / 格挡 / 回复 / 施加状态都不会反向）。要「扣层数」那种语义请用「施加增益 / 减益」填负的固定数值；
- 「数值」填 0 + 写了公式**不会**被当成「0 = 这条效果不存在」丢掉（和「数值 = X」同一条规矩）。

生成出来的样子（不用自己写代码，这里只是让你知道它真的在算）：

```csharp
// ---- 「数值公式」用到的值：打出这张牌时先算一次（和锻造页【数值】模块同一套语法）----
Creature __fgSelf = base.Owner.Creature;
decimal __pM = __fgSelf?.MaxHp ?? 0;   // M= 自己的最大生命
// CET:AmountFormula=M*3
await DamageCmd.Attack((__pM * (3m))).FromCard(this, cardPlay).Targeting(cardPlay.Target)…
```

## 自定义状态可以「覆盖血条」了（像中毒那样，你要求的）

「自定义状态」页那个状态多了一栏「**覆盖血条颜色**」（六位 RRGGBB，留空 = 不覆盖）。
填了之后，身上有这个状态的生物（自己 / 敌人），**血条右端会多出一截这个颜色的条**：

- **规则和本体中毒一模一样**（几何是对着 `NHealthBar.RefreshForeground` 抄的）：
  层数 = **会失去的血量**（3 层 = 盖住右端相当于 3 点血的那一段），红条跟着缩短到覆盖段的左边，
  层数 ≥ 当前血量就是整条盖住（中毒的「致命」那一档）；和本体中毒 / 灾厄同时在场时，
  我们这一截接在它们左边、红条再缩一次；无限血条不插手。
- **为什么只要填颜色**：本体血条上红条 / 中毒 / 灾厄用的是**同一张纯白九宫格**
  （`images/ui/combat/health_bar_fill.png`），颜色全部来自节点自己的 `self_modulate`
  （红 `CC0C0C` / 中毒 `79C03C` / 灾厄是着色器渐变）—— 所以换色就是换一个数字，不用改贴图。
- 多个这种状态挂在同一只身上时**按列表顺序取第一个**（血条上只有一截位置）。
- 颜色不是六位十六进制时生成前的检查**报错拦住**（写坏了会在游戏里抛异常，所以不放过）；
  不填 = **一个文件都不多、一行补丁都不打**（老存档生成的模组一个字符都不变）。
- 补丁是**手动**打的（`RefreshForeground` 是私有方法）：本体哪天改了这个方法名，
  只丢这一截颜色、记一条警告，**不会连累整个模组加载**（带特性的 PatchAll 会）。
- 「从工程恢复存档」会把这个颜色一起认回来（状态类里有 `// CET:HpBarColor=RRGGBB` 标记）。

## 做「数值公式」时顺手修掉的两个老问题

**① 「从工程恢复存档」从来不会把自定义参数恢复回来。**
这件事在公式出现之前只是「界面上少一行」，公式出现之后是**致命的**：
回读出来的存档里公式全在、参数全没了，再点生成就是一片「M 不是一个参数」。
现在按生成代码里那一行 `decimal __pM = __fgSelf?.MaxHp ?? 0;` 把来源、取值对象、
状态类名、固定数值原样认回来（自检里专门断言了这一整条来回）。
只有参数那一栏的「备注」恢复不了 —— 它是纯给你自己看的，不参与生成、代码里没有它的位置。

**② 「施加状态 + 下回合生效」回读后状态名会变成生成的类名。**
生成的是 `<角色>ForgeDelayed<状态>Power`，回读时只把「下回合生效」认出来了，
状态名却留在了 `SevenForgeDelayedWeakPower` 这种**类名**上 ——
再生成一遍就报「增益 / 减益未选择有效的 Power」，整个存档生成不过去
（探针里「回读 → 再生成」这一步踩到的）。现在把前缀剥掉，认回真正的状态类名。

## 已知限制（说清楚，不藏着）

- 「数值公式」这一版**只做卡牌的那 5 种效果**（见上）。
  遗物 / 药水 / 自定义状态触发时机 / 诅咒牌上填公式会被报错拦住；其余效果种类那一栏根本不出现。
- 公式那条的**升级增量不生效**：公式取代了数值，卡面印的也是公式本身，升级看不出变化。
- 公式算出来的正负在生成端看不出来，所以一律按「正面效果」生成（不会反向扣层）。
- 存档里公式引用的参数如果被删掉了，生成会报错（这是故意的：宁可拦住，也不静默换成固定数字）。
- 本体的「自定义参数 → 给予能量 / 给予额外资源量」这两栏目前**只是配置项**，生成端还没有用它
  （恢复存档时也认不回来）。这是这次做公式时顺手查出来的一个老问题，没在这一版动它。
- 「覆盖血条」这一版**只做自定义状态**：本体的状态想换血条颜色请用「本体状态改写」页那一栏
  （那个是整局改色，和这里的「谁身上有谁变色」是两回事）。同一只身上多个这种状态只显示第一个。
- 【且】/【或】门的 A / B 两个入口，在图上落在【条件】模块的**出口 0** 上（从终点那头看不出是「入口」），
  积木编辑器**不接管**这条线：它会把门下面那两块条件摆出来给你看，
  但那两条线写回时**原样留着**，请在节点图里改。
- 把一整个容器（【对象】/【if】）拖进另一个容器里，复杂图上可能出现某一支没接回去
  （块本身不丢、节点不丢，只是那一条线要在节点图里补一下）。
