# V0.2.131 更新说明

> 这一版做的是《卡牌页优化.md》的**中间②（费用）**＋**右侧②（去掉重复的「升级后费用」）**＋**右侧③（去掉三个「= X」开关）**。

## 一、卡牌费用：现在能填参数/公式了

卡牌页中间那块费用区换成**两行四个框**：

| | 左框 | 右框 |
|---|---|---|
| **费用** | 能量费用 | **额外资源量费用**（新增，判断这张卡要花多少额外资源量） |
| **升级后** | **升级后费用**（新增到这里） | **升级后额外资源量费用**（新增） |

每个框里能填：

- **纯数字**：和以前**一模一样**；
- **生成期就算得出来的式子**：`1+1`、`A+3`（`A` 必须是「固定数值」来源的参数）→ 生成时折叠成那个数（本体的卡牌费用要求编译期常量，所以只能这样）；
- **`X` / `Y`**：沿用本体那套 —— 费用里的 `X` = 全部能量、`Y` = 全部额外资源量（卡面照旧显示 X / Y）；`X+1` 这种「升级后 X + 1」也照旧支持。

⚠ 费用框里写**运行时表达式**（读血量 / 状态层数那种）会被校验器**报错拦住**并说清是哪张牌哪一栏 —— 本体的 `base(cost, …)` 收不了运行时值。

**界面上的三个旧开关**（「X 费用」「额外资源量费用为 X」「升级后 X+1」）连同右侧效果编辑器里那份「升级后费用」一起撤掉了 —— 它们的能力**全部搬到上面四个框里**（逐条等价性都做了对拍：原来的勾选配置改写成式子的写法，生成结果**逐字节相同**或语义等价，没有任何一种老配置变成写不出来）。

**老存档兼容**：四个框里写纯数字 / `X` / `Y` / `X+1` 时**仍然落回原来那些老字段**，存档形状与老版本一致；生成端把新旧字段合并判断，所以**老存档的生成结果逐字节不变、而且天然幂等**（连跑两次一个字节都不变）。

顺手修掉一个老 bug：以前「升级后 X + 1」对「数值（公式）」里用的 `X` **不生效**（现在会跟着 + N 了）。

## 二、「升级后额外资源量费用」是怎么实现的

对着本体程序集查证：`CardModel` 上有 `UpgradeStarCostBy(int)`（与 `OnUpgrade()` 同可见性），所以生成的是升级时调用 `UpgradeStarCostBy(差值)`，和能量费用的 `EnergyCost.UpgradeBy(差值)` 是同一个思路。

⚠ 这一条**只在编译期验证过**（元数据 + 探针真 `dotnet build` 0 错误），**没进游戏实测** —— 你进游戏升级一张带额外资源量费用的卡看一眼就知道。

## 四、已知边界（留给你定）

1. **式子的原文不回读**：费用框里写 `A+3`，从工程恢复时拿到的是**折叠后的值**（`5`）—— 再生成一遍仍然逐字节一致，但「原样还原你写的式子」做不到（要给它加标记就会改老存档的生成文本）。要不要为这个单独加标记？
2. 「额外资源量费用」框和效果里负数「花费额外资源量」**同时存在**时，现在只给**提示**（以框为准决定费用，卡面那句仍按效果写，数字可能对不上），没有自动删效果 —— 要不要改成「框填了就忽略那条效果」？
3. 次数公式写 `X` 会被夹到 1~20（老勾选框不夹）—— 要不要让「光秃秃的 X」走无夹取那条路以做到逐字节一致？
4. 卡牌页还剩下：右侧① 「升级增量填公式」（**基础障碍**：升级发生在牌组界面，`OnUpgrade()` 里没有玩家/战斗上下文，等你定口径）、右侧④ 重排 UI＋作用对象 7 档＋概率独立＋「下回合生效」适配全部效果、④ 升级后关键字与自定义关键词、⑤ 升级描述变绿。
