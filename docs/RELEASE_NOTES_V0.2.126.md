# V0.2.126 更新说明

> 你确认的改动：**遗物 = 一份效果 + 一组触发时机**（时机只决定「什么时候触发」），
> 关系用一个开关切「**满足其中一个就触发**（默认）／**全部满足才触发**」，后者保留「重置范围」（本回合 / 本场战斗）。

## 一、结构变了什么

| | 以前（V0.2.122~125） | 现在 |
|---|---|---|
| 效果 | 每条触发时机各自一份 | **整只遗物一份**（右栏效果栏，可加多条效果种类 + 右下角单条效果的条件） |
| 中间栏的时机列表 | 每条时机 + 它自己的效果编辑器 | **只放时机**（种类 / 盯哪个状态 / 到达 N 层·每 N 次 / 统计范围 / 只对哪类牌生效）+ **关系开关** + 「重置范围」（只在「全部满足」时显示） |
| 触发关系 | 各自触发 | **任一满足**（默认）：哪条时机成立就跑这份效果；<br>**全部满足**：每条成立的时机各打一个标记，**最后凑齐的那一下跑一次效果、然后清标记**（一个窗口只触发一次） |

## 二、老存档迁移（按你选的规则）

- 把各条时机原有的效果**按顺序合并**进遗物的效果列表，**完全重复的只留一份**（判据 = 序列化后的紧凑 JSON 相等）；
- 迁移完清空时机上的效果；以前勾过「同时成立」的 → 整只遗物自动切到「**全部满足**」，`重置范围` 沿用原值；
- **幂等**：连跑三次不改一个字节；
- **老存档生成结果逐字不变**（实测哈希，用 `git worktree` 拉 V0.2.125 基线对照）：示例存档 4 只遗物的 `RelicSource` 一致、极老形状（单时机 + 效果挂遗物）一致、遗物描述一致、校验器消息 22/22 行逐字一致；单时机 + 「任一」**不写** `CET:TriggerMode` 标记。

## 四、已知边界（都没动手，留给你定）

1. **老存档「配了 2 条时机但一条都没勾同时成立」**：迁移后是「任一」，于是两条时机的钩子都会跑这份效果 —— 比老行为（各跑各的那一份）覆盖面更广。要严格保持老行为的话，迁移可以改成「只保留第 1 条时机的效果、删掉其余时机」，需要你拍板；
2. 同一钩子上两条**完全相同**的时机（同种类 + 同筛选 + 都没填数值）生成出来一模一样，回读会认成 1 条（已修掉绝大多数情形，彻底解决要给每段加序号标记、会改生成文本）；
3. `PowerReached` 时机的 `Scope` 字段本来就不参与生成、回读也不回来（V0.2.122 起的既有边界）。
