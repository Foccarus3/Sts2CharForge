# V0.3.2 — 触发次数公式：补上「回读」和「解析失败报错」

V0.3.1 上线后有两处如实标注的缺口，这一版都补上。

## 1. 从工程恢复不再丢公式

生成端一直会写这行标记：

```
// CET:TriggerAmount=3m CET:TriggerScope=Turn CET:TriggerAmountFormula=<公式>
```

`ProjectRecovery` 现在会解析 `CET:TriggerAmountFormula=` 并写回 `PowerTriggerSpec.TriggerFormula`
（`UnescapeMarker` 还原特殊字符）。→ 「从已有工程恢复」重建 profile 时，公式不会退化成常数。

## 2. 公式解析不了时**报错**（不再静默退回常数）

以前填了 `N+1` 这种算不出来的公式，生成端只会悄悄用常数，用户以为「填了没生效」。
现在校验器会报一条**错误**：

```
[错误] 自定义状态「X」的触发时机「…」的公式解析不了：「N+1」。
可写算术（2+1）、X / Y、以及你在「自定义参数 / 公式变量」里声明过的参数名；裸写的 M / N 不自动等于你的参数。
```

判据用的是**真的求值一次**（`TriggerAmountFormulaExpr(...) is null`），不是 `TryParse`——
因为 `TryParse` 对未知标识符也会成功、但 `Emit` 会返回 null（V0.3.1 自检就是这么发现的）。
