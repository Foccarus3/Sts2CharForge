# V0.2.375 — 嵌套列表改成**可视化子表格**（不再是 `|` 分隔的多行文本）

按你选的方案做的：那位作者说的「`|` 多行文本是过渡方案」是对的，这一版换成了真的行编辑器。

## 现在是什么样

子列表那一格现在渲染成一个小表格：

```
1.  [段名____] [数值__]  ↑  ↓  ✕
2.  [段名____] [数值__]  ↑  ↓  ✕
+ 添加一行
```

* 每行 = 一组子输入框（子栏位按 `fields` 声明顺序排，鼠标悬停显示标签）；
* 右侧 `↑` `↓` 调顺序、`✕` 删这一行；底部 `+ 添加一行`；
* 任何改动立刻写回该格并触发预览刷新。

## 存储

* 现在存 **JSON 数组**：`[{"label":"第一段","value":"3"}, …]`（放在原来那一格里，`rows.json` 结构没变）；
* **兼容老数据**：V0.2.374 那种「一行一条、`|` 分隔」的文本仍然能读（解析失败也回退到文本行，不丢数据）；
* 生成端用同一份解析（`PluginRegistry.ParseSubRows`），所以界面和生成不会各说各话。

## 自检

**4714 PASS / 0 FAIL**（+2 条：老 `|` 文本仍能读 / 界面上确实是子表格（检测到「+ 添加一行」和 `✕`））。

## 下一步（那位作者提的结构）

有了可视化子表格，「招式 → 动作 / 阶段」这类两层结构现在**能在插件页里直接做**了，不必拆成多页。
如果还需要 **三层**（`EnemySpec → MoveSpec → ActionSpec` 那种），告诉我 —— 存储现在是 JSON，改成递归只差界面那一层。
