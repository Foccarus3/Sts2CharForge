# V0.2.201 —— 锻造图里同一块【数值】模块被两个分支各用一次时，生成出来的卡牌会 `CS0103`

> 用户原话：一张截图 —— `D:\自定义角色存档\MimikyuMod\cs\Cards\MimikyuCard52.cs(80,122):
> error CS0103: 当前上下文中不存在名称"__fgf73650"`。

## 1. 不是存档写错了

`__fgf73650` 是锻造图里一块【数值 / 状态 / 能量】模块的**临时变量名**（`__fg` + 模块 Id 的哈希前 6 位）。
报「当前上下文中不存在名称」= 生成出来的代码**只引用了它、没在同层（或外层）声明过**。
两个原因，都在 `ForgeGraphGen`：

### ① 声明落在分支的大括号里，另一个分支只拿到引用

`ValueVar` 的「这个模块已经算过」缓存（`ValueEmitted`）是按**整个执行点**去重的，
可它写出去的 `decimal __fgXXXXXX = …;` 是**就地写进当前语句流的**：

```csharp
if (false) {                                  // ← 真支
    decimal __fg8131bb = (3m);                //   声明在这里，出了大括号就没了
    … Attack(__fg8131bb) …;
}
else {                                        // ← 假支
    … Attack(__fg8131bb) …;                   //   CS0103：当前上下文中不存在名称
}
```

### ② 缓存键带出口序号，回收时却把序号丢了

【能量】模块右边有两个出口（能量 → `__X`、额外资源量 → `__Y`），变量名按口区分
（`__fgXXXXXX` / `__fgXXXXXXp1`）。缓存键带了口序号（`模块Id#1`），但命中时返回的是裸 `node.VarName`：

```csharp
decimal __fg179b9fp1 = __Y;                                   // 声明带 p1
… Attack(__fg179b9f) …                                        // 第二处引用少了 p1 → CS0103
```

（这条在已发布的 V0.2.200 二进制里就能复现，是拿发布版 Core.dll 真跑出来的。）

## 2. 修法

- `GenState.ValueEmitted`（HashSet）换成 `ValueScope`（键 → **声明时所在的作用域**）+
  `ScopeStack` / `ScopeKey` / `ScopeCovers`；进 `if` 真支 / 假支、【且】/【或】、【条件】的大括号时压一层，
  出来弹掉（新助手 `EmitInScope`）。
- `ValueVar` 命中缓存时先问一句「声明处罩不罩得住当前作用域」：罩得住 → 直接引用；
  罩不住 → 在**当前这一段**里重新声明一份（同名落在兄弟块 / 外层是合法 C#，各支各一份）。
- 变量名统一按出口序号拼，不再返回裸 `node.VarName`。

## 3. 验收

- 探针 `_probe\fgport`：**6/6 PASS**，含「判定器自检」——喂它一段旧版坏样本，必须抓到 `__fg8131bb`；
  以及红线：一个模块只用一次时仍**只声明一次**。
- `--uicheck`：**3953 PASS / 0 FAIL**（新增 4 条：真支/假支各声明一份、出口 1 两处都带 `p1`、只用一次仍一份）。
- `dotnet build` 全解决方案：**0 error**。
- **新旧对拍**（旧 = 已发布的 V0.2.200 Core.dll，新 = 这一版；模块 Id 归一化后逐字节比）：
  - 只用一次【数值】的老写法 → **逐字节相同**（红线没破）；
  - 两个分支共用 / 同一出口用两处 → 只差「补上缺的那份声明 / 补上 `p1`」这一处。

## 4. 遇到这个错怎么办

存档不用改。**用这一版重新生成一次工程**，`cs\Cards\*.cs` 里那条引用就会有对应声明了；
已经生成的目录直接重新生成（或者删掉 `cs\` 再生成）即可。
