# V0.2.189 更新说明

> 你报的：「**最多 N 张和恰好 N 张都是恰好，最多怎么不能少选**」—— 对，界面那一栏以前**有五条链根本没读**。
> 这一版把「取几张」在所有支持它的种类上接通了。

## 一、真因：只有 4 条链真的读了「取几张」，其余硬写「恰好 N」

生成选牌那句 `CardSelectorPrefs` 的地方，有的走公用写法、有的**直接写死两参构造**
（本体那个两参构造 = 「恰好 N 张」）：

```csharp
// 公用写法（正确）：最多 → 三参构造（min=0）
new CardSelectorPrefs(prompt, 0, 3)
// 直接写死的（有问题）：无论选「最多」还是「恰好」，都是
new CardSelectorPrefs(prompt, 3)
```

以前**真的读了**的只有：消耗卡牌 / 丢弃卡牌 / 升级卡牌 / 三种「从某一摞拿牌」/ 节点图那几条。
**没读**（界面上明明有这一栏、选了没用）的是：

| 种类 | 以前 | 现在 |
|---|---|---|
| **变化卡牌**（选哪些牌来变） | 恰好 N | 最多 N ✓ |
| **复制卡牌** | 恰好 N | 最多 N ✓ |
| **重放卡牌** | 恰好 N | 最多 N ✓ |
| **回合结束时自动打出** | 恰好 N | 最多 N ✓ |
| **给予关键词**（选哪些牌） | 恰好 N | 最多 N ✓ |
| **删牌 / 全局变化 / 全局升级**（改牌组那三种） | 恰好 N | 最多 N ✓ |

表现就是你看到的：选了「最多 3 张」，游戏里还是要选满 3 张 —— 少选一张就**卡在选牌界面**
（本体的选牌界面是「选满 MaxSelect 自动结算」，`Min != Max` 时才会出现那颗「确认」按钮；
我们把 `Min` 也写成 3 了，所以确认按钮一直不亮）。

## 二、修法

把这些地方**统一改走共用的 `SelectPrefsExpr`**（就是本来给消耗 / 丢弃 / 升级那几条用的那个）：

```csharp
// 恰好 N 张（默认档）→ 和以前逐字一致
new CardSelectorPrefs(CardSelectorPrefs.TransformSelectionPrompt, 3)
// 最多 N 张 → min=0，本体「净化 Purity」的写法：确认按钮一开始就亮着，选 0~N 张都能结算
new CardSelectorPrefs(CardSelectorPrefs.TransformSelectionPrompt, 0, 3)
// 任意张 → 本体自己用的那个大数
new CardSelectorPrefs(CardSelectorPrefs.TransformSelectionPrompt, 0, 999999999)
```

**默认档（恰好 N 张）生成结果一个字符都没变** —— 老存档的产物逐字不变（`--samplegen` 对拍仍是
那 5 处既有差异，没有任何新变化）。

## 四、用的时候注意

* 「最多 N 张」进游戏后，选牌界面里**少选也能结算**：选够 MaxSelect 会自动结算，
  选得少就点那颗**确认**按钮（本体「净化」那种卡就是这个手感）。
* 「任意张」也是同一套（min=0、上限很大）。
* 三条「改牌组」的（删牌 / 全局变化 / 全局升级）本来就是本体那种**要点确认**的界面，
  现在同样可以少选。
