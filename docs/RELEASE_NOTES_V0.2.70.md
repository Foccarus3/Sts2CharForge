# V0.2.70 更新说明

> 这一版加了两栏：卡牌效果的「**数值公式**」、自定义状态的「**覆盖血条颜色**」；
> 另外修掉两个「从工程恢复存档」的老问题。

V0.2.69 的内容（全体敌人 + 命中次数、无限循环、临时增益负数与两档、自定义状态三个效果、
锻造页可拖的积木编辑器）**也都在这一版里** —— 没装过 69 的直接装这一版就行，不用先装 69。

## 另加一栏「数值公式」（你要求的）

「数值」那一栏只能填一个**死的数字**，而你要的是「打出这张牌那一刻现算」——
比如「造成自己最大生命 ×3 点伤害」「给目标上等于它易伤层数的中毒」。
所以「数值」下面新加了一栏「**数值公式**」：

- **留空 = 用上面那个固定数字**，老存档生成的代码**一个字符都不变**；
- 写了公式 = 打出这张牌时现算，算出来的结果**取代**那个数字；
- 写法沿用锻造页【数值】模块那一套（`M*3`、`max(1, N/2)`、`X`、`Y`、`+ - * / % ( )`、
  `min/max/floor/ceil/round/abs`，最前面可以写 `=`）。`X` = 打出这张牌那一刻的当前能量，
  `Y` = 当前额外资源量，其它字母是「自定义参数 / 组」页里定义的参数。

**只有这 5 种效果能写**（它们的数字是打出时才读的）：
造成伤害 / 获得格挡 / 失去生命 / 回复生命 / 施加增益减益。
其它种类（抽几张 / 生成几张 / 消耗几张）的数字必须**生成时就定下来**
（要提前分配卡面变量、算好选牌上限），所以那些种类上这一栏**根本不出现**。

**这一版只做在卡牌上**（含挂在「卡牌时机」钩子上的那几条 —— 被消耗 / 被丢弃 / 被保留 / 被变化…都能用公式）。
遗物 / 药水 / 自定义状态的触发时机、诅咒牌上填了会**报错拦住**并说清原因
（那几条链没有「打出这张牌」这一刻的上下文：拿不到「打出的那张牌 / 玩家选中的目标」）——
拦住而不是静默忽略，是因为静默忽略最难看懂：公式填了、游戏里还是那个固定数字。

几个写明白的行为：

- 卡面上印的是**公式本身**（「造成 M*3 点伤害」），不是那个占位数字 —— 印占位数字等于骗人。
  想要具体数字就自己写「自定义描述」；
- 效果列表里显示成「数值公式 M*3」，一眼看得出它不是固定数字；
- **升级增量对公式那条不生效**（公式取代了数值），校验器会给一句提示；
- 公式算出来的**正负要到打出时才知道**，所以生成端一律按「正面效果」写
  （伤害 / 格挡 / 回复 / 施加状态都不会反向）。要「扣层数」那种语义请用「施加增益 / 减益」填负的固定数值；
- 「数值」填 0 + 写了公式**不会**被当成「0 = 这条效果不存在」丢掉（和「数值 = X」同一条规矩）。

生成出来的样子（不用自己写代码，这里只是让你知道它真的在算）：

```csharp
// ---- 「数值公式」用到的值：打出这张牌时先算一次（和锻造页【数值】模块同一套语法）----
Creature __fgSelf = base.Owner.Creature;
decimal __pM = __fgSelf?.MaxHp ?? 0;   // M= 自己的最大生命
// CET:AmountFormula=M*3
await DamageCmd.Attack((__pM * (3m))).FromCard(this, cardPlay).Targeting(cardPlay.Target)…
```

## 自定义状态可以「覆盖血条」了（像中毒那样，你要求的）

「自定义状态」页那个状态多了一栏「**覆盖血条颜色**」（六位 RRGGBB，留空 = 不覆盖）。
填了之后，身上有这个状态的生物（自己 / 敌人），**血条右端会多出一截这个颜色的条**：

- **规则和本体中毒一模一样**（几何是对着 `NHealthBar.RefreshForeground` 抄的）：
  层数 = **会失去的血量**（3 层 = 盖住右端相当于 3 点血的那一段），红条跟着缩短到覆盖段的左边，
  层数 ≥ 当前血量就是整条盖住（中毒的「致命」那一档）；和本体中毒 / 灾厄同时在场时，
  我们这一截接在它们左边、红条再缩一次；无限血条不插手。
- **为什么只要填颜色**：本体血条上红条 / 中毒 / 灾厄用的是**同一张纯白九宫格**
  （`images/ui/combat/health_bar_fill.png`），颜色全部来自节点自己的 `self_modulate`
  （红 `CC0C0C` / 中毒 `79C03C` / 灾厄是着色器渐变）—— 所以换色就是换一个数字，不用改贴图。
- 多个这种状态挂在同一只身上时**按列表顺序取第一个**（血条上只有一截位置）。
- 颜色不是六位十六进制时生成前的检查**报错拦住**（写坏了会在游戏里抛异常，所以不放过）；
  不填 = **一个文件都不多、一行补丁都不打**（老存档生成的模组一个字符都不变）。
- 补丁是**手动**打的（`RefreshForeground` 是私有方法）：本体哪天改了这个方法名，
  只丢这一截颜色、记一条警告，**不会连累整个模组加载**（带特性的 PatchAll 会）。
- 「从工程恢复存档」会把这个颜色一起认回来（状态类里有 `// CET:HpBarColor=RRGGBB` 标记）。

## 顺手修掉的两个老问题

**① 「从工程恢复存档」从来不会把自定义参数恢复回来。**
这件事在公式出现之前只是「界面上少一行」，公式出现之后是**致命的**：
回读出来的存档里公式全在、参数全没了，再点生成就是一片「M 不是一个参数」。
现在按生成代码里那一行 `decimal __pM = __fgSelf?.MaxHp ?? 0;` 把来源、取值对象、
状态类名、固定数值原样认回来（自检里专门断言了这一整条来回）。
参数那一栏的「备注」代码里没有（它不参与生成），只有拿旧存档当模板恢复时才带得过来。

**② 「施加状态 + 下回合生效」回读后状态名会变成生成的类名。**
生成的是 `<角色>ForgeDelayed<状态>Power`，回读时只把「下回合生效」认出来了，
状态名却留在了 `SevenForgeDelayedWeakPower` 这种**类名**上 ——
再生成一遍就报「增益 / 减益未选择有效的 Power」，整个存档生成不过去
（探针里「回读 → 再生成」这一步踩到的）。现在把前缀剥掉，认回真正的状态类名。

## 已知限制（说清楚，不藏着）

- 「数值公式」**只做卡牌的那 5 种效果**（见上）。
  遗物 / 药水 / 自定义状态触发时机 / 诅咒牌上填公式会被报错拦住；其余效果种类那一栏根本不出现。
- 公式那条的**升级增量不生效**：公式取代了数值，卡面印的也是公式本身，升级看不出变化。
- 公式算出来的正负在生成端看不出来，所以一律按「正面效果」生成（不会反向扣层）。
- 存档里公式引用的参数如果被删掉了，生成会报错（这是故意的：宁可拦住，也不静默换成固定数字）。
- 「覆盖血条」**只做自定义状态**：本体的状态想换血条颜色请用「本体状态改写」页那一栏
  （那个是整局改色，和这里的「谁身上有谁变色」是两回事）。同一只身上多个这种状态只显示第一个。
- 「覆盖血条」的观感只对着本体源码核过、也真编译过，**没有在游戏里肉眼确认过**
  （这一版的两个新功能都得你进游戏看一眼）。
- 本体的「自定义参数 → 给予能量 / 给予额外资源量」这两栏目前**只是配置项**，生成端还没有用它
  （恢复存档时也认不回来）。这是做公式时顺手查出来的一个老问题，没在这一版动它。
- 【且】/【或】门的 A / B 两个入口，在图上落在【条件】模块的**出口 0** 上（从终点那头看不出是「入口」），
  积木编辑器**不接管**这条线：它会把门下面那两块条件摆出来给你看，
  但那两条线写回时**原样留着**，请在节点图里改。
- 把一整个容器（【对象】/【if】）拖进另一个容器里，复杂图上可能出现某一支没接回去
  （块本身不丢、节点不丢，只是那一条线要在节点图里补一下）。
