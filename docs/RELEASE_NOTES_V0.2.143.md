# V0.2.143 更新说明

> 修你报的：「**遗物的条件选项怎么用不了了**」。精确结论：中间那块「条件选项（整只遗物：不满足时不触发）」**一直是好的**；坏的是**右下角那块「单条效果的触发条件」** —— 选了下拉里的条件**存不住**，切走再回来就变回「无条件」。现在照你的口径修成**和卡牌页一样**。

## 一、真因（一句话）

四个页面（卡牌 / 遗物 / 药水 / 额外资源量）共用的折叠效果行，**整行就是一颗按钮**（点它展开 / 收起）。按钮在冒泡阶段先把鼠标按下事件标成「已处理」，外层列表项就**永远收不到这次点击、永远不会被选中**；而右下角那块条件框的数据来源正是「列表里当前选中的那条效果」——

```
右下角那块 → 绑「选中的那条效果」的 Condition.Kind → 选中项一直是 null → 条件写进空对象、静默丢失
```

卡牌页**没有**这块（它的条件编辑器就在展开区里，绑的是那一行**自己**的效果），所以一直是好的。也就是说：不是你填错，是那块框根本不知道你在改哪一条。

## 二、修了什么

1. **点效果行（那颗展开 / 收起按钮）时，同时把这一行选中** —— 列表里能看到高亮，右下角那块立刻知道改的是哪一条。
2. **三页一起修**：遗物 / 药水 / 额外资源量（它们共用同一份折叠行模板与同一个毛病）。卡牌页本来没问题，另加回归断言保证不被改坏。
3. 右下角那块和展开区里那份「条件」**本来就是同一份数据**（同一个 `EffectSpec.Condition`），改哪边都一样，**不是两份**，不会互相覆盖。

新增断言钉的就是你碰到的这一向（以前**只测过「模型 → 界面」，从没测过「在下列表里选 → 写回存档」**）：点行 → `SelectedItem` 就是这条效果 → 行容器 `IsSelected` 也为真 → 右下角那块的数据源立刻跟过去 → 在下列表里真选一个条件 → **写回 `EffectSpec.Condition.Kind`** → 切到另一只遗物再切回来 **条件还在**。

## 四、已知边界

1. 自检里的「点行」走的是 Click 事件路径（这个环境没有真鼠标），断言覆盖「选中项 / 行容器高亮 / 展开状态 / 右下角数据源」四项；**建议你实机点一下确认手感**。
2. `--uicheck` 在 FAIL 时进程退出码仍是 `0`（既有行为，判据以结果文件里的 `FAIL` 行为准），本版没动它。
