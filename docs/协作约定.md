# 协作约定（给"下一次接手这个仓库的人 / AI"看）

> 这些是用户（Foccarus3）明确指定过的规矩，按时间顺序往下加。改动代码前先扫一眼。

## 1. 网络连不上时：**先问用户，不要自己绕路**

2026-10-23 用户原话：

> 以后发现连不上先问我我可以给你连，不要绕远路

具体含义：

* `git push` / `gh release` / 下载依赖 **连不上或被重置** 时，**第一件事是告诉用户**
  （哪一步失败、报什么错、哪个域名不通），等用户给连通性（代理 / 换节点 / 手动执行）。
* **不要**自己发明绕路方案（例如走 REST API 上传 blob、拼一个 hash 完全相同的 commit
  绕过 `git push`）—— 这次 V0.2.266 就是这么干的：虽然最后落地的 commit 和本地**完全同一个 hash**，
  但那是用户不想要的处理方式。
* 允许的自动重试：同一个命令重试 1~2 次（区分"偶发抖动"和"确实不通"）。
  仍然失败就停下来问，不要折腾第三条路。

## 2. 每次发版都要给更新包

* 本地：`release_all.ps1 -Version V0.2.NNN ... -App D:\ds\s\4 -OutDir D:\ds\s`，
  产物放 `D:\ds\s\Sts2CharForge_更新包_V0.2.NNN.zip`，并让用户拿到文件（present）。
* GitHub：源码 + tag + Release（Release 里挂更新包资产）。

## 3. 生成器的红线

* 老存档生成结果要**逐字节不变**（`t3\_tmp\pwrcmp` 对拍 Sample 113 / WhiteCloak 412：
  只允许 `.sln` 的 GUID 和 `_files.txt` 不同；锻造卡里 `// CET:ForgeGraph=` 那行的 base64 允许变，
  去掉那行后必须逐字节相同）。
* 自检 `--uicheck` 必须 **0 FAIL**，并且新功能要配自检断言；涉及生成代码的功能要进"探针工程真编译"。
* 不静默失败：配置有问题就写校验器提示 / 生成注释，不要让它悄悄没效果。
