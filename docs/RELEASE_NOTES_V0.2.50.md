# Sts2CharForge V0.2.50

> **这是一个修 bug 的版本，请尽快升级。** 只做了两件事：修一个会让「遗物 / 药水」上的某些效果生成出**编译不过**的代码的老 bug，
> 并补上防回归的自检。功能与 V0.2.49 完全一样。

## 修了什么

**症状**：用 V0.2.37 ~ V0.2.49 生成时，如果**遗物或药水**上有「获得状态（力量 / 敏捷 / 中毒…）」这类效果，
构建会在第 1 步「编译 DLL」失败，报两条看不懂的错：

```
参数 2: 无法从 "Creature" 转换为 "IEnumerable<Creature>?"
参数 5: 无法从 "…Relic1" 转换为 "MegaCrit.Sts2.Core.Models.CardModel?"
```

**原因**（我们的锅，不是游戏或你存档的问题）：生成 `PowerCmd.Apply<状态>(…, cardSource)` 时，
最后一个参数必须是 `CardModel?`。卡牌写 `this` 没问题（卡牌自己就是 `CardModel`），
但**遗物和药水不是** `CardModel` —— 传 `this` 会让编译器去选「一群生物」那个重载，于是报出上面那两条错。
这个坑是 **V0.2.37**（「获得类数值支持负数」那次重构把遗物 / 药水并到同一个辅助函数上）引入的，
所以你会看到「旧版本能生成、新版本被拦住」。

**修法**：辅助函数改成**显式指定 `cardSource`** —— 卡牌仍然传 `this`（来源信息不丢），
遗物 / 药水传 `null`。涉及遗物 5 处、药水 4 处调用点，另外顺手修了同一类的第二处：
**遗物 / 药水上的「变化卡牌」+「仅本回合升级」**（它也会生成同样的一对错）。

**验证**：拿一份实测会失败的存档重新生成 → `dotnet build` **0 错误**（V0.2.49 时是 2 个错误）；
`--uicheck` 自检 **1740 PASS / 0 FAIL**。

## 顺手加的防回归自检（9 条）

- 遗物 / 药水上的「获得状态」→ 生成的 `PowerCmd.Apply` / `ModifyAmount` 最后一个实参必须是 `null`；
- 两段生成源码里**任何** `PowerCmd.Apply<` / `ModifyAmount(` 都不得以 `, this);` 结尾（兜底）；
- **对照组**：卡牌上同类效果仍必须是 `this`（防止修 bug 把卡牌改坏）；
- 自定义状态触发器 → `null`（本来就对，锁住）。

## 其他

- 存档格式不变；升级后**重新生成一次**工程即可（生成会整份重写工程目录）。
- 上一版（V0.2.49）的五条新需求（⑧⑦⑥⑨⑩）都在。
- 发布包不含任何存档与游戏素材。
