# V0.2.125 更新说明

> 你要求：遗物页左侧序号**每 5 个一块预留并显示**（3 个遗物 → 显示 1~5；加到第 6 个 → 显示 6~10）。

## 一、做了什么

遗物页左侧列表现在按「每块 5 个」凑满显示：

| 遗物数量 | 显示的行 | 说明 |
|---|---|---|
| 3 | **1~5** | 1/2/3 有遗物，**4、5 是空槽**（灰色序号） |
| 5 | 1~5 | 刚好一块 |
| 6 | **1~10** | 第 6 个开新块，7~10 空槽 |
| 11 | 1~15 | 依此类推 |

- 序号仍是**位置号**（1..N 连续），空槽只是把当前这一块凑满；
- **空槽可以当拖放落点**（把遗物拖到空槽 = 放到那个位置），但不能被当成遗物：
  选中空槽不会改动任何遗物、右侧详情不闪、删除/撤回/全选/生成都拿不到它；
- 空槽只存在于界面（`Profile.Relics` 里永远只有真遗物）→ **生成、存档、回读、校验里一个「空槽」痕迹都没有**（实测：真生成 97 个文件零痕迹）。

## 二、验证

- `dotnet build Sts2CharForge.sln -c Debug` **0 错误**；发布版 `--uicheck` **2820 PASS / 0 FAIL**（V0.2.124 是 2806，新增 14 条）；
- 新增断言实测：3 只 → 5 行（序号 1..5，4/5 是空槽、屏幕上真画出 5 个「N.」）；选空槽 → 选中项不是 `RelicSpec`、当前遗物与字段都没被改；
  6 只 → 10 行（7~10 空槽）；删回 5 只 → 5 行；拖一只到空槽 → `Profile.Relics` 顺序真的变且序号仍连续；
  空槽序号是灰的（`#FFAAAAAA`）、遗物名那一列为空；「全选」只选中真遗物；
- **生成回归**：改动前后各用 `--samplegen` 生成一遍逐文件比 SHA256 → 过滤掉每次都会变的 `ExampleMod.sln` GUID 后 **111 vs 111 差异 0**；
- 附带修掉两个真坑（已写进代码注释）：`RelicRows` 必须 `public`（WPF 反射读不到 `internal` → 绑不上、一行都不显示）；`Clear()` 会触发选中变化重入、两次快照各铺一份导致「加第 6 只还显示 5 行」。
