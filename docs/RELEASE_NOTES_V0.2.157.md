# V0.2.157 更新说明

> 回答你报的：「状态监听『打出一张牌时』这个时机，会监听**施加这个状态的牌**，即这个时机的实际效果是
> 『打出一张牌后』，触发时机靠后、与『一张牌结算完毕时』接近」。

## 一、真因：那一档用的钩子确实是「打完之后」

本体打一张牌的**顺序**（`CardModel` 里就是这几步）：

```
Hook.BeforeCardPlayed(cardPlay)      ← 「打出的那一刻」，这张牌**还没结算**
   ↓
OnPlay(...)                          ← 这张牌的效果在这里跑（「施加状态」就在这一步）
   ↓
Hook.AfterCardPlayed(...)            ← 结算完才回调：内部先 AfterCardPlayed 再 AfterCardPlayedLate
```

工具那一档生成的是 `AfterCardPlayed` —— 所以「打出这张牌才施加的状态」在**同一张牌**上立刻就被触发了
（你说的没错，它实际就是「打出一张牌后」，和「一张牌结算完毕时」几乎一样）。

**修法**：

- 「**打出一张牌时（这张牌还没生效）**」→ 改用本体的 **`BeforeCardPlayed`**
  （在 `OnPlay` 之前派发 ⇒ 这张牌施加的状态还不存在 ⇒ **不会被它自己触发**）；
  ⚠ 这个钩子本体**没给 `choiceContext`**（签名只有 `cardPlay`），所以需要 context 的效果
  （例：消耗卡牌要弹选牌界面）由生成端**按本体的做法自己造一个** `HookPlayerChoiceContext`
  （和「花掉能量 / 自己失去生命」那几条时机同一套机制）。
- 原来那一档**语义不丢**，单独留成了新时机「**一张牌结算完毕时**」→ `AfterCardPlayedLate`
  （旧版生成出来的工程回读时也会落到这一档，语义和它当时一致）。

自定义状态 / 遗物 / 锻造页遗物档**三处的菜单、签名、归属守卫**（只认自己打出的牌）都同步了；
回读也跟着改（`BeforeCardPlayed` → 打出一张牌时；`AfterCardPlayed` / `AfterCardPlayedLate` → 一张牌结算完毕时）。

## 二、这一版里一起带的其它修复（工作区里之前就做好的）

- **自动类名撞名会避让**：真事故是校验器报「卡牌类名重复：`GunnerRainyCard37`」——
  两张自动编号的牌算出同一个类名时，后一张会让位（让位用的名字认不出是自动编号，下次生成不会被改回去）；
- **「强化指定卡牌」的目标卡必须认得出**：填了一个不存在的类名时**生成前**就报错，
  不再拖到编译期 `CS0103`；
- **同一个钩子里合并多条触发时机时，各条各自包一层裸块**：消掉「同作用域重名局部变量」的 `CS0128`
  （例：两条时机各自声明一个掷骰变量）；
- **「回合结束时」的效果真的生成出来**（老 id `TurnEnd` 与新 id `PlayerTurnEnd` 都算数）。
