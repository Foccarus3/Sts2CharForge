# V0.2.101 更新说明

> 两件事：① 你要求的**把触发时机合并成同一套**（遗物 ↔ 状态）；② 你发现的问题
> 「**命中次数的公式是不是无法正确生效**」—— 查清了，确实有一批种类填了不生效，这一版**修掉并且不再静默**。

## 一、触发时机合并：遗物和状态现在是同一套

遗物页的触发时机从 16 条涨到 **28 条**，状态那边有的，遗物这边都有了（同一个 id、同一个显示名）：

| 新加到遗物侧的时机 | 本体钩子 | 生成时的守卫（遗物的 base.Owner 是 Player） |
|---|---|---|
| 打出一张牌后 | `AfterCardPlayed` | `if (cardPlay.Player != base.Owner) return;` |
| 消耗一张牌后 | `AfterCardExhausted` | `if (card?.Owner?.Creature != base.Owner.Creature) return;` |
| 抽一张牌后 | `AfterCardDrawn` | 同上 |
| 弃掉一张牌后 | `AfterCardDiscarded` | 同上 |
| 自己失去生命时（每一下） | `AfterCurrentHpChanged` | 只认自己 + `delta < 0`（回血不算）；钩子没给 context → 自己造 |
| 自己获得格挡后 | `AfterBlockGained` | 只认自己；同上自己造 context |
| 一个敌人死亡后 | `AfterDeath` | `if (!creature.IsEnemy) return;` |
| 敌人回合开始时 | `AfterSideTurnStart` | `if (side != CombatSide.Enemy) return;`；自己造 context |
| 敌人回合结束时 | `BeforeSideTurnEnd` | 同上 |
| 敌人受到伤害后 | `AfterDamageReceived` | `if (target == base.Owner.Creature \|\| !target.IsAlive) return;` |
| 敌人造成伤害后 | `AfterDamageGiven` | `if (dealer is null \|\| dealer == base.Owner.Creature) return;` |
| 敌人获得格挡后 | `AfterBlockGained` | `if (creature == base.Owner.Creature) return;`；自己造 context |
| 某个状态层数变化后 | `AfterPowerAmountChanged` | 只认自己身上的状态（可选「盯哪个状态」） |

反向也补齐了：**状态侧**新增「**获得金币时**」和「**抽牌堆打乱洗牌时**」（遗物早就有的两条）。

同时把**显示名统一**了 —— 同一个时机在两边的叫法现在完全一样：

| 以前（遗物 / 状态各叫一套） | 现在（两边都这么叫） |
|---|---|
| 受到伤害时（每一下） / 自己受到伤害后（每一下） | **自己受到伤害后（每一下）** |
| 受到攻击后（连击只算一次） / 自己受到攻击后（…） | **自己受到攻击后（连击只算一次）** |
| 造成伤害时（每一下） / 自己造成伤害后 | **自己造成伤害后** |
| 每回合开始时 / 玩家回合开始时 | **玩家回合开始时** |
| 每回合结束时 / 玩家回合结束时 | **玩家回合结束时** |
| 每消耗一个能量 / 花掉能量后 | **花掉能量后** |
| 每消耗一个额外资源量 / 花掉额外资源量后 | **花掉额外资源量后** |
| 战斗胜利时 / 战斗胜利后 | **战斗胜利后** |
| 某个状态层数变化时（升或降都触发） / 某个状态层数变化后 | **某个状态层数变化后** |

**老存档 / 老工程照旧能读**：改名前写在工程里的那句 `// 触发时机：<老显示名>` 也认得回来
（`ProjectRecovery.RelicTriggerOfDisplay` 里留了一张老名字对照表），回读不会丢触发时机。

**还剩三处不一样（都是有原因的，说清楚）**：

| 只在遗物侧 | 为什么 |
|---|---|
| 获得时 | 遗物才有「拿到的那一刻」；状态是被施加的，没有拾取这一说 |
| 战斗结束时（房间结算之前） | 状态那边「战斗胜利后」生成的就是**同一个钩子**（`AfterCombatEnd`），只是叫法不同、语义等价 |
| 某个状态层数到达 N 层时 | 状态那边用「某个状态层数变化后」+ **条件「某状态层数刚好达到 N 层」**实现，能力等价（遗物侧这两个也都还有） |

**卡牌侧**没有跟着改：卡牌不是「挂在某个模型上的钩子」，它的时机是
「打出的那一刻（OnPlay）」+「卡牌时机」条件（被消耗 / 被生成 / 被保留 / 被丢弃 / 被变化 / 被给关键词）。
要让卡牌也能选「战斗开始时 / 每回合开始时」这类时机，是另一件事（要给卡牌生成一整套钩子）——
需要的话说一声，我按遗物这套路子做。

## 二、「命中次数的公式」确实有坑，已修

你感觉没错。查下来是这样：

- 「命中次数 / 对群数」这个数字，生成端**只有这三种场合**会读：
  ① 造成伤害（多段：`.WithHitCount(N)`）；② 作用对象 =「随机敌人」（N = 挑几个敌人）；
  ③ 几种「伙伴攻击」（每段各打一下）。
- 其它种类（失去生命 / 单体施加状态 / 单体击晕 / 抽牌 / 获得格挡…）**压根不看它**；
  可是以前这一栏对**所有种类**都显示，填了公式也不报错 → 结果就是「填了没反应」，正是你遇到的。

这一版改成**不静默**：

- 「命中次数 / 对群数」那一栏在这些用不到的种类上**自动收起**（换成「造成伤害」等会再出现）；
- 校验器：用不到的场合填了**公式** → **报错**（说清只有哪三种场合会用到，并指路「整条效果重复几遍」请用**生效次数**）；
  只填了**固定数字** → **警告**（老存档不拦死，但明确告诉你这个数字不生效）；
- 公式本身在会用到的那三种场合照旧生效（夹到 1~20），例：
  `.WithHitCount((int)System.Math.Clamp((__fgPlayer?.PlayerCombatState?.TurnNumber ?? 0), 1m, 20m))`。
