# V0.2.346 — 英文类名「生成即固定」：拖动排序不再改名，目标卡引用不会再丢

你报的：**变换顺序后卡牌自动生成的英文类名会变，导致目标卡丢失**。做法按你选的 **B（判据改一行）+ 五类模型一起做**。

## 根因（两个叠一起）

1. 类名是「**留空就按行号算**」（`<角色类名>Card<行号>`）；
2. 生成 / 部分界面刷新时还会跑 `RenumberCardClassNames`：把**长得像自动名**的（判据是**形状**，不是谁填的）
   按**当前行号**重排 —— 比如拖到第 3 行的 `Card7` 被改成 `Card3`；
   引用（`SpawnCardId` 目标卡 / 先古转化清单 / 卡面 key）只在**生成工程时**才靠类名表搬一次，
   你在界面上拖动的那一刻，显示名已经变了、引用还是旧字符串 → **目标卡当场丢**。

## 改法

* **判据**：`Naming.RenumberCardClassNames` / `RenumberRelicClassNames` / `RenumberPotionClassNames`
  改成「**已经存下来的类名一律不动**，只有**留空**的才按序号自动编号」。
* **五类模型一起**（卡牌 / 诅咒 / 先古卡 / 遗物 / 药水 / 召唤物 / 自定义状态）：
  留空的类名在**打开存档 / 增删 / 拖动**时立刻写实（`NameStabilizer.PinNames`）。
* 写实走**静默**通道（`PinClassNameSilently`：只写字段、不触发 `PropertyChanged`）——
  界面上显示的字符串一个字都没变（算出来的名字 == 固定下来的名字），所以不重刷列表、不打断拖动。
  （⚠ 这条是踩出来的：一开始走 setter，`SyncDetail` 里每刷一次都重建列表容器，自检里「序号列只画出两行 / 拿不到行容器」两连挂。）

## 效果

| 场景 | 以前 | 现在 |
|---|---|---|
| 拖动换位置（类名长得像自动名） | `Card7` 被改成 `Card3`，引用断 | **名字不动**，引用照旧 |
| 留空类名的新卡 | 名字跟着行号飘，引用跟着飘 | 添加 / 拖动时就**写实固定** |
| 复制卡牌 | 类名清空（留空 = 自动编号） | 立刻拿到一个**和源卡不同**的新名字 |
| 校验器 | 提示「下次生成会改名」 | 提示「名字已固定，不会再自动改名」 |

## 注意（行为变化，进游戏前看一眼）

* **老存档**里那些「按位置自动编号」的名字，现在**不会再自动修正**了。要是某张卡的类名和它现在的行号对不上
  （例如 `SparkleCard7` 排在第三行），那它就**一直叫 SparkleCard7** —— 这是有意的：名字变了才会丢引用。
  想换名字直接在「英文类名」里改。
* 已经**进游戏玩过的那一局**里存的还是旧类名；改名 / 这次改动都动不了那一局的存档。
  换新版后如果那张牌在存档里「不见了」，用新版重开一局即可（这条以前就写在交接里）。
