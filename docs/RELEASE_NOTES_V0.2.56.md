# Sts2CharForge V0.2.56

> 这一版把前一版的改动**完整地再打了一次包**：V0.2.55 发出去之后又补了两处
> —— **㉒ 锻造页状态下拉看不到自定义状态** 多修了一个原因（那块布的下拉是重建时才搭的，
> 登记过自定义状态后不重画就还是旧清单），以及 **⑦ 自定义状态里可以用「升级卡牌」**
> （参照本体储君的「暴政」）的实现 + 6 条自检。
> 所以**直接装 V0.2.56**，不用先装 V0.2.55。
> 新功能还是那三块（**自定义参数 / 组**、**锻造页 + 节点编辑器**、**遗物的两个新触发时机**）；
> V0.2.54 那一批新增（**额外资源量的「数量上限」+ 抬上限的效果**、**「本回合这张牌费用变 0」效果**、
> **条件里的「失去生命时」**）也都在这一版里。
> 这一版改了两处：**㉒：锻造页【状态】/【效果】模块里的「增益 / 减益」下拉看不到自定义状态**；
> 以及 **⑦：自定义状态里现在可以用「升级卡牌」了**（参照本体储君的「暴政」）。
> 存档格式向后兼容：老存档照常打开，节点图 / 数量上限都是新字段（老存档没有 = 空 / 0 = 不限）。

## 新增

### ① 「自定义参数 / 组」页

- **参数**：一个字母 = 一个中间变量。点「新建参数」自动挑一个没被占用的字母（X / Y 是保留的：
  当前所有能量 / 当前所有额外资源量）。来源可选 **当前血量 / 最大生命 / 金币数 / 能量数 / 最大能量数 /
  增益减益（状态层数）**，「从谁身上取」可选自己 / 指定敌人 / 随机敌人 / 全部敌人 / 全部友方 / 召唤物。
  → 「自己 + 最大生命」就是 `M=自己最大生命`，「指定敌人 + 易伤」就是 `M=被指定敌人的易伤层数`。
- 这些值**打出牌的那一刻才现算**（血量、层数变了结果跟着变），不是在生成时算成固定数字。
- 右边可以把某个参数指定成「给予多少能量 / 多少额外资源量」（默认那一套就是 X 与 Y）。
- **组**：新建组并命名；「卡牌属性」标题右边会多一排勾选框。组只影响生成器里的查看与筛选
  （「范围」里会多出「组：XXX」这一档），不写进模组代码；改组名不会让已勾的卡掉出去。

### ② 「锻造」页 + 节点编辑器

- 最左侧选**卡牌 / 药水 / 遗物列表**，点「添加」生成一项**名字带 `*`** 的条目；
  这些条目在原页面里被选中时不显示编辑器、只提示「请在锻造页查看」。
- 中间照常改名称 / 类型 / 稀有度，**不用填费用**、也没有「升级后 X + 1」（那两样归节点图里的模块管）。
- 最右侧是**节点图（布）**：中间【触发时机】、左上角固定【能量】；
  拖标题栏移动、**空白处拖框选**、Shift 点选、Ctrl+A 全选、多选后一起移动、Delete 一起删。
  **按住出口圆点往入口圆点拖**就能连线（拖的时候一根黄线跟着鼠标，松手接上；松在空白处取消），
  也可以先点出口再点入口；**在连线上右键就删掉这条线**；连错会画红色虚线并说明原因。
- 模块共 11 种：**【触发时机】【if】【对象】【状态】【数值】【能量】【效果】【且】【或】【条件】** 与
  【能量】（固定左上角）。端口有字以小字显示，没字只有一个圆点。
- **【能量】右边两个出口**分别是「能量」和「额外资源量」：接出去就是当前能量 / 当前额外资源量
  （已经扣掉【能量】模块上填的「打出时消耗」），**两个出口各算一份、互不撞名**。
  以前这两个口都算成同一个值，第二个口等于没用。
- **【数值】** 可以填公式：`M*3`、`X`、`Y`、`min(2, X)`…（支持 `+ - * / % ( )` 和
  `min/max/floor/ceil/round/abs`）；参数名写错 / 括号不配会在生成前给中文提示。
  【数值】留空 = 转发它接入点接进来的那一块（这样才用得上【能量】那两个出口）。
- **执行顺序**：从【触发时机】顺着线走，接了几个出口就按顺序走几个；【if】按「否 / 是」成 `if`/`else`，
  【且】【或】【条件】成立才继续。
- **升级前 / 升级后**两张布：点悬浮按钮「一键复制『升级前』的内容」= 把「升级前」**那一刻的样子**
  整份拍下来当成「升级后」的内容。之后在「升级前」上继续改**不会**影响它 —— 两块是独立的数据。
  「升级后」空着时，升级后的卡走的就是「升级前」那张布（所以不填也完全能用）。
  下面一行会写清两块布的差异（几块改了设置 / 多了几块 / 少了几块）。
- 效果种类接了 **26 种**（伤害 / 格挡 / 抽牌 / 能量 / 回复 / 失去生命 / 最大生命 / 金币 / 额外资源量 /
  施加·扣除状态 / 临时增益 / 翻倍状态层数 / 清除单个或全部减益 / 禁止获得格挡 / 击晕 / 结束回合 /
  生成卡牌 / 消耗 / 丢弃 / 升级 / 变化 / 复制 / 从三摞各拿牌到手牌 / 预见 / 获得药水 / 获得卡牌奖励），
  其中消耗 / 丢弃 / 升级 / 变化 / 复制都有**自己选**（弹本体选牌界面）与**随机**两档。
- 「获得卡牌奖励」只能挂在【触发时机】=「战斗胜利时」那一支上（本体没有战斗中直接弹奖励的入口），
  挂错会跳过并写明原因。

### ③ 遗物的两个新触发时机

- **当遗物被点击时**（本体没给 `RelicModel` 留点击虚方法，生成端挂一个只认你自己那只遗物的窄补丁转发）。
- **血量低于 N**（填小于 1 的值按百分比算，`0.5` = 血量低于 50%）。
- 两者都能填 **本场战斗 / 本回合 / 本次游玩仅生效 N 次，填 0 = 无限次**；用尽后会像本体一样**变灰**。

### ④ 效果种类「禁止打出某类牌」、触发时机「自动打出时」

- 自定义状态的触发时机新增「自动打出时」；卡牌新增「卡牌被自动打出时」这一档。
- 自定义状态触发器现在也能用「从抽牌堆 / 弃牌堆 / 消耗牌堆拿牌」（以前被校验器拦住）。

### ⑤ 额外资源量的「数量上限」+ 抬上限的效果

本体**没有上限这个概念**：`PlayerCmd.GainStars` → `PlayerCombatState.GainStars` 里只有
`Stars = Math.Max(Stars + amount, 0)`，想涨多少涨多少。（`Hook.ShouldGainStars` 只能拦、不能改数。）

- **「额外资源量/状态」页新增「数量上限」**：填 0 = 不限（和本体一样）；填 N = 涨到 N 就不再增加，
  超出的部分**直接不加**（不是先加满再扣掉，卡面与播报的数字就是实际拿到的）。
- **新效果「增加额外资源量上限值」**（卡牌 / 遗物 / 药水 / 节点图【效果】里都能选）：
  给**当前战斗**加一层隐藏加成，实际上限 = 页面上填的基础值 + 这个隐藏状态的层数；
  战斗结束清空（基础值不受影响），所以「本场战斗上限 +2」这种牌可以反复叠。
- 那个隐藏状态 `…ForgeStarCapPower` 是 `IsVisibleInternal => false`：**不出现在状态栏里**
  （不想让玩家看见一个莫名其妙的状态），也不占玩法位置。
- 只填页面上限、没用那个效果时不会生成隐藏状态；只用效果、页面上限填 0 时上限从 0 起加。
- 卡面描述写成「<资源名>上限 +{ResourceCap:diff()}」，升级增量跟着本体算。

### ⑥ 另外两个新效果 / 新条件

- **效果种类「本回合这张牌自己费用变 0」**：生成 `base.SetToFreeThisTurn();`
  （本体 `CardModel.SetToFreeThisTurn` = 能量费用与本回合星星费用一起归 0）。
  与「这张牌被打出时给别的牌减费」是两回事：这条改的是**它自己**，而且**本回合内多次打出都管**。
- **条件新增「失去生命时」**：卡牌触发时机多一档 `HpLost`，走本体
  `AbstractModel.AfterCurrentHpChanged(creature, delta)`（`delta < 0` 才算掉血）。
  想写「自己掉血就抽一张」这类牌时用它，比拿「生命值低于 N%」近似要准。

### ⑦ 自定义状态里可以用「升级卡牌」了（参照本体储君的「暴政」）

需求原话：「图片里的效果为什么不行，参考一下原版储君的『暴政』」。

以前在**自定义状态**的触发时机里选「升级卡牌」，生成前的检查会拦住：

```
自定义状态「奈奈」「玩家回合开始时」的第 1 条效果是「UpgradeCard」，
这种效果需要卡牌上下文（选牌 / 结束回合），状态触发器里用不了。
```

这条限制**太保守了**。本体自己在状态钩子里就是让玩家选牌的 —— 储君的「暴政」就是：

```csharp
// TyrannyPower.AfterPlayerTurnStart
foreach (CardModel item in await CardSelectCmd.FromHand(choiceContext, player,
             new CardSelectorPrefs(CardSelectorPrefs.ExhaustSelectionPrompt, base.Amount), null, this))
    await CardCmd.Exhaust(choiceContext, item);
```

`EntropyPower` / `ToolsOfTheTradePower` / `StratagemPower` / `ForegoneConclusionPower` 也都是这么写的。
我们的状态钩子里 `choiceContext` 同样有（没有的那几个钩子会自己造一个），只差生成端没给状态写这条实现。

现在：

- **「升级卡牌」进了状态触发器的效果白名单**，也就会出现在那个效果下拉里；
- 生成端新增这条实现，和卡牌那条语义一致：**自己选** → `CardSelectCmd.FromHand`（手牌）/ `FromCombatPile`（抽牌堆 / 弃牌堆 / 消耗牌堆），
  只列 `c.IsUpgradable` 的牌，选中后 `CardCmd.Upgrade`；
  **随机** → 走本体 `Rng.CombatCardSelection`，随机挑能升级的那几张。
- 玩家用 `base.Owner.Player` 取（状态里 `base.Owner` 是 **Creature**，不是卡牌上下文里的那种 `base.Owner`）；
  提示语只能用**静态**的 `CardSelectorPrefs.UpgradeSelectionPrompt`（`Prompt` 是实例属性，写了会 CS0120）。
- 落在**不带** `choiceContext` 的钩子上（例：敌人回合开始时）时，照旧自己造一个 —— 这条也补进了
  `NeedsChoiceContext` 清单，否则会 CS0103。

> 顺带说明：「丢弃卡牌 / 消耗卡牌」在状态里**仍然不支持**。它们语义上和「升级」同级（本体也有
> 状态里选牌丢弃的例子，如 `ToolsOfTheTradePower`），但那是另一批实现，等你要的时候再加 ——
> 现在选它们校验器会明确告诉你「状态里用不了」，不会静默生成一个什么都不做的空壳。

## 修了什么

### ① 真实的 GIF 素材**一律解不开**（GIF 解码器）

GIF 的色表项数按规范是 `2^(N+1)`，而代码写成 `(1 << (N + 1)) & 31` —— N = 7（**满 256 色**，
真实素材几乎都是）时算出来是 `256 & 31 = 0`，**色表一项都不读**、后面整块数据全部错位。
实测 6 个真实 GIF 里 5 个挂在这一句。现在按规范算。

同一处还修了两个会「静默变成解不开」的问题：LZW 解出的像素数少于画布时会越界被吞成「解不开」（现在补足），
以及解不开时**会带上具体原因**（文件头不是 GIF / 没有全局色表 / 某一帧的数据解不出来…）。
实测：本机 8 个真实 GIF（含隔行 / 4 帧动画 / 满 256 色）现在全部解开。

### ② 空壳「解包工程」让效果库为空 → 生成被整个拦死

有的整合包里那个解包工程是空壳（`Powers\*.cs` 是几百个 1 字节文件、`Cards` 那边上千个）。
以前只看「目录在不在」，于是**不再去读 `sts2.dll`**、正则又一条都匹配不上 → 效果库为空 →
校验器把生成整个拦死（连不含动画的角色都生成不出来）。现在两道保险：
抽样判空壳、读空回退读 `sts2.dll`。

顺带把读 `sts2.dll` 的方式换成**只读元数据**（不加载程序集）：
以前用 `Assembly.LoadFrom(dll).GetTypes()`，在依赖不全的程序集上只能拿到 35/9760 个类型，
**.NET 9 上还会直接把栈打爆**（`StackOverflowException` 抓不住、工具当场死）。现在快且不会崩。

### ③ 节点编辑器里模块点不动、连不上线（StackPanel 转 Border 的异常）

点一下模块标题栏就会抛 `InvalidCastException：Unable to cast object of type 'StackPanel' to type 'Border'`
（拖动那段代码写的是 `(Border)header.Parent`，而标题栏的父级是装标题栏 + 端口 + 字段的 `StackPanel`）。
这一下把整条交互链打断：**模块选不中、拖不动，也就接不上线**。现在改成把模块自己的外框直接传进去。

顺带修掉同一处的两个问题：标题栏上挂了两个 `MouseLeftButtonDown`，前一个把 `e.Handled` 置了之后
**后一个「选中」根本不会执行**；以及画布只在「换了一张图」时才重画，一旦数据先变、画布后指过来，
布上画的模块数就和数据对不上（照样找不到外框、拖不动）——现在会补一次重画。

### ④ 【能量】右边第二个出口（额外资源量）接出来没用

【能量】右边是两个出口（能量 / 额外资源量），但取值那一步只看模块、**没看是从哪个口接过来的**，
于是两个口都算成同一个值 —— 接第二个口等于没接。现在按接的是哪个口分别取值，
两个出口各产生一个独立变量，不会撞名。

### ⑤ 【效果】的「数值 / 指向对象」接不上（端口写成了出口）

【效果】左边少了两个接入点：生成端本来是按「第 1 个口 = 数值、第 2 个口 = 对象」去读的，
但这两个口在模块定义里被写成了**出口**——于是它们画在右边、左边根本没有圆点可以落线，
**没法把【数值】/【对象】接给【效果】**，只能靠模块上填的常数。同理【if】的「条件」也接不上。

现在【效果】左边是「接入 / 数值 / 指向对象」三个口、右边一个「完成」出口；
【if】左边一个「条件」口 + 右边「否 / 是」。拖线、先点后点、在线上右键删除都走同一套判定。

### ⑥ 效果种类底下那一堆栏全摊开了

二十多栏一起显示，大多和当前选的效果没关系（比如选「造成伤害」也摆着「目标药水」）。
现在只显示用得上的：药水那两栏只在「获得药水」、目标卡 / 生成到只在「生成卡牌」、
取牌方式只在「消耗 / 丢弃 / 升级 / 变化 / 复制」。数据不删：换回对应种类，之前填的还在。

### ⑦ 【对象】「指定召唤物」不能选是哪一只

选了「指定召唤物」和「随机召唤物」效果一模一样（都是第一只）。现在选「指定召唤物」时下面会多出
**「召唤物名称」**一栏（只列你在「召唤物」页配的那些），生成代码按名称找那一只，找不到才退回第一只。

### ⑧ 锻造卡的两处布局按需求调整

- **卡牌页选中带 `*` 的锻造卡**：中间的属性区**照常能改**（名称 / 类型 / 稀有度 / 卡池 / 关键字 / 卡面），
  但**费用那几栏整块藏掉**（费用 / X 费用 / 额外资源量费用 / 升级后 X+1 —— 由锻造页的
  【触发时机】/【能量】模块定），**右边效果栏连「添加效果 / 删除效果 / 撤回删除」三个按钮一起藏掉**
  （效果归锻造页的节点图），只留一句说明告诉你去哪改。
- **锻造页中间那半（属性）去掉**：这一页只管右边的节点图，属性回「卡牌 / 药水 / 遗物」页改，
  节点图因此能占满整宽。

### ⑨ 【if】的端口按需求分方向

【if】左边原本是「条件」入口、没有链的接入点。现在左边是**「接入」（接前置：触发时机 / 对象 / 别的分支）**，
判断条件从**右边新开的一个「条件」口**接（和【效果】的「数值 / 指向对象」同一套写法）。

### ⑩ 节点图：字更清楚 + Ctrl 滚轮缩放

- 布上的说明文字是小字号（10~12px），走的是 WPF 默认的「理想排版」，小字会糊。
  现在整块布换成**按像素对齐 + ClearType**，模块里的端口名 / 说明清楚一档。
- **Ctrl + 滚轮放大 / 缩小**（Ctrl + `+` / `−` 也行，Ctrl + `0` 回 100%），
  工具条右边多了一排：`−`、当前百分比、`＋`、适应窗口、100%。
  缩放中心跟着鼠标走；不带 Ctrl 的滚轮仍然是上下滚画布。

### ⑪ 校验器新增：自定义状态贴到敌人身上会提示

自定义状态的触发时机（玩家回合开始时 / 自己受到伤害后 / 打出牌后…）在生成代码里盯的都是
`base.Owner`（= 挂着这个状态的那个单位）。所以**把这种状态施加到敌人身上时，它永远不会触发** ——
用户实测踩过（「染色：红 / 黄 / 蓝」三张附魔牌贴给了敌人，一条都不生效）。
现在校验器会出中文警告，说清为什么不会触发、怎么改（把效果的「作用对象」改成「自己」）。

### ⑫ 修「敌人回合结束时 + 每回合衰减」编译不过（CS0111）

自定义状态里把触发时机选成「敌人回合结束时」、又勾了「每回合衰减 / 回合结束移除」时，
生成的代码里会出现**两个** `BeforeSideTurnEnd` 覆写 → 一键构建直接报：

```
error CS0111: 类型"Xxx"已定义了一个名为"BeforeSideTurnEnd"的具有相同参数类型的成员
```

原因：这两个时机在代码里是**同一个本体钩子**（`BeforeSideTurnEnd`，用 `side` 区分玩家 / 敌人），
而衰减 / 移除也写在那个方法里。以前只给「玩家回合结束时」做了合并。

现在改成**按钩子分组**（不是按时机名）：同名钩子只会生成一个方法，里面玩家侧跑玩家侧的、
敌人侧跑敌人侧的，衰减照旧在最后。顺带修好一个连带问题：只配「敌人回合结束时」时，
以前那句 `if (side != CombatSide.Player) return;` 会让整块效果永远不执行。

### ⑬ 卡牌页的锻造卡：费用栏与效果按钮整块藏掉

- 中间的**费用 / X 费用 / 额外资源量费用 / 升级后 X+1** 整块隐藏（不占位置）。
- 右边效果栏连**「添加效果 / 删除效果 / 撤回删除」三个按钮**一起隐藏，只留一句说明。

### ⑭ 自定义描述「填入参数…」会给出不存在的占位符

用户报「自定义描述的参数怎么缺失、是不是还有大部分遗漏」。全量审了一遍（58 种效果逐种类对比
「生成代码声明了哪些变量」和「菜单给出哪些占位符」），结论是**不是缺失、是多了**：

`HasNoDynamicVar` 里把「**种类天生没有动态变量**」和「**这一条的数值是 X / 本状态层数**」
两件事混成了一件（后者写在名单末尾的 `&& !AmountIsX`）。后果是【数值 = X】的
「从抽牌堆 / 弃牌堆 / 消耗牌堆拿牌」和「升级牌组里的牌（全局）」被当成**有**变量，
菜单里跑出一个 `{Value:diff()}` —— 可生成代码里根本没声明它，贴到卡面也显示不出数字。

现在两件事分开：`NoDynamicVarKind`（看种类）+ `HasNoDynamicVar`（再看数值），
上面 5 种不再冒出占位符；其余 30 种照旧。顺带把「自己明明声明了变量却出不来占位符」也审了一遍：
**0 种**（没有真缺失）。

### ⑮ 自定义状态在「增益 / 减益」下拉里选不到

`PowerChoices` 以前直接返回本体那 200+ 个状态，**没把自己的自定义状态拼进去** ——
「自定义参数」页的「增益/减益（状态层数）」、效果里的那一栏、条件的「状态」全都看不到自己造的状态。
现在返回 `AllPowers`（本体 + 自定义，界面上一直在维护的那份）。

### ⑯ 锻造页新增「自定义状态列表」

以前锻造页只有「卡牌 / 药水 / 遗物」三类，自定义状态不在里面。现在多了第四类
**「自定义状态列表」**：左边照旧「添加 / 删除」，右边是那块节点图（新建的状态会立刻出现在
「增益 / 减益」下拉里）。自定义状态自身的字段（类型 / 层数颜色 / 衰减 / 回合结束移除）还在
「自定义状态」页；节点图上把触发时机的效果接起来（这块布目前是记录用，生成仍走「自定义状态」页那套
`Triggers`，下一步再把它接到生成端）。

### ⑰ 卡牌类型 / 稀有度新增「状态」（照原版「粘液」）

本体的 `CardType` / `CardRarity` 里本来就有 `Status` 这一档（`Slimed.cs`：
`base(1, CardType.Status, CardRarity.Status, TargetType.None)`、`MaxUpgradeLevel => 0`、关键字 `Exhaust`、
打出时抽 1 张）。工具以前只给了 Attack / Skill / Power 三种类型、「稀有度」里也没有 Status，做不出这类牌。

现在：

- **类型**：`Attack / Skill / Power / Status / Curse / Quest`
- **稀有度**：`Basic / Common / Uncommon / Rare / Ancient / Status / Curse`
- 稀有度选「状态」的牌会自动：**不能升级**（照粘液写 `MaxUpgradeLevel => 0`）、
  **不进普通战斗奖励**（和诅咒 / 先古卡同一套排除）。费用 / 关键字照你自己填 —— 想要粘液那种就填
  1 费 + 勾「消耗」。

### ⑱ 自定义状态的自然衰减不触发「某个状态层数变化后」

用户报：「触发时机选『某个状态层数变化后』，上状态时能触发一次，之后每回合自然衰减就不触发了」。

原因是**本体只在 `PowerCmd.ModifyAmount` / `Apply` 里调 `Hook.AfterPowerAmountChanged`**
（PowerCmd.cs 第 249 行），而生成的「每回合衰减」以前直接写 `SetAmount(base.Amount - N)` —— **绕过钩子**。
本体自己的状态衰减清一色是 `await PowerCmd.Decrement(this)`，就是这个道理。

现在衰减改成：

```csharp
// 每回合减 N 层（减到 0 就移除）—— 走 PowerCmd.ModifyAmount 才会通知「层数变化后」那些钩子
if (base.Amount <= N) await PowerCmd.Remove(this);
else await PowerCmd.ModifyAmount(choiceContext, this, -Nm, null, null);
```

`applier` 传 `null`（和本体 `Decrement` 一致），衰减不会被「施加者加成 / 减伤」那套影响。
「回合结束移除」仍然是 `PowerCmd.Remove`。

### ⑲ 自定义状态里「从抽牌堆 / 弃牌堆 / 消耗牌堆拿牌」编译不过（CS0120）

别人的构建日志里报出来的：

```
cs\Powers\SerenPower2.cs(17,165): error CS0120: 对象引用对于非静态的字段、方法或属性
                                 "CardSelectorPrefs.Prompt" 是必需的
```

`CardSelectorPrefs.Prompt` 是**实例**属性（只在构造函数里赋值），生成端却当成静态常量用了。
现在按「从哪一摞拿」分别挑**静态**提示：

- 从抽牌堆拿 → `CardSelectorPrefs.RemoveSelectionPrompt`
- 从弃牌堆拿 → `CardSelectorPrefs.DiscardSelectionPrompt`
- 从消耗牌堆拿 → `CardSelectorPrefs.ExhaustSelectionPrompt`

### ⑳ 【if】的「条件」口挪到右边最上面（先判断再分支）

按需求调整：右边从上到下依次是 **「条件」→「是」→「否」** —— 先判断「条件」，
成立走「是」、不成立走「否」；左边那个「接入」仍然是接**前置**（触发时机 / 对象 / 别的分支）用的。

实现上「条件」口还是按**出口下标 0** 存（生成端也按出口读它），所以顺带修了一个下标撞车：
【if】的「接入」是 InputPort(0)、「条件」是 OutputPort(0)，两个口下标都是 0 ——
判定连线时必须**先看是不是「条件」这种插槽**再退回普通入口，否则条件口永远被遮住、
连上去会误报「这个入口是执行链的入口」。

### ㉑ 上限补丁拦错了地方（CS1061：`PlayerCombatState` 没有 `Player`）

第一版的上限补丁是拦 `PlayerCombatState.GainStars` 的，想从 `__instance` 反查玩家 ——
可本体那个类**没有公开的「我是谁」属性**（`private readonly Player _player;` 只给内部用），
于是生成出来的工程直接编译不过：

```
cs\StarCapPatch.cs(18,37): error CS1061: "PlayerCombatState" 未包含 "Player" 的定义
```

改成拦**上面那一层**的 `PlayerCmd.GainStars(decimal amount, Player player)`：它本来就带着 `Player`
参数，`player.Creature` / `player.PlayerCombatState.Stars` 都是公开的，一个反射都不用。
本体里所有涨星星的地方（卡牌 / 药水 / 状态 / 控制台 / `SetStars`）全都走这一个方法，
`PlayerCombatState.GainStars` 只是它的实现细节、全网没有别的调用方 —— 覆盖面一样。

顺带说明这次为什么**没有**用反射读私有字段：本体一改私有布局，反射会静默失效
（补丁还在、上限没了，玩家看不出来），而公开 API 失效是编译期就报错。

### ㉒ 锻造页【状态】/【效果】模块里的「增益 / 减益」下拉看不到自定义状态

同一个坑的**第二处**（第一处在卡牌页，V0.2.53 修过）：锻造页那块布上的状态下拉是
**重建布的时候现搭的**，而它取的是

```csharp
ItemsSource = Core.Effects.EffectCatalog.Powers,   // 只有**本体**状态的静态清单
```

—— 玩家自己配的「自定义状态」根本不在这个清单里（它们登记在 `EffectCatalog.CustomPowerEntries`，
由「新建自定义状态」时调 `RefreshCustomPowerRegistry()` 刷新）。所以卡牌页能看到、锻造页看不到。

现在：

- 那块布的下拉改成吃**和卡牌页同一个数据源**（`ForgeCanvasView.PowerSource`，
  窗口用 `PowerSource="{Binding PowerChoices, ...}"` 绑过去）—— `PowerChoices` 就是
  「本体增益 + 本体减益 + 自定义状态」那个集合，两边**永远一致**；
- 新建 / 删除自定义状态时（`RefreshPowerChoices` 里）**顺手把布重画一遍** ——
  下拉是搭布的时候建的，不重画就还是旧清单；
- 顺手剔掉了数据里以 `-` 开头的伪条目（那是「给予能量」那种标记，不是状态），并按显示名排了序。

自检新增 5 条断言（`锻造页状态下拉非空 / **布上真的绑到了窗口那个集合** / 每条自定义状态都在 /
和卡牌页条数一致 / 没有伪条目`）—— 其中「每条自定义状态都在」是**故意写成会失败的**：
以前正是没有它，这个 bug 悄悄活了两轮。

顺带查出**第二个原因**：不只是数据源取错，那块布上的下拉还是「重建布的时候现搭」的 ——
登记过自定义状态之后不重画一次布，下拉里还是旧清单。现在新建 / 删除自定义状态时也会重画布。

## 注意

- 节点图（含升级后那张布）会存进存档；`--recover` 从工程反推存档时**不会**重建节点图，那种情况下要重做一次。
- 【对象】里的「指定队友」等同于「自己」—— 本体是单人游戏，没有可指定的队友对象；
  召唤物走「指定 / 随机 / 全部召唤物」那三档。
- 锻造页的条目如果还没接节点图，生成出来是「没有任何效果」的空条目，校验器会给一句提醒。
